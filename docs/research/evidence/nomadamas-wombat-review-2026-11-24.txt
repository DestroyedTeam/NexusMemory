# Candidate #260 review — NomaDamas/wombat (2026-11-24)

## Decision
**Useful adjacent prior art: local multi-Harness session reader, distiller, mirror and search index; not a cross-Harness migration engine.** Do not classify it as a ChatGPT-to-Claude migrator. Its broad parser inventory can inform source adapter coverage and source-pointer preservation, but its central projection is intentionally lossy and it has no destination writer.

## What the implementation actually does
- Implements 20 **local source readers**: Codex, Claude Code CLI, OpenCode, Pi, OMP, Hermes, Aside, Kiro, Droid, Goose, Mistral Vibe, Aider, CodeBuddy, iFlow, Continue, Copilot CLI, Crush, Qwen, Kilo and Gemini CLI. Sources include local JSONL/zstd logs, SQLite databases and provider-specific JSON layouts. The source-root and parser registries in `src/parsers/mod.rs` and `src/model.rs` confirm the list.
- Reads local source records, normalizes them to `ParsedSession` and `Turn`, writes a prefix-stable local Markdown mirror and SQLite catalog, then can invoke an external MinSync CLI for sparse/dense search. CLI help exposes `doctor`, `sync`, `index`, `search`, `sessions`, `show`, `trace` and `chunk`; it exposes no `import` or `export` subcommand and no target-Harness/session creation API.
- The normalized `ParsedSession` holds agent, session ID, source path, cwd, start/end timestamps, title, `is_subagent`, optional `parent_session_id` and turns. A `Turn` is only role, text, timestamp and source offset. This supports useful local source lineage and subagent filtering, not ChatGPT Project/Section Group or session-to-session orchestration graphs. There are no fields for attachments/media, links as typed blocks, token accounting, Skills, MCP servers, plugins, scheduled jobs, memories or target-side configuration.
- The mirror renderer retains local source path and cwd in ordinary Markdown and records offsets back into the source; `wombat trace` re-reads the source file to show raw records (including tool/thinking material). Raw trace is therefore not a self-contained portable export. No encryption layer was found in the reviewed mirror/catalog path; the local mirror is plain text. If indexing is enabled/configured with a remote embed endpoint, that configuration needs a separate data-boundary review.
- README documents parser-specific loss: system/developer prompts and injected context, reasoning/thinking, tool calls/results, snapshots, images/attachments or provider-only events are excluded from the dialogue projection. This is appropriate for text search, but not fidelity-preserving session migration.
- It reads local **Claude Code CLI** histories; no ChatGPT export/Projects parser and no Claude Desktop Chat, Cowork, or Code provider-mode adapter was found. It also has no Claude Code API-key/gateway destination writer.

## Nexus Memory disposition
Keep as a **reader/parser/source-offset and local-search architecture reference**. Its 20-provider inventory is valuable for broad Harness discovery; its normalized text mirror is explicitly not a canonical lossless SessionGraph and not a restore artifact. Nexus Memory should keep raw provider-native events/attachments and Project/Section/session relations separately from searchable text projections, emit per-field loss reports, and add destination-specific import adapters only where the target supports an actual restore path. Treat its clear-text mirror/local paths and optional external embedder as privacy boundaries. Do not claim session conversion accuracy from this repository.
