PRODUCT / TARGET FIT
- AKM is a local-first knowledge/capability library with 14 native asset types; broad harness/runtime integration; read-only adapters for Claude Code/OpenCode directories, Agent Skills, OKF/LLM wikis and other sources; path-based project defaults; Task v4 files plus cron/launchd/schtasks backends. Product docs mark session extraction, tasks/scheduling and harnesses as Evolving.
- Docs explicitly say AKM complements MCP/native skills; it does not replace or migrate arbitrary MCP servers. The richer platform plugins for Claude Code, Codex and OpenCode are a separate repo, `itlackey/akm-plugins`, not part of this review.
- LLM connections are OpenAI-compatible endpoints and API keys are environment-variable references. They support AKM model-work calls, not destination session storage in Claude Cloud.
- `projects` are path-selected read/write/filter scopes. They are not a nested Session/Project/SectionGroup graph. `--project` supplies fields such as user/agent/channel/metadata to memory/proposal assets.

SESSION ADAPTERS AND LOSS
- `SESSION_LOG_HARNESSES` derives from registry providers for exactly Claude Code, Codex and OpenCode. No ChatGPT-history session adapter was found.
- Claude Code reader parses local JSONL and folds the parent’s subagent JSONL files into one chronologically sorted parent SessionData. Child transcript content is stamped with parent session identity/provenance; no parent-child edge is emitted.
- Codex reader reads rollout JSONL from CODEX_HOME/sessions; includes codex exec, excludes subagent/guardian/internal rollouts. It accepts response_item message, function/custom tool calls and tool outputs. `blockText` reads only text blocks; image/audio blocks are discarded.
- OpenCode reader handles v1/v2 SQLite read-only and does not start the OpenCode process. v2 lists top-level sessions only (subagents and AKM model-work omitted); event projection keeps text/tool-call/tool-result strings.
- `SessionSummary` only contains harness/session id/file path/times/cwd/project hint/title. `SessionEvent` only contains harness/text/time/session id/role/file path. It lacks canonical parent/fork edges, SectionGroup, multimodal attachments, explicit interruption/steering, provider continuation markers and token/cost accounting.
- `akm proposal extract --sessions ...` (or `--auto`) calls a model to turn transcripts into durable insight proposals; default discovery window is 24h, with `--since`, `--session-id`, `--location`, `--dry-run`, `--force`, `--project`, model/connection selectors. The `sessions/**` asset writer stores metadata, source `log_path`, access instructions, tags, LLM Summary and Key topics only; it does not copy raw message events. The local source log must remain available. Pre-filtering truncates long events and uses a recency-biased total-character budget. Session extraction remains Evolving per STABILITY.md.
- No actual ChatGPT Project/Section/session payload, provider credential, API key or user home session log was accessed. All test fixtures and temp dirs were synthetic and isolated.
