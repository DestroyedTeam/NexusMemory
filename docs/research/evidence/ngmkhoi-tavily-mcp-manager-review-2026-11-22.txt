## Implementation and test findings

- Good patterns: separate secret values (`keys.env`) from active-key metadata (`config.json`), single-quote key values to prevent shell expansion, Node storage operations with a lock and atomic rename, `0600` writes for the key/config store, masked key output, backup-before-patch intent, JSON parse refusal, dry-run support, and using each agent's CLI where available.
- Dynamic disposable fallback probe: with no `claude` binary on a controlled PATH, seeded only a temporary `HOME/.claude.json` with an existing `mcpServers.tavily` entry (`old-server`, custom args and placeholder token) and an unrelated server; ran `bash src/cli/tavily-manager mcp install claude` **without `--force`**, under umask `022`. The command exited 0, printed `fallback claude CLI not found, patching ~/.claude.json` and `installed Claude Code`; the old Tavily entry was silently replaced by the wrapper entry, while the unrelated server remained. It changed the fixture's pre-existing mode `0600` to `0644`; the new `.claude.json.bak` also had mode `0644` and retained the old placeholder token. This is a reproducible overwrite/permission regression in the fallback writer, not a test against user data.
- A second disposable `mcp install all` probe deliberately provided no agent CLIs. Codex returned a manual-setup/attention condition, Gemini/Claude/OpenCode file installs were written to temporary HOME paths, the summary said `ok 3`, `attention 1`, yet the whole command exited 0. Automation cannot rely on its exit status to detect partial installation.
- `json_patch_file` does not lock or preserve file modes when patching config; backup and temp files use the process umask. The `--force` CLI branches remove an existing server before attempting add and suppress removal errors, so failure after removal can lose the prior entry. The tests cover config content/idempotency/dry-run/invalid JSON, but do not cover file modes, backup confidentiality, fallback replacement without `--force`, concurrent config writers, or `install all` nonzero failure propagation.
- Candidate key storage is substantially more careful than its general MCP-config writer; treat these as separate components. The manager's MCP path is one Tavily stdio service, not an adapter that imports arbitrary remote/local MCP servers, auth modes, resources, prompts, or plugin bundles.
- Current official Claude Code docs define Local/Project/User MCP scopes: local and user settings use `~/.claude.json`, project config uses `.mcp.json`, and project-scoped MCP use can have trust/approval behavior. This confirms the repo's Claude target is Claude Code CLI config, not Claude Desktop's 3P gateway store.
