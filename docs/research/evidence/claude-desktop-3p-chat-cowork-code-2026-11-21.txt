# Claude Desktop third-party inference: Chat / Cowork / Code scope review

Date: 2026-11-21. User confirmed that all three Claude Desktop surfaces/modes—Chat, Cowork, and Code—are in scope. They clarified that Claude Code means local/self-hosted usage, and the “Cloud” target is the Claude Desktop/client-managed session path configured for a third-party inference gateway, not Anthropic-hosted Claude Code Cloud. Keep Desktop mode, Code runtime, and gateway endpoint/auth as separate axes. Version and OS remain open; no user account data or application store was inspected.

## Findings from current first-party documentation

- The 3P inference gateway is an officially documented target: Developer → Configure Third-Party Inference can use an LLM gateway. The gateway must implement streaming `POST /v1/messages` and tool use; `GET /v1/models` is optional. Static gateway API key and interactive SSO/OIDC are separate auth options. The docs recommend preserving `cache_control` to avoid repeated full-context processing. These configure inference only; a key is not a session-history token.
- Claude Desktop on 3P stores chats, settings and credentials on the device. OS paths are `~/Library/Application Support/Claude-3p/` (macOS), `%LOCALAPPDATA%\Claude-3p\` (Windows), and `~/.config/Claude-3p/` (Linux), with documented legacy Windows variants. When configured by MDM, local config or bootstrap, users do not sign in to Anthropic and Anthropic has no per-user app state.
- Chat and Cowork use `local-agent-mode-sessions/`: one `local_<uuid>.json` state file and per-session working directory with transcript, uploads/attachments, outputs and `audit.jsonl`. The audit log contains prompts, assistant text, tool inputs/results, returned thinking, permission decisions, model and token usage. It is plaintext, not sent off-device by the app, and deleted with the session; at-rest protection is delegated to full-disk encryption. Project-specific memory lives under `spaces/<projectId>/memory/`; global Cowork memory/instructions have a distinct tree.
- Code session records are in `claude-code-sessions/`, while transcript JSONL is in Claude Code's own `~/.claude/projects/` store. That location is shared with local Claude Code CLI. Treat Code session metadata, transcript, workspace, files and trust state as separate records; do not assume a single common Chat/Cowork/Code archive.
- Product terminology is in transition: first-party help docs say Chat and Cowork are being unified gradually for some plans. Projects can start either Chat or Cowork; local-folder Projects are a Cowork/Desktop capability. Therefore the required adapter dimension is surface/mode plus version/runtime, not a rigid assumption that “Chat” and “Cowork” always have separate top-level containers.
- The 3P import wizard is a source-specific importer, not a generic cross-harness writer. It can copy a user's Claude.ai chats/projects (one-time; via account authorization or Claude data-export ZIP) and local earlier-install Cowork/Code sessions. The wizard must be enabled in managed configuration and requires Desktop running in 3P mode; for a Team/Enterprise Claude.ai export, an owner must also enable member-data export. It does not sync later source changes. Claude.ai project knowledge-file contents and chat attachments are not in a personal export; imported project folders may need to be reattached in Chat. Cloud Cowork sessions are not imported by the Enterprise-to-3P wizard. An encrypted/native-format generic ChatGPT archive writer is not documented.
- Version gates matter: the automatic copy of earlier third-party sessions brings the larger set of projects, memory/instructions, tasks, skills/plugins, live artifacts and attached files on Desktop 5.11492.0 or later; earlier versions bring less. Device-to-device export/import requires Desktop 4.23118.0+ on both devices, the same OS and organization. Export ZIPs are unencrypted. Exported JSON configuration may contain a gateway API key in plain text; locally stored `configLibrary/` credentials can be encrypted to the OS account and should not be copied directly to a different device/user. Keep credentials out of Nexus bundles and make the user rebind them.
- Claude Desktop's device-to-device export/import is a separate feature: it can include Chats, Cowork tasks, attachments/output files, memory, project data, Code sessions/tasks, Skills/plugins/scheduled tasks and local MCP definitions (with required manual re-binding). It excludes credentials/API keys, sign-ins/connectors/permissions, some settings and artifacts. The ZIP is explicitly unencrypted. This is not evidence that ChatGPT-origin data is accepted.
- Enterprise Compliance API is a separate authenticated product: it can list/read local Cowork and Claude Code sessions for managed Enterprise organizations, but exposes what reached Claude's API rather than all local device activity. It is not the generic 3P local-store importer and does not grant access to the user's 3P/API-key session store.

## Migration implications / open tests

1. Build one Claude Desktop 3P destination adapter with distinct Chat/Cowork/Code projections and explicit local/hosted-session type; don't use a hosted Cloud endpoint or Anthropic login for the API-key case.
2. Inspect only a user-selected, disposable 3P export/store. Determine whether native create/import is supported for arbitrary ChatGPT events; until demonstrated, mark any direct writes into undocumented app-state files as unsupported/manual review.
3. Test project, custom group, folder, attachment, memory, schedule, Code workspace/trust, tool/event order, branches and subagent references separately. Validate that the target app lists/resumes each imported thread and that tool/events remain interpretable.
4. Verify the gateway's Messages API semantics (streaming, tools, cache metadata, model IDs) independently from history restoration. Never transfer API keys or permissions; preserve only secret references for user re-binding.
5. Treat local 3P audit/transcript data as sensitive plaintext: encrypt backups, minimize copies, hash attachments, enforce owner-only file permissions and explicit retention. Do not copy prompt-bearing hook logs into a portable bundle without user opt-in/redaction.

Evidence boundary: official documentation was read; no Claude Desktop install/config/store, gateway, Compliance API key, or account was accessed or modified. No ChatGPT/Codex import into Claude Desktop was executed.

## Follow-up reconfirmation after the user's scope reply (2026-11-21)

The user selected **all three Claude Desktop modes: Chat, Cowork, and Code**. A fresh read of current first-party help docs confirms that Claude Desktop on a third-party provider is a distinct deployment path from Anthropic-hosted Claude Enterprise/Claude Code Cloud: configured inference can use Bedrock, Google Cloud Agent Platform, Microsoft Foundry, or the user's own LLM gateway; the app's own history/projects/memory remain on the device. The documented one-time importer carries each user's own Claude.ai chats/projects plus Cowork and Code sessions already local on that computer; it is not a ChatGPT export importer. Personal export lacks uploaded-file contents, and provider-hosted Cowork sessions are not part of the local-session step. See https://support.claude.com/en/articles/18426225-move-from-claude-enterprise-to-claude-desktop-on-a-cloud-provider.

The same guide now documents Desktop's own session export as an **unencrypted ZIP** covering app data such as sessions, projects, memory, scheduled tasks, skills, and uploaded plugins. Its importer is for another device with the same OS and organization, with Desktop 4.23118.0+ on each device, and it explicitly excludes Claude Code CLI sessions. This is useful for backup/restore test design, not evidence that arbitrary ChatGPT data can be injected. Never put API keys or permission grants in Nexus bundles.

Mode-specific capability must remain explicit: Cowork Projects can hold instructions, files/context, schedules, and memory, but current help docs state Projects are available in Cowork and not yet in Claude Code. Separately, consumer Cowork has moved new tasks to cloud execution since 2026-10-06, whereas the documented Claude Desktop-on-3P route keeps history on-device. Thus a single "Claude Desktop" label is insufficient: record deployment/provider mode, Chat/Cowork/Code surface, task locality, project capability, Desktop version, OS, and import/export path independently. Sources: https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork and https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile.


## 2026-11-22 mode-scope reconfirmation and current product boundary

The user reconfirmed that all three Claude Desktop logical surfaces—Chat, Cowork, and Code—are in scope. Fresh first-party pages checked today show the labels are not a stable storage hierarchy: Anthropic is gradually merging Chat and Cowork into one conversation experience; the same Cowork Project can be used by Chat and Cowork, and current help says Projects are in Cowork/Claude but not Claude Code. On the third-party-inference deployment, the gateway contract separately requires streaming `POST /v1/messages` plus tool use and supports either a static gateway API key or OIDC; that endpoint/credential configuration is not a history-import mechanism. See https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude, https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork, and https://claude.com/docs/third-party/claude-desktop/gateway.

The current 3P local-data docs distinguish Chat/Cowork conversation state under `local-agent-mode-sessions/` (per-session state JSON, working directory, uploads/outputs, audit JSONL and project memory under `spaces/<projectId>/memory/`) from Code session records in `claude-code-sessions/` and transcripts in Claude Code's `~/.claude/projects/`. The first-party 3P importer is source-specific: it copies claude.ai data and earlier local Claude Desktop Cowork/Code sessions; it does not document a ChatGPT export importer. See https://claude.com/docs/third-party/claude-desktop/data-storage and https://claude.com/docs/third-party/claude-desktop/import.

A separate current Anthropic Help Center update says new Cowork tasks for Pro/Max/Ultra have run in Anthropic's cloud since 2026-10-06, while earlier computer-only tasks remain local; cloud sessions continue across surfaces/account and local file access depends on Desktop being online. Therefore the migration matrix must record **deployment (3P gateway vs Anthropic account Cloud), logical surface (Chat/Cowork/Code), task locality, client version and OS** independently. Treat API-key inference and hosted Cowork Cloud authentication/session storage as different routes unless a version-pinned test proves otherwise. See https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile. No app/account/store or API key was accessed; this was documentation-only research.
