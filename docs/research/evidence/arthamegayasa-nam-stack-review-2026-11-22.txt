## What is actually present

Five skills: grok-imagegen, openrouter-imagegen, openai-imagegen, whats-next, and improve-loop. Files follow skills/<category>/<name>/SKILL.md, with Python image-generation scripts in two skills, a repository structure validator, and an OpenAI-imagegen fake-HTTP eval suite. There is no transcript, Projects, Sections, session tree, memory store, context or token ledger, MCP registry, plugin marketplace, scheduled-task or multi-harness migration code.

The plain SKILL.md folder format is a portable starting point, but the instructions are not semantically universal:

- grok-imagegen relies on Grok Build, T3 Code delegate_task or Grok CLI; its headless route uses the --always-approve flag. This is not equivalent to an ordinary safe shell capability.
- whats-next requires repo/issue-tracker orientation, gh issue list and a specified subagent workflow.
- improve-loop assumes a panel/gatekeeper and harness-specific subagent/wait/ledger semantics.
- openai-imagegen and openrouter-imagegen need their respective paid-provider credentials and API endpoints. Scripts read keys from environment/files and, on Windows, the user environment registry; no key should be copied or migrated as skill content.
- The repo lacks plugin.json, marketplace.json, MCP manifests, environment/capability declarations, and per-harness invocation adapters. Copying these folders does not provision Chat/Cowork/Code gateways, required providers, tools, user grants, or local plugins.

## Relevance to the user-confirmed destination

User scope remains Claude Desktop on 3P inference in Chat, Cowork, and Code, plus local/self-hosted Claude Code. Current official docs confirm Desktop 3P has a local skills/plugin provision plane, but Claude-account-synced skills do not sync when Claude Code uses an API key or third-party provider. To distribute skills across Desktop surfaces, use a user-uploaded plugin or a managed plugin marketplace; a plain raw Skill folder is not enough for Desktop's organization-plugin layout, and Code requires the marketplace route rather than the organization plugin directory. The repo contains no Claude Desktop plugin manifest or marketplace. Detailed official-source map: docs/research/evidence/claude-desktop-3p-skills-routing-2026-11-22.txt.

Disposition: keep as a small personal Skill corpus and cross-harness behavior fixture, not as a manager or session migration dependency. Useful for evaluating portability loss of tool assumptions, provider credentials, CLI execution and permission semantics; not evidence of Projects/Sections/session graph portability.
