WHAT IT ACTUALLY DOES
- Omaset is an Omarchy/Linux settings manager: a Quickshell UI, CLI, and stdio MCP server share a typed settings schema and backend registry. The MCP tools expose settings search/schema/get/set/reset/undo/history; the UI and CLI operate on local Omarchy/Hyprland settings. It targets Omarchy, not arbitrary Harness runtime state.
- The setting called “schedule” is a display/night-light schedule, not an AI session or agent automation scheduler.
- It is not a transcript/event store, project hierarchy importer, memory vault, or multi-provider adapter. No ChatGPT/Codex Project or Section Group, conversation Session/message/branch/subtask tree, attachment, tool-call ledger, usage/token/cost record, schedule migration, or ChatGPT-to-Claude writer was found.
- Claude Desktop Chat, Cowork, and Code are all unsupported as session sources or targets. A helper returns a Claude Desktop config filename, but CodeGraph/source caller review found it referenced only by tests; runtime discovery/injection works against Claude Code settings and Codex config, not Desktop’s Chat/Cowork/Code stores or a third-party API-key gateway session format.
- Positive design ideas only: a shared schema/control plane used by UI/CLI/MCP, value-by-value edits rather than full-file rewrites, explicit history/undo, validation before apply, and process/output bounds. These patterns do not provide conversation fidelity or cross-Harness restore.
