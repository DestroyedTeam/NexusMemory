## What is shipped

Zen Agent Skills is a collection of written agent instructions and distribution tooling, not an agent runtime or data migration utility. Its source of truth is one harness-agnostic `SKILL.md` per skill, with supporting templates, references, rules, and scripts. The skills focus on software delivery: project/work tracking, specifications, task decomposition, coding/review, handoff, and verification.

The installer has `core`, `spine` (default), and `all` profiles; it resolves sibling-skill references so a profile does not ship a dangling composed skill. It places native `SKILL.md` directories globally for Claude Code and OpenCode, keeps a hash manifest, avoids overwriting unowned files, supports dry-run/check/uninstall, and installs shared rules. The generator creates project-level Cursor `.mdc` rules and VS Code/Copilot prompt files while rewriting allowed relative links. An optional output generates a Claude Code plugin tree. Docs list other Harnesses as manually reading the canonical skill or receiving a locally authored adapter; Codex is not a first-class target in the install integration table. The acceptance run produced 48 adapter files for 24 skill directories and exercised dry-run plus a temporary install/uninstall cycle, but did not launch every target client or prove its runtime actually loaded the skill.

This is useful prior art for Nexus Memory's **portable Skills plane**: single-source skill bodies, adapter generation, profile/description budgets, explicit ownership, non-destructive installation, and tests for broken relative links. It does not configure MCP servers, gateway/API-key authentication, ChatGPT Projects, Claude Desktop 3P modes, or any session/transcript importer. A Claude Code plugin tree is a Skills distribution format, not a session migration bridge.

## The adjacent session observatory is narrower and not shipped

The same repo includes `scripts/observatory/` and `.agents/skills/agent-observatory`, but its own catalog marks `agent-observatory` as a **draft**, and the README/architecture say observatory is maintainer tooling that `install.py` never places. It is not evidence that the published skill kit supports cross-Harness memory or session transfer.

The observatory reads Claude Code's local `~/.claude/projects` JSONL corpus and `~/.claude/sessions` live-session registry, deriving a local SQLite report. Its schema is useful analytics prior art: a session row; message UUID and `parent_uuid`; `message_occurrence` to account for fork/resume replay; tool-call rows; subagent `agent_run` sidecars with model/status/token/duration/tool counts, worktree branch/path, and spawn depth; and context-budget samples. This is **not a portable archive**: the default adapter is Claude Code-specific, the observatory is not delivered to adopters, and its message table stores identifiers, parent/type/time/model/attribution/token/error metadata rather than raw message bodies or attachment payloads. It has no ChatGPT source decoder, Section Group/project membership mapping, Claude Desktop Chat/Cowork/Code adapter, or import/resume writer. Its read-only session actions are only opening a PR, copying a work path, or copying a `claude --resume` command; it does not execute session actions.
