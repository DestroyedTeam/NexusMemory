## Verdict

**Retain as a high-value adjacent artifact-memory reference; do not rank as a cross-Harness session-migration engine.** It can help Nexus remember and later rediscover a source document, Figma design, issue, file, etc. It cannot move the conversation that found it, preserve its Project/Section or session ancestry, or resume a target-native ChatGPT/Codex/Claude conversation. The memory-card and source-pointer concepts can complement a canonical conversation graph but must stay a separate entity plane.

## Implementation review at the pinned commit

- The Rust CLI supports `add`, `get`, `index`, `search`, `recent`, `forget`, `reindex`, `doctor`, `stats`, and `context init`; DB defaults to `$HOME/.artmark/artmark.db`, with `--database`/`ARTMARK_DB` override. It uses local SQLite + FTS5. The v1 schema contains `artifacts`, URI aliases, topics/entities/tags and an FTS index; no Project, Section, Session, message, branch, attachment, token-usage or schedule tables.
- `add` canonicalizes an artifact pointer and records an alias/explicit-save bit; `index` accepts an agent-authored card after the source was inspected. Card fields include concise summary/search text, topics/entities/tags and source/retrieval metadata. Search returns cards and a locator; the existing agent harness fetches the live source. `artmark` itself has no provider auth and does not fetch or copy source documents. `forget` deletes only its catalog record, not the underlying artifact.
- Canonical identity supports local paths and provider patterns including Google Drive/Docs, Figma, GitHub, Notion and Slack; ordinary HTTP(S) URLs retain query identity while fragments are dropped. Add uses transactions and SQLite prepared parameters; canonical aliases deduplicate known resources. Schema is early v0.x and README explicitly says the CLI/data schema may change before 1.0.
- `IndexInput` requires nonempty summary/search text, bounds their lengths and metadata, rejects recursively named source-body and credential fields. A separate bounded iterative URI scanner rejects recognizable credentials in URLs, nested/encoded query/fragment/path forms and userinfo before persistence; tests assert rejected adds do not change a populated DB/FTS. This is conservative defense, not arbitrary-secret detection. Catalog titles/search descriptions can still reveal sensitive topics, and local DB backups need protection.
- The bundled `skills/artmark/SKILL.md` gives a behavioral workflow: quick-register user-supplied durable locators; inspect current source with the user's existing provider tools; only then index a small card; query the catalog before provider search for vague rediscovery; ask before storing artifacts discovered through research. README documents manual installation for Codex and Claude Code local skill directories. It is an instruction-plane integration, not target session serialization. No Claude Desktop Chat/Cowork/Code or ChatGPT Project/Sections adapter is present.
- No MCP server implementation or MCP dependency is present in this release; README calls stdio MCP a planned next step. The GitHub `mcp` topic is not evidence of a shipped MCP surface.
- CI includes format/clippy/Python tests, Linux/macOS/Windows builds, release packaging/clean-install checks, dependency audit, and a PR semver/lockfile gate. ## Nexus Memory disposition

Keep only as an optional **ArtifactCatalog / retrieval-hint** design reference, not a dependency assumption or a SessionAdapter. Nexus should model `{ArtifactPointer, canonical source identity, source facts, separately-provenanced retrieval card, resolver/auth reference}` independently from `{Project, SectionGroup, ConversationThread, Message, Branch, ToolEvent, Attachment, Schedule}`. A conversation may reference an artifact; its pointer or search card must not be injected as a substitute for its history. Preserve source URLs only after credential filtering; persist no secrets; require consent for research-discovered items; and fetch the live source through a target-authorized provider tool before answering. Artmark has no import/export accuracy score because it implements no session conversion.
