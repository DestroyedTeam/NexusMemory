## What is genuinely useful to Nexus Memory

This is a **local cross-harness configuration inspector/archive UI plus a live API-context logger**, not a historical project/session migrator. It inventories Skills for Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI and OpenCode; MCP config for Claude Code, Codex, Cursor, Gemini CLI and OpenCode; hooks for Claude Code, Codex and Gemini CLI; and Claude Code plugins. Its archive/restore operations move or restore resources in their existing local paths and include backups for configuration-file changes. The README's “never deletes” means it archives/moves rather than permanently deletes.

The logger can capture **new live API requests** after the user routes Claude Code CLI through `ANTHROPIC_BASE_URL=http://localhost:<port>/claude-code`, and a beta Codex route through `openai_base_url`. For captured calls it stores each request JSON and parsed response, groups by session ID, extracts prompts/system/tool content and token usage, and displays main/subagent threads. This is a useful observability/reference design for the source side of future ingestion.

It does not import historical ChatGPT/Codex Projects or Section Groups; does not ingest pre-existing Claude Code session files; does not write a portable target session; and has no Claude Desktop third-party-gateway **Chat**, **Cowork**, or **Code** adapter. It does not produce a Project/Section/SessionGraph transfer or preserve forks, task-parent IDs, user interrupt/event order, or attachment files as independent assets. MCP config is view/archive/restore, not schema conversion between Harnesses. Plugins are Claude Code only. Codex logging is labeled beta and the README says its analysis is designed for Claude Code.

Session IDs come from Claude Code headers/user metadata or Codex session/conversation/cache headers. If Codex provides none, `sessionOf()` assigns `codex_sin-sesion-YYYY-MM-DD`; a temp probe with two different no-ID requests returned the same `codex_sin-sesion-2026-11-22`, showing they would merge in that fallback case. Claude Code agent IDs and Codex turn metadata produce thread keys, while parent-spawn association is inferred by comparing child first prompts with the first 120 characters of an Agent/Task prompt—not by a stable parent event ID.

## Synthetic-only probes and limitations

All tests used temporary paths beneath `/tmp`; no actual `~/.claude`, `~/.codex`, project, API credential, session, or user content was read.

1. **Subagent parent-link ambiguity:** wrote a synthetic index with two parent Agent spawns whose prompts share the first 120 characters and two separate child threads. Actual `sessionDetail()` output linked both `child-a` and `child-b` to `first-child`, not the second spawn. Output: `[ {id:"main", kind:"principal"}, {id:"child-a", kind:"subagente", label:"Agent: first-child", linkedSpawn:"first-child"}, {id:"child-b", kind:"subagente", label:"Agent: first-child", linkedSpawn:"first-child"} ]`. This is an observed topology reconstruction error under a valid collision case.
2. **Skill-detail path boundary:** actual `skillDetail()` code is exposed by `GET /api/skill?file=...`; it checks `dir.startsWith(allowedRoot + '/')` rather than resolving and containment-checking the path. First synthetic probe constructed `skills/../../outside/SKILL.md`, which normalized to a different nonexistent temp location and returned Bun `ENOENT`, exit 1; corrected the fixture/path to use three `../`. The actual function then accepted `/tmp/nm-acm-pathprobe/home/.claude/skills/../../../outside/SKILL.md` and returned the external `NEXUS_OUTSIDE_SKILL_SENTINEL`. This confirms a local API path-validation bypass beyond the configured Skill roots. The web server does bind to loopback and checks Host/Origin; this probe is not a claim of internet reachability.
3. **Logger stores prompt-body secrets:** actual logger proxy with a fake local upstream received synthetic `authorization`, `x-api-key`, and user body `NEXUS_BODY_SECRET_SENTINEL`. Exit 0 / HTTP 200. Persisted record checks: `bodySentinelPersisted=true`, `authHeaderPersisted=false`, `apiKeyHeaderPersisted=false`. Thus auth headers are redacted, but full request bodies/replies are intentionally stored unencrypted under `~/.agent-config-manager/logs/<session>/`; any secrets included in prompts/tool results remain on disk. This is material if the logger is enabled.
4. **MCP config backup copies secrets as-is:** fake `home/.claude.json` included `NEXUS_BACKUP_API_KEY_SENTINEL`. Actual `createBackup()` copied it into the backup; observed `secretPersisted=true`. With the synthetic source created under default umask, source and backup modes were both `0644`. There is no encryption or redaction in the copy path. Existing real config modes vary, so the observed mode is specific to the synthetic file.

The code has other useful properties: the HTTP server binds to `127.0.0.1`, checks Host and Origin, limits incoming API routes, and tests the fake API streaming flow. Important caveat: `requestDetail()` returns the full stored request/response record, so local logs are a high-sensitivity cache. Keep the logger opt-in, document at-rest exposure, and add retention/encryption/redaction policy before treating its data as a portable memory vault.
