## Isolated failure and integrity probes

1. **Remove path traversal.** With an existing disposable `.agents/skills` parent and sibling temp directory, `skillz remove ../../../victim` exited 0, stdout `ℹ Removing skill '../../../victim'...`, stderr `⚠ Removed '../../../victim' directory but it was not in the lockfile.`, and deleted the sibling victim sentinel. The resolved victim was `/private/var/folders/62/8__6fhqd5dq7bh2cgp2_75lh0000gn/T/nm-kayaman-skillz-probes-xr5halj_/victim`.
2. **Failed overwrite loses old contents and leaves stale lock.** First `skillz add ./demo --yes` exited 0 with old `SKILL.md`. A second install with new content and a dangling symlink exited 1 after `shutil.rmtree(dest)` followed by failed `shutil.copytree`. The destination remained partially recreated with `# new`, the old `# old` content was lost, and the lock hash remained the old value `571b0fc6f2e50e66ef03ca8d8d2cd09bbad28897d1736833e56df5719dbfd52e`.
3. **Dotfile omission and hash framing collision.** Different `.private` contents hashed identically to `b8076aef1d6e7fff009d97a39f8d9e581483c133dbf0848fb47f9c20cb3d972d`. Distinct file layouts (`a`=`bc` versus `ab`=`c`) produced the same `1971e4d30c53a0f541391a8f6861bb674307eaa3a3f98013a1cce4e146a12f3e`.
4. **Failed upstream update is reported as success.** A fake `git` executable returned 128 (`fatal: forced fixture failure`). `skillz update demo` nevertheless exited 0, stdout `ℹ Checking 'demo'...
ℹ All skills are up to date.`, stderr `✗ git clone failed: fatal: forced fixture failure
⚠ Failed to update 'demo': Failed to clone https://github.com/owner/no-such-repository.git: fatal: forced fixture failure`; the installed skill remained.
5. **Failed lock write leaks fetched temp state and still returns success.** A fake `git clone` created a new remote Skill, while the synthetic project `.agents` directory and lock file were made read-only after a valid lock was written. `skillz update demo` returned exit 0 and printed `Checking`, `has changes, updating`, `Updating existing skill`, then `All skills are up to date.` Its stderr reported `Permission denied` writing `.skill-lock.json`; the installed Skill had already changed to `# new` while the recorded hash remained `oldhash`. Because `cleanup_temp(tmp_path)` occurs after installation rather than in `finally`, one `skillz-*` directory remained under the probe’s explicitly isolated `TMPDIR` (`/tmp/.../tmp/skillz-ml3gskjw`). All temporary files, permissions and directories were removed/restored after the test.

## Disposition

Retain only the shared `SKILL.md`/v3-lock vocabulary as a reference; do **not** reuse its path handling, replacement, update status, cleanup or hash semantics. It has no ChatGPT Projects/Sections, Claude Desktop modes, transcript/session graph, MCP/plugin/memory/schedule migration. Full test/source/probe evidence is local; no target host was invoked.
