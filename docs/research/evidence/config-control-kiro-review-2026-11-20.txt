- Global scope: `~/.kiro/`; workspace scope: `<project>/.kiro/`.
- Manages Kiro agents, MCP configuration/tool discovery, permissions/sandbox, hooks, steering, skills, prompts, specs/workflows, powers, ACP, code intelligence and settings. Skill import paths are local-folder or GitHub-to-Kiro, not general cross-harness sync.

SESSION / GRAPH SOURCE REVIEW (CodeGraph current: 339 files, 4,270 nodes, 11,299 edges)
- `internal/sessions/store_v3.go` states that Kiro V3 chats are under `<home>/sessions/<folder key>/sess_<id>/`, with `session.json` and `messages.jsonl`; local index journals mark added/removed chat paths.
- V3 parser only reads metadata and metering. `Session` includes ID/title/folder/engine/time, agent/model, message count, running state, context-use/credits, parent ID and resume command. It counts user events, reads credit usage summaries/context percentages and never reads prompt text, assistant response text or tool results into the app's chat list.
- V3 `parentSessionId` with `createdReason=subagent` is a parent/subagent link. `createdReason=tangent` or `rewind` becomes `Kind + BranchOf` rather than subagent containment. Parent chat credit totals include subagent chat credits.
- V2/classic listing delegates to `kiro-cli chat --list-sessions --all-cwds --format json`; local legacy usage is read under `<home>/sessions/cli/<id>.json`.
- `dashboard-meta.json` supplies local V3 bookmark/title/Kiro-native tags, read-only. `dashboard.apply` looks up the `v3\0local\0` key only. Tests verify a remote dashboard entry is not applied. App-local tags live separately in `<global>/kiroui/chat-tags.json` and do not change Kiro's chat tags.
- `resumeCommand` constructs `kiro-cli chat [engine flag] --resume-id <id>`; no Session archive writer/loader or transcript-conversion API is implemented in the app's routes.
- Kiro memory is a separate resource model: local shared/account SQLite stores; `USER_PREFERENCE` / `SEMANTIC` types and `Global` / repository scopes. List is read-only; create/update/delete are called through Kiro's `_kiro/memory/*` ACP methods so Kiro validates and writes the memory. It is not a generic memory import/export mechanism.

CLOUD / EXPORT BOUNDARY
- Official Kiro CLI docs state local sessions can be saved/loaded with `/chat save` and `/chat load`, while those archive commands are unavailable for cloud sessions.
- Official docs distinguish Cloud sessions in the account's remote store from the local per-directory session database; Cloud sessions can resume from another machine.
- The reviewed app's local V3 reader scans local Kiro-home session folders and applies local-only dashboard metadata. It has no explicit cloud/remote field or Cloud archive adapter. The app delegates V2/classic listing to `kiro-cli`; whether that command returns remote Cloud rows in all supported versions was not tested. Therefore do not state that Config Control can export, import, or migrate Cloud transcripts.
- No ChatGPT/Codex Project/Section reader, parent/fork/turn transcript converter, attachment export, image/link/tool-output preservation, token-history conversion, scheduled-task migration, or Claude/Claude Code Cloud writer was found.
