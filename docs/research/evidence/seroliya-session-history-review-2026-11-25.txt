- Product scope is a read-only Node CLI/Skill for DeepSeek Harness (DSH), Codex and **local Claude Code**. It has no ChatGPT export adapter, no ChatGPT Project/Section/Section Group source, and no Claude Desktop Chat/Cowork/Code or Anthropic-hosted Cloud writer. It cannot move sessions into a new harness. ## High-value prior art

- Canonical read model groups messages/events into turns and typed items with stable `T<turn>.<item>` refs. It can render outline/chat/tools/full views under a bounded token/character budget and expose tool calls/results, actions, files, todos, usage counts, compaction and handoff notes.
- DSH `isSeeded`/`session/end-seed` marks inherited history; Codex `forked_from_id` and paged rollouts build explicit lineage; DSH fork lineage is heuristically inferred from a shared first message; Claude Code follows `parentUuid`/`logicalParentUuid` to the active branch and detects subagent sidecars. Later same-cwd sessions are suggestions, not guaranteed causal links.
- Data handling is local/read-only with no network calls in the inspected CLI; the Skill explicitly says old transcripts are data, never instructions. It warns that redaction is heuristic and `--no-redact` disables it. This is useful source-adapter/lineage/read-budget prior art for Nexus, not a destination writer.

## Fidelity limits relevant to Nexus Memory

- No first-party ChatGPT conversations export/JSON tree, Project, Section or Section Group adapter. No app database/Projects/Section importer. Claude adapter is Claude Code's local JSONL only and has synthetic fixtures only; it is not Claude Desktop Chat/Cowork/Code.
- `claude.ai` is not a source/target adapter here. No session import/export writer, project migration, attachment byte preservation, file hashing, schedules, MCP/plugin/Skill inventory migration or credential/gateway transport.
- Images and attachment payloads are reduced to placeholders/notices; no asset manifest or source bytes. Unknown record types are skipped, not surfaced as a loss report. Codex compact content and some reasoning/agent bodies are encrypted and unreadable; tool formats and internal session schemas may change.
- It is a local history reader for a coding-agent's next session. `handoff` is a heuristic text brief, not a rehydrated session. The README's benchmark (3 projects × 2 models, 12 runs) is small and author-reported; one with-skill DeepSeek run gave a reversed/obsolete plan as complete, and v1.1 lineage changes have not been re-benchmarked.

## Cache privacy defect reproduced with fake stores only

CLI output passes through `redact()`, but cache construction does not. `Store.buildDigest()` serializes raw user/assistant/tool text; `summarize()` also persists first-user/last-assistant snippets in `index.json`. A synthetic fake HOME (0755) and umask 022 held one fabricated API-key-shaped string and marker in a Claude JSONL under a temporary source root. Running default cached `search` produced redacted terminal output (`sk-[REDACTED]`), while the cache's `index.json` and gzip digest still contained the full `sk-test1234567890abcdefXYZ` and synthetic marker. Cache directory mode was 0755; both cache files were 0644. No real home/session was scanned. The same synthetic query with `--no-cache` exited 0, remained display-redacted, and created no cache directory.

Evidence: `/Users/vincentadamnemessis/Library/Caches/NexusMemory/test-results/seroliya-session-history299/cache-permissions-redaction-probe.json` and `no-cache-probe.json`. Chrome's storage docs are not applicable to this CLI; file-mode findings are from this synthetic local filesystem probe. Recommend redacting before persistence and enforce owner-only permissions, or default to `--no-cache` for sensitive transcripts.

## Installer safety and cross-platform test failure

- `scripts/install.mjs` treats **any symlink** in `~/.dsh/skills/session-history`, `~/.codex/skills/session-history`, or `~/.claude/skills/session-history` as installer-owned; it overwrites such links without `--force` and without backup. `uninstall` likewise removes any symlink at those exact slots. Fake DSH_HOME probes confirmed install replaces a user-owned symlink silently and uninstall later deletes a user-created symlink; the original target directory/sentinel survives. This contradicts the documented “only links/copies this installer created” guarantee. Evidence JSON: `/Users/vincentadamnemessis/Library/Caches/NexusMemory/test-results/seroliya-session-history299/symlink-probes/install-uninstall-user-symlink.json`.

## Decision

Disposition: **high-value read-side architecture prior art; not a migration engine or transfer dependency**. Reuse the typed event/item read model, source-specific parsers, branch/lineage warnings, read budgets, and prompt-injection posture as design references. Do not treat redacted terminal output as proof the cache is redacted; do not run installer/uninstaller against existing user symlinks until ownership is verified; preserve explicit loss reports and target-side native verification in Nexus.
