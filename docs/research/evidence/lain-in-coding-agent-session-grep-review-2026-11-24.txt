## Implemented scope and canonical data model
README lists **14 implemented / 16 planned local coding-agent providers**: Claude Code, Codex CLI, Grok Build, Antigravity, OpenCode, Pi, Hermes, Cursor, Kimi Code, OpenClaw, Qoder, Tencent CodeBuddy, Cline and Aider. DeepSeek Harness and ZCode are deferred. The authoritative capability matrix marks every implemented adapter `Experimental`; ChatGPT and ChatGPT Codex Projects are not providers.

The implemented model is a valuable message-level graph: a stable `Session` identity; text `Message` plus optional timestamp; `SourceDocument` keyed by provider/variant and byte fingerprint/length; `MessagePlacement` for session/document occurrence, ordinal, sidechain and optional exact source span; and `MessageEdge` from child occurrence to parent message with relations Reply/Retry/Fork/Continuation/Subagent/ToolResult. This preserves intra-session branch/sidechain topology when the source exposes native parent pointers. `SessionContextGraph` is one selected Session graph, not a Project/Section/session-to-session parent graph. `Session` itself currently stores only its stable ID; repo/CWD are separate metadata/search facets, not first-class Projects or Section Groups.

The actual canonical `Message` body is normalized **plain text**, with provider timestamp. Current domain/storage does not implement attachment blobs or ContentOccurrences. RFC-0001's richer `ContentBlob`/`ContentOccurrence` model (including `attachment_ref`) is explicitly **Draft**, not shipped code. Tool activity and token-usage observations exist as separate typed events, but only selectively: capability matrix says Claude Code has partial tool activity/native usage and Codex partial tool activity/derived usage; most other providers mark these unsupported. Activity records are bounded observations (kind/actor/name/optional target/status/short message), not full provider tool payloads or permission transcripts. The capability matrix marks native context only for Claude Code; the other 13 implemented providers are unsupported for context-graph reconstruction.

All 14 providers currently report Experimental maturity. A README/provider matrix is honest about capability differences; there is no parity promise and no conversion-fidelity or source→target round-trip metric.

## Actual operations and destination boundary
This is a local-first, read-only **search/catalog and handoff** tool, not a converter. It discovers/parses coding-agent local transcript stores into SQLite/FTS; supports context retrieval, evidence spans, MCP/Robot/TUI/loopback Web, and deterministic redacted handoff packs. The `HandoffTarget` is a suggested provider/agent/command, and the handoff implementation explicitly outputs a pack rather than silently injecting it. This may help a human/agent reconstruct context, but it is not a lossless export or destination writer.

`asg resume` builds a safe native CLI resume descriptor for a subset of providers (`claude --resume <id>`, `codex resume <id>`, etc.). That is same-provider resume of the original session, not transfer: it does not synthesize a Claude Desktop Chat/Cowork/Code session or import a ChatGPT Project/Section/Session. The CLI refuses to fabricate commands for unverified providers. The separate `resume`/`handoff` paths do not migrate Skills, MCP servers, plugins, scheduled tasks, model credentials, project instructions or uploaded files.

Session identity is not automatically portable across machines: README says the `ses_v1` namespace still depends on installation path and cross-machine relocation needs an explicit alias migration. Four of fourteen adapters cannot provide exact byte spans (two SQLite and two whole-document formats), and the provider readiness ledger labels missing/derived facts instead of inventing them. These are useful honest-loss/provenance patterns, not full-fidelity guarantees.

## Disposition for Nexus Memory
**High-value adjacent prior art for the Search/Canonical SessionGraph core; not a direct migration engine, ChatGPT source adapter, or Claude Desktop target writer.** Consider the conceptual architecture: stable entity identity separated from placements/source snapshots; parent-edge/mainline semantics; exact evidence spans plus honest unknowns; per-provider maturity/capability matrices; read-only import with fingerprints; bounded/redacted handoff and fail-closed native resume. Do not adopt the current schema as the full Nexus interchange format: it omits Project/Section, session-parent links, multimodal attachments and most provider event/config planes. A Nexus canonical model must extend beyond this tool and must add round-trip/loss tests for Chat, Cowork, Code and local Claude Code independently.
