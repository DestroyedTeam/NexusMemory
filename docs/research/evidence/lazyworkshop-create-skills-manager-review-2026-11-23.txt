## Scope and behavior

This repository is a small Python UI/downloader/updater for Agent Skills in `wshobson/agents`. It lists preselected Skill mappings from `skills.json`, can browse the remote repo, then copy Skills to a VS Code global directory, a generic `./skills` project directory, a user-entered path, or a hard-coded “Claude Desktop” folder. It has no Harness/session schema and performs no state migration. No support for ChatGPT/Codex projects, Section Groups, conversation hierarchy, branches, events, transcript/attachments/media/token accounting, MCP, plugin connectors, memory, or schedules. It does not set up an API key or third-party gateway.

The implementation clones the default remote branch shallowly (no commit/hash pin), copies directory trees, and if a Skill contains `requirements.txt`, invokes pip against the active `sys.executable`. Existing destinations are recursively deleted before copying, without ownership checks, backup, dry-run or rollback. No test suite, license file/SPDX, dependency lock, or CI workflow was found. The README says the code was AI-generated but that is not a license grant.

## Claude target mismatch confirmed against current official docs

The candidate's `--claude-install` path is `~/Library/Application Support/Claude/skills` on macOS, `%APPDATA%\\Claude\\skills` on Windows, and `~/.config/Claude/skills` on Linux. This does not match Claude Desktop on 3P's documented app-local-data deployment model (`Claude-3p`), and the current official Skills docs do not specify these generic paths as the Desktop 3P Chat/Cowork installation mechanism. Desktop 3P user extensions are added/managed in the app UI and stored in that app's local data directory; organization-wide distribution uses plugins/marketplaces or a system-wide directory. The distinct Code filesystem skill conventions are `~/.claude/skills/` (personal) and `.claude/skills/` (project). This installer reaches either only via its arbitrary custom-path option, with no target validation, and does not configure plugins/MCP/hooks needed by some extensions.

The official Skills help says account Skills synchronize into Claude Code only when signed in with a Claude account; they do not sync when Claude Code is signed in with an API key or runs against a third-party cloud provider. For this user's API-key/gateway path, Skills synchronization must therefore be handled by a separate explicit adapter; this installer neither detects that boundary nor handles it.
