## Candidate function and migration fit

Dotai is a Go configuration-pack engine for Claude Code CLI, Google Antigravity CLI (`agy`), and OpenCode. A pack can render rules, agents, Skills, MCP server configuration, hooks, permissions, settings, tools, and Claude Code plugin mods, with variants and project profiles. `dotai apply/install` are plan-first; dry-run, isolated versus replace modes, backup/journal and restore/rollback are valuable safety patterns. The word “project” in this tool means local project configuration/profile, not a ChatGPT Project or Section Group.

No ChatGPT/Codex adapter, Project/Section hierarchy, parent/child/branch/task SessionGraph, event/transcript/media/attachment/token transfer, cross-harness durable memory sync, or scheduler migration was found. Claude Desktop Chat/Cowork/Code are not harness adapters here. The Claude adapter is the Claude Code command line.

## Current Claude Desktop scope confirmed from official Anthropic sources

The user's clarified target is **all Claude Desktop capabilities (Chat, Cowork, Code) through Claude Desktop on third-party inference (3P)**, plus **local/self-hosted Claude Code**, not Anthropic-hosted `claude.ai` chat or Anthropic-hosted Claude Code Cloud. This is a valid first-party-supported target concept: Anthropic's current admin migration docs explicitly describe Claude Desktop on 3P routing all model inference to the configured provider, which may be Bedrock, Google Cloud Agent Platform, Microsoft Foundry, or the organization's own LLM gateway. The supported Desktop feature set lists Chat, Cowork, projects, artifacts, memory, scheduled tasks, file upload, Skills, plugins, connectors, and Code. API-key/static-key use is documented for proof of concept; production provider identity should be per-user or through a controlled credential helper/authenticating gateway.

Current UI model: Unified Claude is rolling out and merges Chat and Cowork into one conversation/home. Therefore the migration schema must retain the source mode and target capabilities, but must not assume Chat and Cowork are always separate target roots. Code remains a distinct mode and its local CLI transcript store is shared with Code tab transcripts under `~/.claude/`. Anthropic-hosted Claude Code Cloud sessions are a different plane (GitHub-backed cloud runner); they must not be conflated with Desktop 3P/local sessions.

Official `Import history from claude.ai` is **not** a ChatGPT/Codex universal importer. It imports the signed-in user's own Claude chats/projects (one-time copy, repeatable without duplicates) and local Cowork/Code sessions from the same machine or an added folder. It omits cloud Cowork/Code sessions; project knowledge/attachments in a personal member export are omitted; memory/personal instructions require manual transfer; skills/plugins/connectors require reconfiguration or a separate local-data move. This path proves cross-mode move workflows within Claude only, not ChatGPT-to-Claude compatibility. A ChatGPT/Codex adapter must translate into target-specific local/session format or provide a provenance-preserving archive plus resumable handoff, then verify each item.

Official local layout clues for the target adapter:
- Desktop 3P app data: macOS `~/Library/Application Support/Claude-3p/`, Windows `%LOCALAPPDATA%\Claude-3p\`, Linux `~/.config/Claude-3p/`. The 3P app-data namespace is separate from standard Claude Desktop.
- Chat and Cowork session: state file + working directory under `local-agent-mode-sessions/`; working directory includes transcript, `uploads/`, `outputs/`, and `audit.jsonl`. Audit/transcript can hold prompt/response/tool inputs/results, and session detail such as model, token usage, thinking and permission decisions is recorded for Cowork/Chat.
- Projects and memory: project-scoped memory under `local-agent-mode-sessions/.../spaces/<projectId>/memory/`; global Cowork memory/instructions are distinct. Chat only reads/updates project memory when inside that project.
- Code: `claude-code-sessions/` stores session record metadata (working folder, settings, title, sometimes summary); actual Code transcripts live in Claude Code's own `~/.claude/projects/` store. `~/.claude/` and `~/.claude.json` also hold shared Code/CLI settings, Skills/plugins/hooks/permissions/MCP/trust state. Do not conflate Desktop session summaries with the actual transcript.
- Desktop local session export is not encrypted. It may carry secrets embedded in files/arguments; saved provider API keys, sign-ins, connector credentials and env-var values do not move and must be re-established. A safe Nexus format must encrypt or redact at rest, never copy provider keys by default, and re-consent to connectors/MCP/tool permissions.

## Disposition

Retain Dotai as a high-quality ResourcePlane, pack format, dry-run/rollback, and local Claude Code API-key launch pattern; do not reuse it as a SessionGraph importer. The official Anthropic Desktop 3P docs materially improve Nexus's target contract: model Desktop 3P as a separate local data plane with three mode capabilities and explicit cross-mode relationships. The initial prototype should emit an immutable archival package, a normalized source SessionGraph, target-specific artifacts for Skills/MCP/Projects/Chat/Cowork/Code, a loss ledger per item/field, and a user-approved resumable handoff for items whose target format is undocumented or not safely writeable.
