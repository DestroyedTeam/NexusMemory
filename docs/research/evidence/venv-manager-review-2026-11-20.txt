POLICY / EXECUTION REVIEW (CodeGraph initialized and current: 41 files, 588 nodes, 1,782 edges)
- `internal/mcp/server.go:NewServer` constructs a `safe` policy by default.
- `internal/mcp/policy.go:readOnlyTools` permits inspection tools. `confirmationRequiredTools` includes remove_venv, install_packages, run_in_venv, exec_ephemeral, rollback_venv, set_registry_metadata. Safe policy checks for caller-supplied boolean `confirm: true`; `create_venv` is allowed without that field. `PolicyFull` bypasses the policy checks after the optional explicit-tool allowlist. Read-only blocks mutating/execution tools.
- The `confirm` field is a server-side argument gate, not an independent consent interface or proof the human approved the operation.
- `authorize("exec_ephemeral", {sandbox:true})` returns success, but `internal/mcp/exec.go:execEphemeral` rejects `sandbox == true` with `sandbox mode over MCP not yet supported; use CLI ...`. Without `sandbox:true`, it creates a temporary environment, optionally installs packages, runs arbitrary argv through the venv command handler, then removes the environment. Thus the CLI's documented OS sandbox does not exist on this MCP handler at the pinned revision.
- `runInVenv` executes a resolved command via `exec.Command`; safe mode requires `confirm:true` before dispatch. No executable was actually run in this review.
