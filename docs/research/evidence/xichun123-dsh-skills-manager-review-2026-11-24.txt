## Product / data model / fit

This is a DeepSeek Harness (DSH) plugin for the DSH Skills provider, not a general cross-Harness migration product. It installs selected `SKILL.md` bundles into the plugin-private `$DSH_HOME/skill-manager/.agents/skills/` directory. `skills-lock.json` records source provenance; `state.json` stores separate global and workspace/project enablement and a manual-only invocation override. “Project” here means a DSH workspace root and descendant paths for Skill scope, not a ChatGPT/Codex Project/Section hierarchy or a conversation Session. The plugin adds a Settings panel and a composer toggle; the toggle is resolved against the current session's workspace path.

Positive adjacent patterns for a future Nexus ResourcePlane: isolate imported Skill files from active workspaces; keep origin/lock metadata and enablement state separately; preserve source `SKILL.md` bytes when applying manual-only policy; invoke the packaged CLI with argv rather than shell text; reject escaping source symlinks; expose per-workspace scope. These are design observations, not code reuse permission. The package explicitly declares `UNLICENSED`.

## Source review and current DSH compatibility report

Pinned source review covered the plugin entry, manager/provider, RPC client/server, Settings and composer UI, tests, package manifests, lockfile and workflows. The source registers `ctx.connection.rpc.handle('/skill-manager', ...)`, gates local file mutation controls on loopback, and uses Connection's RPC integration. It also preflights a remote source before invoking the Skills CLI, but the remote ref can change between preflight and the CLI's second clone (a TOCTOU window).

The public repository's still-open [issue #1](https://github.com/Xichun123/dsh-skills-manager/issues/1), opened 2026-10-16, reports three install/runtime blockers against DSH 0.2.0-rc.2 and the published 0.2.0 plugin: (1) plugin activation throws `cannot get property "webServer" without inject` at `connection.rpc.handle`; (2) after the reporter locally injects `webServer`, browser POSTs to `/skill-manager/list` return HTTP 405; and (3) the declared DSH peer ranges stop at `0.1.5-alpha.1`, so 0.2.0-rc.2 is rejected by the installer absent a risk override. The issue reporter proposes call-site injection or exact `/api` routes through `connection.fetch.register`, plus widened peer ranges. Source inspection independently confirms the custom `/skill-manager` RPC registration and the peer-range ceiling; the activation/UI 405 reproductions are the issue author's report, not a live DSH runtime test by this review. The issue page was open with no linked fix/PR when checked. README's assertion that the RPC uses the authenticated `/api` fence is therefore not treated as proof of a working route on current DSH builds.
