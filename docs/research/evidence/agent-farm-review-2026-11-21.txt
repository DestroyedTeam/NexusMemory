WHAT IT ACTUALLY CONFIGURES
- Native harnesses are Claude Code CLI and Codex CLI only. A Profile resolves to an Agent, harness/model/instructions, child agents, shared skills and optional workspace MCP connections; the launch compiler renders generated bundles into the repo under `.agent-farm/generated/`. User-global config lives under `~/.config/agent-farm`; project workspace config is a tracked `.agent-farm/workspace.yaml` with an explicit trust step. “Project” in this product is a repository/workspace identity, not a ChatGPT Project/Section. No Claude Desktop Chat, Cowork or Desktop Code session adapter appears in the product boundary.
- Third-party gateway support is real for native CLI launches: provider settings contain `name`, `base_url`, `api_key_env` (the environment-variable name, not the key value), and optional match=`all|slash-models`. Codex receives a generated runtime `config.toml` using Responses API; Claude Code receives `ANTHROPIC_BASE_URL`, model alias overrides and a child-side resolved `ANTHROPIC_AUTH_TOKEN`. Existing native config remains outside bundles. The local provider-smoke test completed real Codex 0.154.0 and Claude Code 2.1.76 turns against a mock server bound to 127.0.0.1, with synthetic key `FAKE-LOCAL-PROVIDER-KEY` only; mock received `/v1/responses` and `/v1/messages?beta=true`, and the key was absent from printed launch config/bundle. This verifies CLI gateway configuration, not Claude Desktop developer-mode or hosted Cloud sessions.

SESSION / TELEMETRY DATA MODEL
- Every supervised Agent Farm run generates a local UUID Session ID and writes `session.json` plus OTLP JSONL `traces.jsonl`, `logs.jsonl` and `metrics.jsonl` under `~/.local/state/agent-farm/telemetry/<id>`. Metadata includes profile/variant, harness/model, canonical project/worktree, state/start/end/exit, launch ID and parent Session ID. OTel server is loopback-only with random per-session endpoint token; inherited remote OTLP destinations/headers are cleared. Native prompts/tool content are disabled by default; `capture_content` is explicit opt-in. Data is local and README says it is not sent elsewhere; operations docs say no automatic retention policy for telemetry folders.
- Separate `~/.local/state/agent-farm/launches/<launch-id>.json` records profile, variant, harness, directory, launch time, Codex home, optional native session ID; stale launch records older than 90 days are pruned. On resume, a recorded Agent Farm ID must use the same profile and harness. It looks up Claude JSONL/Codex rollout state and passes the native ID to the same CLI; a resume ID not known to Agent Farm is simply passed through to the selected harness. This is native same-harness resume, not identity translation or data import.
- Child sessions can record `agent_farm.parent.session.id` and OTel trace parent context; `TelemetryStore.runs` groups parent/descendant sessions. Dashboard and read-only telemetry MCP expose session list, metadata, trace spans, log events and reconstructed turns. Conversation normalization derives requests from spans and enriches them with events; it intentionally omits thinking/reasoning and binary images/documents, truncates content, can warn on partial/malformed data, and does not guess referenced files. Token/cost values are parsed from native fields; summaries explicitly avoid inferring totals from overlapping spans.
- `agent-farm telemetry export --bundle DIR --session/--launch ...` copies explicitly selected sessions and child descendants into `bundle.json` plus `evidence/telemetry/<id>`, and has `--include-content` and `--require-finished` gates. Export is an artifact evidence snapshot with `publication: pending`, not an importable canonical session archive. It exports `session.json`, filtered `logs.jsonl`, and `metrics.jsonl`; it deliberately leaves out `traces.jsonl` (records `traces_left_out_bytes`, removes stale trace files). The unit tests assert there is no exported traces.jsonl. Thus the exported bundle lacks the span tree required by its local turn normalizer and cannot fully reconstruct the dashboard conversation or replay a provider Session. No telemetry import command or cross-harness writer was found.

SECURITY / ADOPTION LIMITS
- Operations docs state every Claude launch uses `--dangerously-skip-permissions` and every Codex launch uses `--yolo`; there is no setting to disable this. Agent Farm does not sandbox filesystem edits or isolate credentials; generated runtime homes can still expose native config/global skills. Workspace instructions/trust are not an access boundary. Use disposable worktrees and review the security model before even a test deployment.
- Provider configuration stores only env var names, not API key values. This is a useful secrets-by-reference pattern. However its gateway adapters target Claude Code CLI and Codex CLI, not Claude Desktop Chat/Cowork/Code or Anthropic-hosted Cloud.
- No ChatGPT project/session import, Sections/Section Groups, Claude Code external JSONL import, attachments, persistent memory, scheduled tasks, or Cloud/API-key Session creation. No conversion-accuracy/fidelity metric or round-trip test exists.
