- The Skill says to run an automatic update check at conversation start, counting `~/.claude/skills/` and `~/.agents/skills/`; it offers list/health/conflict/update/remove instructions and tells the model to call `npx skills`. This is prompt text only: there is no app hook, executable watcher, test, schedule, or enforceable guarantee that the check runs on every session. It scans those two path families and is not a cross-Harness adapter. It does not migrate Projects/Sections, session history, MCPs, plugin configuration, memory or schedules. - Mutation commands prescribed are `npx skills update -y` and `npx skills add <source>@<skill-name> -g -y`; `-y` bypasses confirmation. Removal alone explicitly requires confirmation. The prompt does not require a diff/backup review before update. The referenced CLI's installer recursively cleans destination directories before writing; an update can therefore replace a locally modified copy. Treat any update as a user-authorized mutation with preview/backup, not as silent session-start work.

README advertises OpenCode, Claude Code, Codex, Cursor and 75 more. `docs/agents.md` lists Claude Code but no Claude Desktop Chat/Cowork/Code; its paths describe Skills files only.
- Valuable Skills portability reference: supports per-agent paths and a shared `.agents/skills` canonical directory, symlink/copy fan-out, project/global scope, Git/source URL/ref/commit lock metadata and a deterministic content hash. `skills-lock.json` is useful for provenance and drift checking; `experimental_sync`/`experimental_install` handle skills shipped by npm dependencies or project lockfiles. `plugin-manifest.ts` discovers Skill directories nested in Claude plugin manifests; this does not migrate plugin settings, MCP server definitions, permissions, credentials or runtime state. No conversation/session/Project archive or native session writer.
- Current `skills check` status is version-sensitive. Upstream issue #954 reports versions through 1.7.4 (2026-10-27) accidentally reinstalling skills during `check`; merged PR #2605 on 2026-10-28 separated check mode and added read-only tests. Local v1.9.0 source branches to `reportOutdated` without installing; `tests/check.test.ts` passed 4/4 (local synthetic git fixture). However the primary Skill does not pin a minimum CLI version. The CLI's `check` path still emits anonymous `skills.sh` telemetry by default; documented opt-outs are `DISABLE_TELEMETRY=1` or `DO_NOT_TRACK=1`. Auto-running it every chat is a network/telemetry side effect unless disabled.
- Install/update safety boundary from source: add without `-y` has an overwrite confirmation; `-y` bypasses it, and installer `cleanAndCreateDirectory` performs recursive removal before copy. The CLI can report local changes in `check`, but the reviewed `update -y` prompt itself asks for no change review. Use a transaction/backup and compare deltas before applying to customized Skills.
