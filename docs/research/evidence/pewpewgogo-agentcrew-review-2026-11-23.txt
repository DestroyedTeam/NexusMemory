## Product fit: a project/task context relay, not a chat/session importer
AgentCrew provides a hosted/self-hostable REST + Streamable HTTP MCP server and CLI. Its real domain tree is **Project → Milestone → Task** (a task's milestone is optional), with per-project knowledge fields (`repos`, `urls`, tech stack, notes), membership roles, and an append-only context log. This is a useful adjacent pattern for shared human/agent project notes and task status. It is not a ChatGPT Project or Claude Desktop project/session store.

The context record schema is only `{id, projectId, targetType(project|milestone|task), targetId, authorUserId, authorKind(human|agent), note, createdAt}`. MCP `add_context` appends one text note; `get_context` queries them. No source-harness ID, conversation/session ID, message ID/parent, fork, turn/task relation to a chat session, transcript blocks, reasoning/tool-call records, attachments, token usage, or schedules are modeled. No import/export route or adapter for ChatGPT, Codex, Claude Desktop Chat/Cowork/Code, or other harnesses was found. The Skill asks an agent to read project/task state and append findings—an AI/user-triggered context workflow, not deterministic no-AI history migration.

**Important terminology:** the server's `cs_s_` “session token” is an application login/auth bearer, stored hashed in the database with `name='__session__'`; it is not a conversation session. `cs_k_` is an AgentCrew MCP/API bearer key, also Argon2-hashed server-side. Neither is an Anthropic/OpenAI/model-provider API key, nor does AgentCrew configure a third-party inference gateway. README's only bundled Skill install target is Claude Code (`~/.claude/skills/...` and `~/.claude.json`), not Claude Desktop's three 3P modes.

## Data integrity and access control from source
- Context append derives project ID from the target and REST/MCP routes check caller membership before allowing writes; read results are constrained to member projects. Task routes check membership and block viewer mutations.
- Context is append-only at the service level and indexed by project/target/time; `context_log.target_id` is not a foreign key to task/milestone, so deleting a target can leave historical records pointing at an absent entity. Project deletion cascades its context log.
- `Task` includes optional `milestoneId`, goal, status, priority and assignee; no `parentTaskId` / nested subtasks.
- `ApiKey`/password hashes use Argon2, and `~/.agentcrew/config.json` writes are chmod 0600. However, `init` also writes the raw app MCP API key into `~/.claude.json` via `writeFileSync` without chmod/permission hardening.

## Disposition
Keep as a high-value **shared Project/Task/append-only human-agent context** reference; reject as a Nexus session migration engine. A Nexus adapter might map project metadata or user-approved session summaries to project/task context, but cannot reconstruct vendor session trees from this schema. Its bearer key is an app authorization token, not a model gateway key. Before any reuse, fix CLI config permissions for raw keys, constrain URL transport to HTTPS for remote servers, and expose provenance (`harness`, source project/session/message IDs, ancestry) plus attachments/event payloads without flattening them into `note`.
