## Main v0.3.0 safety review — verified source and test path

- Account profiles are read-only unless `writes: true` is set; this is a useful baseline least-privilege design.
- However the main tool schema uses `confirm?: boolean`. `runAdsWrite()` sends a Google `validate_only` request when `confirm` is absent, but `confirm: true` directly proceeds to mutation without a server-issued Preview ID or binding that apply to a prior preview. `packages/mcp/test/runner.test.ts` explicitly exercises `confirm: true` and expects it to apply/log the write. Thus the README's “preview first / your yes” workflow is agent/skill-mediated, not guaranteed by the main MCP server API. With a writable profile and a misdirected/prompt-injected tool call, callers can bypass the intended preview flow.
- Main `workspacePath()` interpolates supplied `workspaceId` into a GTM API path without validation. The open PR adds a digits-only check because an injected path could escape the profile's allowed GTM container scope; this is a material main-branch risk, not a merely cosmetic change.
- Main `ads_demand_gen_audience` creates a new custom audience (`validate_only: !confirm`) before sending the larger audience/batch write through `runAdsWrite`. For `confirm: true`, the child custom segment is already live if later batch operations fail. The PR delays that create until after the preview confirmation.
- No live Google OAuth, Ads/GA4/GSC/GTM account, write operation or customer data was used in this review; the confirmation bypass is source + mock unit-test evidence, not a live-service exploit.

## Open PR #1 (0.4.0) — genuinely improved, but still not the released product

The PR replaces boolean confirmation with a single-use Preview ID (`pv_…`) bound to profile alias, tool name, canonical JSON SHA-256, and a 15-minute expiry. It consumes the ID once, refuses altered content or mismatched profile/tool, and asks through MCP elicitation when the host supports it. Profile `requireHumanApproval: true` fails closed when elicitation is unavailable; when that setting is false and the host cannot elicit, the PR permits a preview-matched second call, so operators still need strict profiles for mandatory human approval. The PR also validates GTM `workspaceId` as numeric, defers the custom audience create until after confirmation, and adds rollback/drift protection for Ads/GTM/GA4.

The PR branch build passed and all 272 tests passed locally with mocked Google clients; upstream CI on the PR SHA succeeded. `gh pr view` still reports the PR open; publish was skipped. Dependencies did not change (only version strings changed in package.json/lock), so the dependency-audit findings below remain on that branch unless separately updated.
