## Implemented behavior (source and fixture tests)

Better Agent (`bta`) is a narrow local-first history index and CLI-to-CLI handoff prototype. Its README claims two source agents: local Claude Code and OpenCode. The adapters read Claude Code JSONL and OpenCode's SQLite store; OpenCode is opened read-only. Imported records go into a local SQLite/FTS index, while source files remain the source of truth. The normalized schema records source/session IDs, project path, branch/title/model/timestamps/token counts and message parts; it does not model ChatGPT Projects, Section Groups, or an equivalent workspace hierarchy (the project field is a path).

`bta switch --to claude|opencode` builds a deterministic context pack and starts the installed native CLI in the source session's project directory. The default pack is capped at 8,000 characters; it carries the old session ID and points back to `bta show` for stored history. Interactive mode previews and confirms before execution; `--yes` bypasses that gate, and `--dry-run` previews. It does **not** import/restore the old native transcript into the destination: it starts a new destination CLI session with a prompt pack. `bta resume` instead reopens a session in its original agent.

The pack's default summary comprises the session metadata, user intent spine, selected tool/command activity, files touched, Git state, last assistant text, and linked-session references. `--full` can include a rendered transcript, but output is still subject to the character cap. The renderer omits thinking and displays tool names/targets rather than full tool results. The Claude adapter filters to user/assistant events plus summary metadata; Claude message parent/sidechain IDs are recorded, while OpenCode parent/fork sessions become typed links. Links include related/continuation/handoff/fork/subagent, but they are loose undirected typed edges rather than a strict parent-controlled session tree. Tool results are truncated by the adapters. These behaviors make it useful for explicit, inspectable handoffs and a local history UI, not lossless migration.

## Fit against confirmed Nexus Memory scope

- ChatGPT/Codex source: no ChatGPT or Codex adapter; source Projects/Sections/Destruction Era hierarchy is not imported.
- Claude Desktop third-party-gateway Chat: no Desktop Chat reader/writer.
- Claude Desktop third-party-gateway Cowork: no Cowork task/session/artifact reader/writer.
- Claude Desktop third-party-gateway Code: no Desktop Code-mode reader/writer.
- Local/self-hosted Claude Code: local Claude Code CLI history is an input source; a CLI can be launched as a destination, but no native transcript restoration, project/session tree transfer, Skills/MCP/plugin/schedule/memory transfer, or API-key/gateway configuration migration is provided.
- Only Claude Code and OpenCode are supported. This is pairwise context handoff, not the universal, unattended, cross-Harness migration tool requested.

## Privacy and operational boundaries

The README states data stays local and there are no LLM calls. The code's interactive switch previews the pack before launch, but `--yes` skips preview/confirmation. It does not redact stored messages or handoff-pack content, so packs may contain sensitive user prompts, paths, and work details. `bta switch` passes the pack to the destination CLI as a prompt; treat it as content disclosure to that CLI/provider. No personal session files, provider accounts, API keys, live agent CLI, or gateway were accessed in this review.
