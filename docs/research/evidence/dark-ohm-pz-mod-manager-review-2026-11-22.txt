## What the implementation actually does
- The README and source define a Project Zomboid server/client/mod manager: GUI + JSON CLI + MCP over stdio. `src/mcp.rs::tools` maps `src/cli.rs::COMMANDS` into MCP tools and annotates `readOnlyHint` from each command’s mutation flag; `tools/call` dispatches into the same command executor. This is an MCP integration example, not an agent-session interchange format.
- The 50 MCP tools cover game environments, client/server mods, workshop downloads, mod profiles, INI/sandbox options, players, backups, server process controls and `.pzpack` sharing. The `.pzpack` archive contains Project Zomboid mod order/workshop IDs/server connection fields/local mod assets and an `AGENT.md` with PZ-specific instructions. Profile revision/hash fields track mod-pack updates, not conversation events or transcript fidelity.
- No ChatGPT export importer, Project/Section Group entity, cross-session parent/child or branch graph, prompt/message history, attachments/media, tokens, subtask orchestration, portable memory, schedule, Claude Desktop mode adapter, Claude Code session adapter or migration report exists. “Profile” and “MCP” are product- and game-domain terms here, not equivalent Harness structures.
- Disposition: pass as a false-positive/off-topic candidate for Nexus Memory. It is not a migration dependency. At most, its single command registry shared by GUI/CLI/MCP plus JSON schemas and mutation hints is a generic tool-adapter pattern; no PZ-specific code/state should be reused.
