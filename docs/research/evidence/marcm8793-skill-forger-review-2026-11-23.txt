Scope and disposition
This is a non-generative declarative Agent Skills CLI built on top of the Vercel skills CLI. It installs, adds and uninstalls skills from skills.json, with a generated skills-lock.json and agent flags. Useful adjacent ResourcePlane/tooling reference, not a Nexus SessionGraph or migration adapter. It has no ChatGPT/Codex Project/Section/session/message/branch/attachment/usage/memory/schedule parser or writer. No Claude Desktop 3P Chat/Cowork adapter; overlap between the default Claude Code target and Desktop Code was not tested and must not be claimed.

Observed model and behavior
- skills.json is a repo-level array of source strings plus optional Skill names. The separate JSON Schema requires only a skills key and source per item; runtime assertSkillsConfig only checks that the object has a skills property and otherwise casts it, so it does not enforce the full schema.
- CLI defaults to Claude Code and delegates actual installation/removal to a locally installed skills binary or npx skills. It accepts an agent flag; README documents Claude Code, Cursor, Codex and GitHub Copilot. The product does not implement each agent adapter itself.
- handleAdd invokes installSkillSource with yes=true before persisting the source into skills.json. Default install also passes yes=true. It can invoke npx skills when the local binary is not found. The wrapper does not show a content preview/review gate or create a rollback transaction before the delegated write.
- Config and lock files are rewritten directly with writeFile, without an atomic journal/backup. An install can succeed before skills.json is updated; failures across add/uninstall can leave disk/config/lock out of sync.
- Confirmed synthetic edge case: uninstalling a source whose skills.json entry has an empty skills list (meaning all skills) prints a warning and returns before invoking skills remove. The CLI then removes the source from skills.json and its entries from skills-lock.json while previously materialized Skill files remain on disk. In an isolated /tmp fixture the command exited 0, skills.json became an empty skills array, skills-lock.json became empty, and .claude/skills/demo/SKILL.md remained. The warning is disclosed by the CLI, but the config no longer tracks the orphaned file. No real user project was touched.
- Positive: subprocess uses spawn with an argument array, not a shell string; config add merges named skills and a helper appends missing skills directories to .gitignore. The uninstall-all orphan behavior is explicit in a warning; it is not an undetected deletion.
- This is a small CLI around Skills resources, not projects, sections, sessions or stored chat state. No target app import/resume test was performed.

Nexus disposition
Keep as a low-priority ResourcePlane discovery/install reference only. It can provide an agent-target flag and declarative Skill source list, but its state is not a harness project/session tree. Do not reuse as a SessionGraph adapter or claim Chat, Cowork, Code or local Claude Code session transfer. Nexus should preserve content preview, explicit per-file ownership, atomic lock/config state, and an undo journal when implementing similar resource operations.
