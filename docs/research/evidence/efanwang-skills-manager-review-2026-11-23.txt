Implementation value and boundary
- This is a Skills provenance/inventory/update helper rather than a cross-Harness portability layer. It has a per-install `sources.json` registry, remote revision checking, install/update backup/rename flows, and an “unclaimed” audit. It supports only a single parent Skills directory per manager copy and GitHub remotes. Source tracing's last unresolved step is an agent WebSearch handoff; the Python script emits a `search_query_hint` and does not itself do general web search. Thus it is not a fully harness-independent, AI-free transfer engine.
- `SKILL.md` instructs its invoking agent to ask before an update, to confirm installs before replacing, and not to automate delete. The scripts themselves do not implement a confirmation UI; direct `update_skill.py`/`install_skill.py` calls mutate immediately. Updates discard local edits, but first move the existing directory under `.backup/` and try to roll back on later failures. The `sources.py remove` command only removes a registry entry; deletion is a PowerShell/manual recipe in the Skill text.
- Positive source properties: skill names are regex constrained; `safe_resolve_subpath()` rejects `..` components, resolves symlinks, and requires the final subpath to remain beneath the clone root. Update/install use same-manager-root temp directories, backup existing Skills, rename replacement into place, atomically write the registry, and attempt rollback. Tests cover install/update backups and a simulated registry-write rollback. These are useful file-resource patterns, not SessionGraph semantics.
