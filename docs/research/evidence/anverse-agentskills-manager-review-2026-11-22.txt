## Implementation vs. specification

The README/spec describe a package manager for Agent Skills using agentskills.yml + agentskills.lock, Git/local sources, reproducible installs, and project-level agent targets such as .agents/skills, .claude/skills, and .cursor/skills. However, the current Go implementation only exposes help and version. internal/cli.New registers only the version subcommand and --version flag; its no-args action prints help. The binary's actual help lists only completion, help, and version. No init, install, add, remove, upgrade, validate, diff, agents list, YAML/JSON schema parser, lockfile reader/writer, Git source resolver, content-addressed store, target materializer, ownership reconciler, or filesystem mutator exists in this checkout.

The desired target is still Skills-only. It models no ChatGPT/Codex Project/Section/session tree, branches, parent-child task relations, messages/events, interruption/resume, attachments or media, token usage, memory, MCP configuration, plugin state, schedules, Claude Desktop 3P Chat/Cowork/Code, or local Claude Code transcript records. The README's .claude/skills path is specifically the Claude Code Skills directory, not a Claude Desktop 3P session adapter. Its v0.1 milestone also explicitly defers user/global scope.

## Useful design material (specification only)

These are ideas worth considering, but none has an implementation to reuse:

1. ADR-018 defines a deterministic SHA-256 tree hash over raw file bytes and normalized relative paths; it refuses symlinks/non-regular files, excludes file modes, and treats content rather than filesystem representation as the reproducibility identity.
2. ADR-017 proposes an immutable, content-addressed per-user store with stage -> verify lock hash -> atomic rename, per-skill links, and copy as the portable fallback. It correctly prohibits symlinking the Skills root because some clients do not traverse symlinked roots.
3. ADR-019 proposes lock records with resolved Git commit SHA, resolved skill path, and content hash, and excludes machine-local materialization strategy/timestamps.
4. ADR-023 proposes provenance-based ownership: remove/replace only entries proven managed; fail on unmanaged name collisions; retain hand-edited copies as unmanaged. A receipt/state file is considered but deferred.
5. The project-relative-only scope is intentionally constrained; ADR-012 defers global/user installs. There is no cross-session or transcript graph model.

## Conclusion

This is a design/spec reference for future reproducible Skills dependency management, especially content-addressing, lock provenance, portable copy fallback, and non-destructive ownership. It cannot be counted as a cross-harness session/project migration project or as demonstrated Skills compatibility: the installer does not yet exist. Full migration coverage is absent, including all user-confirmed Claude Desktop 3P surfaces and local/self-hosted Claude Code sessions.
