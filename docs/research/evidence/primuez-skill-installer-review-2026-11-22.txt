## Source-level findings and isolated probes

- The security gate has a fail-open branch: when NVIDIA SkillSpector is found but exits nonzero and produces empty/unparseable stdout, `scan_security()` catches JSON parse failure and returns `{safe: true, risk_score: 0, risk_severity: LOW}` unless the raw stdout literally contains `HIGH` or `CRITICAL`. A temporary executable `skillspector` stub that exited 42 with empty stdout reproduced exactly `{'safe': True, 'risk_score': 0, 'risk_severity': 'LOW', 'findings': [], 'scanner': 'NVIDIA SkillSpector'}`. No installation was run in this probe.
- The remote URL path accepts arbitrary HTTP(S) content but only rewrites GitHub `/blob/` to raw content; it does not handle GitHub `/tree/` repository-folder URLs used by the README example. With `urllib.request.urlopen` monkeypatched to return synthetic GitHub HTML, `install_and_sync("https://github.com/owner/repo/tree/main/skills/docker-deploy", ...)` exited successfully, derived the name `skills`, and installed the HTML page as `SKILL.md`, not the directory's skill. No external URL/network request occurred.
- Skill `name` frontmatter is not path-validated before `Path(target_dir) / meta["name"]`. In a disposable temporary HOME, an actual `install_and_sync` call with fixture name `../escaped` and backup route forced to local-only passed the fallback security scan and wrote the skill outside its requested `<temp>/skills` root at `<temp>/root/escaped`; the escape remained inside the disposable fixture, which was then deleted. This is a path traversal install flaw.
- `run_cmd()` uses `subprocess.run(..., shell=True)` and later builds Git/GWS commands by interpolating skill name/path into quoted shell strings. The same unvalidated frontmatter name can therefore reach command construction. The code can auto-create a private GitHub repo and `git push`/GWS-upload installed skill contents; this remote side effect was not executed.
- The fallback scanner is a small ten-pattern regex list and can miss arbitrary malicious instructions/code. `--force` bypasses both alternatives and a failing security decision. The README's “security-first” posture is not supported by fail-closed implementation/test evidence.
- License conflict is independently evidenced by the pinned source, local `LICENSE`, and the latest commit diff (which changed LICENSE from MIT to proprietary while leaving README's bottom section claiming MIT).
