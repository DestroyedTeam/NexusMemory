## Decision

Classify as a **narrow, adjacent Skill asset manager**, not a cross-Harness migration engine. Its useful reference is a manifest/pinned-source workflow and symlink distribution for `SKILL.md` directories. It does not serialize or import Projects, Sections, conversations, Session hierarchy, task/fork links, memory, MCP declarations, plugins, attachments, usage/token ledgers, schedules, or Claude Desktop modes. The user-confirmed Claude Desktop Chat, Cowork and Code modes therefore remain separate targets, not supported merely because the registry contains a `claude-code` skill folder.

## Source and implementation inspected

- `README.md`, package manifests, docs, source, tests, and main implementation were inspected from the pinned local clone; CodeGraph was initialized and verified at 105 files / 1,035 nodes / 2,846 edges. The only CodeGraph `.gitignore` edit was removal of its `!.gitignore` exception, keeping generated index files ignored.
- `packages/skills-package-manager/src/config/types.ts` models `SkillsManifest` as `$schema`, `installDir`, `linkTargets`, `selfSkill`, `skills`, and `patchedSkills`. `ResolvedSkillEntry` is a source specifier/resolution plus digest and optional patch. No conversation/project/session entity appears in this model.
- `packages/skills-package-manager/src/cli/agentCompatibility.ts` hard-codes 45 names to skill-directory destinations (e.g. Claude Code `.claude/skills`, Codex `.agents/skills`, Cursor `.agents/skills`/global `.cursor/skills`, OpenClaw `skills`; also Antigravity, Gemini CLI, Copilot, Windsurf, OpenCode, Goose, Kiro, etc.). `linkSkill()` creates one filesystem symlink per skill name at each configured link target. These are static Skill paths, not format converters or history/session adapters.
- `packages/skills-package-manager/src/specifiers/` and website docs support Git/GitHub refs (including pinned commits/subpaths), npm versions, local paths/links, and local tarballs. The published install flow materializes files into one `installDir`, then links them to `linkTargets`.
- The main manifest lacks Skill-to-Skill dependency-lock fields. Open PR #36 proposes frontmatter dependencies and lock behavior; open PR #37 proposes install-time manifest bootstrap/adoption. Neither was merged in the inspected state.
- No source model/adapter was found for ChatGPT/Codex Project or Section groups, session/message trees, active branches, child tasks, turns, interruptions, images/audio/video/links, token/cost usage, MCP servers, plugins, persistent memories, scheduled tasks, or provider Cloud session APIs. Skill path portability is not session-data portability.
