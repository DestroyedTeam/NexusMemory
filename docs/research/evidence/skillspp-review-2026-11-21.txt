## Repository/code review

- README and contracts describe a package-manager-like CLI for Markdown Agent Skills, with per-agent skill paths and project/global deployment. It does not model Projects, Section Groups, chats, Session ancestry/forks/subtasks, message/event order, attachments, token usage, memories, or schedules.
- `apps/skillspp-mcp/src/request-handler.ts` exports only one MCP tool, `skills.validate`; it validates a Skill source and does not provide resource/config/session import or export.
- `packages/core/src/runtime/skill-installer.ts:311-335`: `runHookPhase` executes configured pre/post-install commands via `spawnSync("sh", ["-c", command])`, without a timeout or sandbox.
- `prepareInstallerArtifacts` blocks hooks only when the caller explicitly supplies `allowHookCommands:false`. `evaluateHookTrustPolicy` rejects only `sourceType === "well-known"` absent trust; GitHub/Git sources are allowed by default. The production `add.install` caller passes source type, policy mode and trust flag, but omits `allowHookCommands:false`.
- Harmless isolated hook POC used only `printf` to temporary marker files: GitHub/default policy was allowed and wrote marker; well-known/default policy rejected with no marker; GitHub/explicit-deny rejected with no marker. No user data, credentials or real install target was touched.
- Dependency destination validation uses lexical `path.resolve` containment. A temporary symlink POC placed a symlink inside the skill destination pointing to a sibling temp directory; the installer wrote `synthetic-payload` outside the destination. This is a reproduced local symlink escape in the reviewed code, not evidence of a remotely exploitable vulnerability.
- Arbitrary HTTP(S) dependencies use `fetch` then `response.arrayBuffer()` in `prepareDependency`; that function receives no host allow/deny, download-size, or timeout options. This is a static concern, not separately network-probed.
- `installToCanonicalDir` removes the existing canonical directory before copying the new tree; the add path has no atomic staged swap. `update.migrate` has a separate backup/rollback path.
- CodeGraph reports no covering tests for `runHookPhase` / `prepareInstallerArtifacts` / installer security controls.
