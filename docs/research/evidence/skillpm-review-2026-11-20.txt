WHAT IT IS / IMPLEMENTATION
- `skillpm` is an npm-native package manager for reusable Agent Skills. Project model is standard `package.json` dependencies, npm semver/lockfile/registry; package convention is exactly one `skills/<name>/SKILL.md` per package. `SkillPackageJson` and Skill frontmatter are minimal; skillpm does not define or transform per-harness conversation formats.
- `install(args,cwd)` delegates to `npm install`, scans `node_modules` recursively (including nested packages and symlinked npm workspaces), reads SKILL.md frontmatter, rejects duplicate Skill `name` collisions, and calls `npx --yes skills@1.7.0 add <skillDir> -y --json`. It requires one result with status `installed` and scope `project`. It does not pass `--all` or a specific `--agent`, and delegates target discovery/paths to the upstream `skills` CLI. It doesn't implement a cross-Harness adapter matrix itself.
- `sync` repeats scanning/linking. `uninstall` runs `npm uninstall`, then wires remaining packages; code/docs explicitly warn that removed package copies may remain in agent directories and need manual `skills remove`. `skills-lock.json` records upstream install projection separately from npm `package-lock.json`. `publish` validates exactly one skill with official Python `skills-ref` then delegates to `npm publish`. `init` scaffolds a SKILL.md. Repo README explicitly defers full project-wide agent configuration to Microsoft APM.
- Source README says Agent Skills are accepted by Claude, Codex, Cursor, Gemini CLI, Augment and others, but itself warns host-specific frontmatter/tool permissions are not universally portable. The upstream supported-agent table names Claude Code (not Claude Desktop Chat/Cowork); our actual pinned-version probe exercised Codex detection only. No Claude Desktop mode claim is inferred from Skill file presence.
