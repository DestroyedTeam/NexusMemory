## Product surface and canonical data model

LocalSkillManager (`lsm`) is a cross-platform Rust CLI for local Skills only: `add`, `list`, `search`, `pull`, `push`, `remove`, reusable groups, config, and self-upgrade. The only managed runtime assets are `.agents/skills/<name>/` in two scopes: global (`$LSM_HOME/skills`, default `~/.agents/skills`) and project (`<cwd>/.agents/skills`). Project scope is exactly the current working directory; it does not discover a root. Pull/push copy directories, not links. A group is a global TOML list of skill names and `@group` references; nested references are DFS-expanded, de-duplicated, and cycle/missing-reference checked. This is not a ChatGPT Project/Section Group container.

The data model is a directory name + SKILL.md frontmatter (`name`, `description`) plus arbitrary local files. Strict skill names are lowercase ASCII letters/digits/single hyphens, at most 64 characters, with Windows reserved device names rejected. No Session/message/branch/subtask/event graph, transcript, attachments, usage tokens, MCP or plugin config, memory store, schedule, remote-Harness source adapter, or Claude Desktop/Claude Code session writer was found in `src`, docs, or READMEs. The repository scan for session/transcript/MCP/plugin/conversation terms returned no matches. Thus it contributes only local asset-plane patterns, not any requested Project/Session portability.

## Source and safety review

- `src/commands/add.rs`: accepts a local Markdown file or directory; directory basename must match parsed frontmatter name; rejects destination nested inside source; refuses an existing destination without explicit `--force`.
- `src/domain/name.rs`: rejects slash, backslash, dots/path traversal, uppercase Skill IDs, invalid hyphen forms, long names, and Windows reserved names. The parser is tested for traversal-shaped names.
- `src/infra/fsops.rs`: recursively copies in deterministic filename order, rejects symlinks rather than following them, stages into a same-volume sibling temp path, renames the old target to backup only after staging succeeds, rolls the old target back if final rename fails, and cleans or reports leftover backups. `remove` similarly renames to a temp entry before deletion. Explicit `--force` intentionally replaces the named target.
- Source-level caveat: sibling temp and backup names are predictable (`.tmp-<name>-<pid>`, `.bak-<name>-<pid>`) and pre-existing collisions are removed with `remove_existing` before use. No collision POC was run; treat as an unverified stale-name/data-loss edge, not a reproduced finding.
- Project skill groups live in the global `groups.toml`, not per-project metadata. A group contains only skill IDs/references; no project/session tree or target-specific capability/loss model exists.
- Cargo.lock pins the Rust dependency graph; no cross-Harness formats, adapters, migration receipts, or conformance fixtures are present.

## Disposition

Retain as a comparatively strong **narrow Skills ResourcePlane reference**: strict path-safe identifiers, explicit scope, safe default no-overwrite, explicit force, symlink rejection, atomic directory replacement/rollback, and hierarchical reusable Skill groups. Do not adopt as a migration engine or equate its groups with Section Groups. It has no actual Harness session or project import/export. Confidence is reduced by the red full test suite, strict-Clippy failure, no upstream CI runs, small adoption, and a HEAD version newer than its latest tagged release. Full source/test ledger only supports the above local formats and checks.
