MCP adapter review
- `scripts/nanofile_cli.mjs::callMcp` first invokes bundled `nf.exe call ...`; its fallback starts `NanoFile.exe --mcp` and hardcodes protocol version `2024-11-05`.
- Source path uses `initialize` id=1, then immediately sends `tools/call` id=2 on the initialize response; it does not send `notifications/initialized`. The legacy lifecycle specification requires the initialized notification before normal requests. The newest MCP revision (2026-07-28) is stateless and has removed the initialize handshake; this adapter does not negotiate that revision. This is a compatibility concern, not a reproduced failure with the real NanoFile server.
- Stdio parser applies `JSON.parse()` to each arbitrary stdout `data` chunk rather than buffering newline-delimited protocol messages; split or combined messages can be discarded. It silently swallows parse errors and stderr and has no child exit handler. MCP stdio messages are newline-delimited; stderr may be diagnostic and should not be treated as protocol output.
- Synthetic local fake-server probes used a copied JS client and a harmless fake executable; they did not execute NanoFile or touch user files. Whole-message response probe: `rtk proxy env PATH=/tmp/nm-nanofile-probe-20261120/bin:$PATH FAKE_MCP_LOG=/tmp/nm-nanofile-probe-20261120/normal.log node /tmp/nm-nanofile-probe-20261120/scripts/nanofile_cli.mjs probe_tool '{"key":"value"}'` exited 0 and printed the following pretty JSON on stdout: `{
  "ok": true
}`. Captured request methods were exactly `initialize`, `tools/call`; no `notifications/initialized` was sent.
- Fragmented-response probe used the same client copy, an MCP initialize JSON response deliberately split across two stdout writes, and a wrapper that shortened the client's 15s timer to 500ms. Observed child exit 1, stdout empty, stderr `ERROR NanoFile MCP 调用超时 (15000ms)`; fake-server log contained only the initialize request. This proves the tested client code loses that synthetic fragmented response; it does not establish behavior of the unavailable Windows NanoFile app or every Node pipe schedule.
