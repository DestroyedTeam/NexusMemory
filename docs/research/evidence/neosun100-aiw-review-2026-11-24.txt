## Product model and migration fit

AIW manages running local agent CLIs inside persistent tmux sessions. Each workspace record is a small metadata object (`tool`, `model`, `desc`, `dir`, `created`) keyed by workspace name in `~/.config/aiw/sessions.json`; tmux stores the live process/session. The tool can start a new CLI in a project directory, attach, show recent terminal output, send commands and kill one/all workspaces. REST/WebSocket, local CLI and stdio MCP are management surfaces.

This is **live process/workspace orchestration**, not a transcript importer, history archive or migration graph. A `dir` is a single workspace binding, not ChatGPT Project/Section Group or nested Session hierarchy. The source has no source/target adapter, raw transcript/event model, import/export bundle, parent/fork/subtask/artifact links, attachment/tool/usage preservation, Skills/MCP/plugin transfer, memory migration, or scheduled-task converter. It launches tools such as Gemini/Kiro/Claude CLI from configured commands; it is not a Claude third-party-gateway/API-Key provider adapter or a writer into Claude Desktop Chat, Cowork or Code session stores.

## Security and source defects

- README and source default the HTTP server to `0.0.0.0`; REST endpoints and WebSockets cover create, send-to-agent, kill, logs and interactive terminal attach. No authentication/authorization middleware is present. README itself warns to add an authenticated reverse proxy and HTTPS before exposure. This is a material deployment risk for a service that can control agent shells.
- `src/aiw/tmux.py::_run` invokes `subprocess.run(..., shell=True)` and interpolates workspace names, paths, tool configuration and terminal commands into shell strings. Treat inputs/config as privileged; do not expose this API as a trusted migration endpoint.
- `rename_workspace` references `SESSION_PREFIX`, `run_tmux` and `META_DIR`, none of which are defined in the indexed `tmux.py`; it uses a metadata-file layout different from `config.py`'s `sessions.json`. API and README advertise rename, but there is no rename test. A synthetic safe probe patched `workspace_exists` to return true and called `rename_workspace('fixture-old','fixture-new')`; observed `NameError: name 'SESSION_PREFIX' is not defined` before any tmux/shell operation.
- The MCP server exposes `aiw_create`, `aiw_send`, `aiw_kill`, logs and status through stdio. The HTTP app's API/test paths do not authenticate; tests call routes with no auth header. MCP is a control plane, not an import/export contract.
