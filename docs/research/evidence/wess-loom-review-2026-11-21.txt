## Scope and model

Loom is a small Rust CLI/Homebrew-style package manager for reusable agent Skills. Its manifest is a YAML recipe (name/version/license/source/ref/subdirectory/entry/files), not the skill payload. The installed-state JSON only tracks `{name, version, agent, path, source_url}`. Config maps arbitrary agent IDs to skills directories; shipped defaults are `claude-code`, `codex`, and `cursor`. Git refs can be tags/branches/commits; archive manifests require SHA-256. The website catalog stores manifests, and Loom's own `~/.loom` holds config, state, and fetch caches.

No Projects, Sections/Section Groups, transcripts, Sessions, message/event/branch trees, parent-child sessions, attachments, token/cost use, MCP/plugin configuration, schedules, or memory stores are represented. It has no ChatGPT/Codex Projects or session importer, no Claude Desktop Chat/Cowork/Code adapter, and no Cloud/API-key session writer. “Agent” is a directory-placement target; it is not a session-runtime adapter. Thus it does not address the confirmed migration target beyond an adjacent Skills ResourcePlane.

## Source review

- `src/manifest/mod.rs`: manifest fields are a Skill payload recipe. Git `ref` may be a movable branch; no resolved commit/tree hash is persisted in the installed registry. `compatibility` is advisory rather than an enforced capability matrix.
- `src/config/mod.rs`: defaults are Claude Code, Codex, and Cursor skill folders; adding another local directory does not make it a Desktop history adapter.
- `src/install/mod.rs`: before each install, `target = agent_skills_dir.join(manifest.name)`; if it exists, `remove_dir_all(target)` runs unconditionally, then the fresh payload is copied. There is no ownership/managed-marker check or per-operation confirmation. State tracks only the simple registry record.
- `src/manifest/mod.rs` validates that a name is lowercase/nonempty/no whitespace, but does not reject path separators or `..` segments. `src/install/mod.rs` directly joins the untrusted name to the target root.
- `src/fetch/mod.rs`: Git source refs are fetched via `git`; archives are checked against declared SHA-256. These are useful reproducibility primitives but do not constitute a bundle-level or session fidelity lock.
- CI (`.github/workflows/ci.yml`) runs release build, Rust tests, manifest lint, and website index generation. The 15 Rust unit tests cover manifest parsing/linting, URL/front-matter parsing and presentation; CodeGraph reported no covering tests for install/state/path behavior. There is no Project/session-import conformance suite.

## Disposition

Reject as a Nexus Memory migration dependency. Retain only the general Skills packaging ideas—source manifests, explicit source refs/checksums, per-target resource projection, and non-mutating fetch/test—implemented independently with strict safe names, immutable content digests, target ownership checks, preview/approval, staged transactional writes, and rollback. The project is very small/low-adoption and demonstrates narrow resource placement, not cross-Harness transfer fidelity. Do not call the observed 15 tests or CI status evidence of migration accuracy.
