## Capability boundary against Nexus Memory

This is a useful **Skills resource-package manager and trust layer**, not a cross-Harness memory/session migration engine. It installs `SKILL.md` packages to Claude Code, Codex, Cursor, and VS Code/GitHub Copilot target directories. The adapters and README do not provide a ChatGPT/Codex Projects, Section Group, or Session reader/writer; no Session event/fork/parent-child graph, transcript/turn chronology, attachments, token/cost state, MCP/plugin transfer, schedule/task transfer, or memory-plane migration was found. The TUI's own `Session` concept is transient application UI state, not a model-conversation session. It does not target Claude Desktop third-party-gateway Chat, Cowork, or Code session stores, and it does not import/export local Claude Code conversation files. Those three Desktop surfaces remain separate acceptance tracks, alongside local/self-hosted Claude Code.

Keep as **adjacent design references only**: explicit Skill capabilities and consent, package SHA-256 lock/integrity verification, archive path/symlink/size validation, static scan plus policy gating, transactional multi-target writes, journaled crash recovery, and rollback. Its security docs correctly warn that static scan is not a safety verdict; no sandbox is provided and runtime-generated/reworded behavior can evade heuristics. Treat any candidate use as untrusted package-management code requiring independent security review; do not reuse it as the migration engine or infer a Skill match from names alone.
