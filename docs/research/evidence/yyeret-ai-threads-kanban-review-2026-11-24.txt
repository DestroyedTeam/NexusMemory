## Product, source formats and data model

This is a local workflow dashboard and session finder for already-running native harnesses. README highlights Claude Code, Codex and Gemini CLI; source scanning also includes Google Antigravity. The scanners read:

- Claude Code: `~/.claude/projects/**/*.jsonl` transcripts, excluding `subagents/`; live `~/.claude/sessions/*.json` and `history.jsonl` can enrich cwd/title fallbacks.
- Codex: `~/.codex/session_index.jsonl` plus rollout JSONL under `~/.codex/sessions/`; it also finds rollout files missing from the index when their filename yields an ID.
- Gemini CLI: `~/.gemini/tmp/**/chats/session-*.json[l]` and `projects.json`.
- Antigravity: `~/.gemini/antigravity/brain/**/.system_generated/logs/transcript.jsonl`.

Default scan window is 30 days. The scanner writes `threads.<machine>.jsonl`, a per-machine Markdown board, and legacy aliases under the configured registry root. Reconciliation merges per-machine scanner cards into `active-threads.jsonl` / `active-threads.md`, preserves selected manual fields, and flags sessions absent from the current scan window instead of deleting their registry row. Optional shared-folder synchronization is eventually consistent; last-writer-wins and concurrent reconcile behavior are not made transactional.

Each scanner card is a **summary/pointer**, not an event archive: harness label, session ID, cwd, transcript path, first prompt/title, last user/assistant text, activity, approximate tool/user counts, heuristic workflow stage and resume string. The registry groups one or more native sessions under a workflow “thread,” but does not preserve per-message event bytes, tool argument/result chronology, forks, parent/child/subagent relationships, interruption/edit/retry edges, attachment payloads, context-window/token/cost records, native Project/Section/Section Group hierarchy, or a portable target import manifest. The board's Kanban lanes and OKR-style Goals are product workflow/goal objects, not source ChatGPT Projects or nested sections. It has no ChatGPT parser, Claude Desktop third-party-provider Chat/Cowork/Code reader, Anthropic Cloud writer, or Claude Code API-Key session importer.

### Thread identity and merge behavior

`repo_key` is only the lowercased final basename of `cwd`. `intent_hash` is the first 10 hex characters of SHA-1 over the normalized first real prompt (or title fallback), lowercased, punctuation-stripped and truncated to 240 characters. `thread_id` is the first 12 hex characters of SHA-1 over `repo_key|intent_hash`. Reconciliation also fuzzy-merges cards from the same `repo_key` if both contain at least five intent tokens, at least four are shared, and Jaccard similarity is at least 0.55. This can merge different repositories sharing a directory basename and can merge distinct sessions with similar wording; it may also split one task when first prompts differ substantially. These are intent-cluster heuristics, not stable source identities or faithful Session lineage. Within a group, sessions are deduplicated by `harness:session_id` (machine is recorded but not part of the dedupe key), sorted by activity, and stored as a flat session list. No typed fork/parent/subagent edge is present.

Manual state such as stage, completion status, area and note survives rescan. Automatic stage/status inference uses keyword and recent assistant-text regexes plus tool counts; it is explicitly a heuristic. Goal grouping and thread-to-goal assignment are separate derived/override files, not native session hierarchy. Only a single latest session is selected by the board's continue route, rather than prompting for a source branch or a target profile.

## Native resume, rename and archive side effects

The board links to local native commands: Claude Code `claude --resume <id>`, Codex `codex resume <id>`, Gemini CLI `gemini --resume latest`, and an Antigravity message that direct terminal resume is unavailable. Resume opens a local terminal in the recorded cwd and may copy the suggested next step to the clipboard. It does not import/fork a session into another harness or rebuild a native context graph.

The optional Codex-specific name/archive writer stamps `[Stage] title` into `~/.codex/session_index.jsonl`. On explicit manual-Done it moves a rollout file to `~/.codex/archived_sessions/` and removes its index line; it does not retain an archive receipt or transaction journal. Claude Code/Gemini picker titles cannot be rewritten by this tool. This is a potentially useful local workflow affordance, but it is a destructive native-state side effect and is not a portable cross-harness archive operation. I did not run the installer, hook, resume or archive writer against any real user profile.

## Runtime/server/install security review

The zero-dependency Node HTTP server binds `127.0.0.1` only, but has no login/authentication, CSRF token or request-origin validation, and its route dispatcher does not restrict mutations to POST. State-changing endpoints include GET `/set-stage`, `/set-goal-stage`, `/set-thread-goal`, `/create-goal`, `/update-goal`, and `/refresh`. A disposable test `HOME`/registry seeded only with one synthetic thread received GET `/set-stage?id=synthetic-thread-1&stage=Plan` with `Origin: https://evil.invalid`; response was HTTP 200 body `ok`, and both `stage` and `manual_stage` persisted as `Plan`. This confirms the unauthenticated GET mutation path; it is not a browser exploit demonstration, and loopback/private-network browser defenses can affect exploitability.

`/continue` ultimately passes a raw generated resume string to terminal-launch code. The Codex ID is copied from local `session_index.jsonl` without an allowlist or shell quoting; on macOS the command is embedded into an AppleScript `do script` string and executed by Terminal. In a disposable synthetic HOME, a synthetic index ID `fixture; echo NM_UNEXECUTED_SENTINEL` produced stored resume command `codex resume fixture; echo NM_UNEXECUTED_SENTINEL`. The command was **not executed**. This demonstrates untrusted session metadata can reach a shell command boundary; do not treat a native resume link as safe without identifier validation/argv-based launching.

`/refresh` can run `git pull` on the application repository and invoke `npm install` if `package.json` changed. Installer scripts write registry-root/version/deployment files under the real home, write Codex hook config when absent, print manual hook instructions for Claude/Gemini settings, scan native histories, and optionally create a launchd LaunchAgent (macOS) or Scheduled Task (Windows). README says “No daemons,” but install instructions start the web server in a background process manager/task. Do not run installation or refresh against real profiles as part of a migration review. The UI presents transcript previews and stores prompt excerpts/paths in the registry; optional Drive/Dropbox sync is not an encryption or secret-redaction guarantee. `reconcile-threads.mjs` also reads local `skill-telemetry/events.jsonl` to detect `finish-thread` events and the board exposes a local Telemetry Insights view; no remote telemetry egress was observed in the reviewed scripts.

README says the tests do not cover server handlers, but `tests/serve-thread-board.test.mjs` does exercise several local GET board/goal mutations. The dedicated tests README is stale for that row. The scanner/classifier has no covering test according to its README and the reviewed test suite, and current tests do not check Origin/CSRF behavior, resume-shell injection, prompt redaction, thread collision/split/merge quality, scanner compatibility with real evolving transcript formats, or cross-machine concurrent writes.

## Disposition and transfer value

**High-value adjacent reference for a local SessionInventory/workflow board, not a Session migration system.** Preserve as prior art for local format-specific readers, per-machine discovery, a human-reviewed workflow overlay, stable UI abstraction, and explicit per-harness resume/archive capabilities. Do not adopt its fuzzy thread IDs as canonical identity, flattening into a single user-intent thread as native Session lineage, or claim the board's “Goals” as imported Project/Section structure. Any Nexus reuse/deployment requires separate security review and hardening first: allowlisted resume IDs and argv launches; POST + CSRF/origin protections for mutations; explicit confirmation/transaction receipt for native Codex archive; versioned adapters with real synthetic/representative fixtures; path containment; secret minimization/redaction; and concurrency-safe registry writes. MIT permits source reuse in principle, but current security/data-integrity and fidelity gaps make direct adoption inappropriate. No real profile, transcript, credential, API key, chat, project or session was read or modified.
