## What it does / fit to Nexus Memory

This repository provides two Agent Skills: `skill-router` instructs an agent to scan the current installed skill shelf and rank/load up to three descriptions; `skill-manager` provides shell operations to list/count/search/info/validate/disable/enable/install skills. `catalog.sh` prints descriptions; `manage.sh` manipulates skill files in the same shelf. These are local ResourcePlane/shelf-management and workflow-routing patterns.

There is no ChatGPT/Codex Project, Section, Session, turn/event, parent/child/fork graph, transcript, attachment/artifact, token/cost, MCP/plugin, memory, provider, or scheduled-task migration. “Works for every agent” means proposed SKILL.md discovery conventions, not one native adapter per agent and not a portable session format. No Desktop 3P Chat/Cowork/Code archive reader/writer or local Claude Code session adapter exists. Treat it as an adjacent Skill UX reference, not a Nexus Memory migrator.

## Disposable synthetic safety probes

All paths below were under `/tmp/nm-skill-router-synthetic-20261123-*`; no real skill home or user file was touched. Tests invoked the actual checked-out `manage.sh` with `SKILLS_HOME` pointing to the disposable fixture.

1. **Path escape in skill-name resolution:** Created `<tmp>/outside/victim/SKILL.md` and set `SKILLS_HOME=<tmp>/home`. `rtk bash .../manage.sh disable ../outside/victim` exited 0 and printed `disabled: ../outside/victim (SKILL.md -> SKILL.md.disabled)`. Post-state: outside `SKILL.md` absent and outside `SKILL.md.disabled` present. `skill_dir()` accepts a name containing `../` and mutating commands operate beyond the skill home; `info`, `enable` have the same resolver.
2. **Disable overwrites an existing disabled backup:** Created `home/collision/SKILL.md` containing `ACTIVE_SENTINEL` and `SKILL.md.disabled` containing `OLD_DISABLED_SENTINEL`. Actual `disable collision` exited 0, reported success, removed the active filename and silently replaced the existing disabled file with the active contents. The prior disabled copy was lost.
3. **Enable overwrites an existing active skill:** With the displaced disabled copy present, created a competing active `SKILL.md` containing `ACTIVE_RESTORED_CONFLICT_SENTINEL`. Actual `enable collision` exited 0 and reported success; it replaced the active file with the disabled copy and removed `SKILL.md.disabled`. The competing active file was lost.

## Disposition

Keep the idea of runtime inventory and skill description matching as a separately versioned Skill ResourcePlane feature; require per-Harness directory capability maps and separately test whichever installer the user actually chooses. Reject the current helper as a safe mutator without (a) canonical containment of all names under the selected skill home, (b) no-overwrite checks for both disable and enable, and (c) Bash/macOS compatibility fixes plus nonzero exit on scan failure. Do not claim skills can restore any session context. The four Claude destination tracks remain `desktop-3p/chat`, `desktop-3p/cowork`, `desktop-3p/code`, and `claude-code-local`; none is implemented here.
