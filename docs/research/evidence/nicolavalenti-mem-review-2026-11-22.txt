## Source and behavior findings

- `mem.py` stores text chunks with `source`, `kind`, `tags`, a content SHA and timestamp in one SQLite DB plus a `sqlite-vec` vector table. The embedder is local (`fastembed`, `BAAI/bge-small-en-v1.5`, 384 dimensions), and the CLI/MCP/Pi integration share one query/add implementation. This is useful for durable fact recall, but has no first-class Projects, Section Groups, conversation graph, source message IDs, parents/children, branches, attachment/blob store, model/token/tool-call metadata, or exact turn replay.
- `nightly_ingest.py` converts only readable user/assistant text from three transcript formats into Markdown; tool events and non-text content are discarded, each turn is truncated to 2,000 characters, and it indexes only Markdown. There is no generic transcript-export parser or Claude Desktop Chat/Cowork/Code input.
- `idle_checkpoint.py` filters sessions by file mtime/turn counts, uses only the first 3 and last 30 turns (40,000-character prompt cap), and asks `$HOME/.local/bin/claude -p --model haiku --output-format json` to produce a handoff note. Python writes the file and timestamps; state is tied to the transcript mtime. This preserves a useful freshness/idempotence model, but the text is sent to the installed Claude CLI's configured model endpoint; the memory tool does not guarantee that summarization traffic is local. No summarization/API call was made during review.
- Handoff metadata includes harness/session/title/project/repo/turn count, but no parent or child links. `resume.py` lists and prints Markdown notes; it does not restore a non-Claude native session. `write_handoff` hardcodes a `claude --resume <session-id>` instruction for every harness. A synthetic Pi handoff was written under a disposable directory and observed literal line `Resume this session with: `claude --resume pi-synthetic-123` ...`; that is a misleading resume action for Pi/Codex. The note itself says to prefer a fresh session from the handoff.
- Repo path attribution scans `file_path` strings only and recognizes `/Projects/<name>` or `/Apps/<name>`, capped at the first 30 MiB and top three repositories. It is not a general workspace map.
- `checkpoint_now.sh`, `bin/Mem Checkpointer`, and `session_catchup.sh` are user-specific shell/launchd integrations. Two scripts hardcode `/Users/nickvalenti/Projects/mem` and `.local/bin/uv`; these are not reusable cross-platform adapters. `integrations/pi/mem.ts` is the only harness-specific extension shipped. Claude Code and Codex setup instructions are manual; no Claude Desktop config writer or developer-mode gateway integration exists.
- Privacy boundary: embedding/query storage is local after installation, but checkpoint summarization invokes the Claude CLI with transcript text. The README’s “no cloud” describes storage/embedding, not a tool-enforced guarantee about the summarizer backend.
