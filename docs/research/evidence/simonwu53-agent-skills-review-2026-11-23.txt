## What it implements

This is a Bash personal Skill library manager. `main.sh` dispatches `--load/--unload`, `--install/--update/--remove`, `--list`, `--pin/--unpin`, and `--sync`. `config.yaml` models source repositories/local Skills, Skill subpaths/categories, a Boolean pin flag, and coarse install destinations. `download.sh` accepts root GitHub repositories, local folders, and ZIPs; `install.sh` copies by default or symlinks and may clear a tool's destination first; `sync.sh` refreshes Git submodules but does not update already-copied installs. Each Skill is essentially a folder containing `SKILL.md` plus optional assets.

The `claude` tool adapter is one generic path mapping: global `~/.claude/skills/`, project `<project>/.claude/skills/`. It does not distinguish Claude Desktop 3P Chat vs Cowork vs Code, standard Desktop vs 3P, or standalone CLI. There is no parser/writer for ChatGPT/Codex history, Project/Section IDs, message/turn/event records, active branches, parent/child sessions, interruption/re-prompt lineage, images/files/links, token/cost usage, memory, schedules, MCP definitions, plugin bundles, permission decisions, outputs, or target-native resume IDs. It cannot migrate the requested session structure.

## Current official Claude Desktop on 3P cross-check

The official [Desktop 3P overview](https://claude.com/docs/third-party/claude-desktop/overview) explicitly supports Chat, Cowork, and Code, routes model inference through the configured provider/gateway, and keeps conversation storage on the device. The [feature matrix](https://claude.com/docs/third-party/claude-desktop/feature-matrix) says device-local conversation history exists while Anthropic-cloud sessions do not. The current [local-data map](https://claude.com/docs/third-party/claude-desktop/data-storage) says Chat and Cowork use `local-agent-mode-sessions/` session-state JSON plus per-session working directories (uploads/outputs, audit/transcript, memory); Code session metadata is in `claude-code-sessions/`, while transcripts live separately in Claude Code's `~/.claude/projects/`. The same pages describe local provider credentials, device identity, app settings, and data that does not pass through the inference gateway.

The user selected all three Desktop modes in the latest clarification response. Current [Unified Claude documentation](https://claude.com/docs/third-party/claude-desktop/unified-claude) says the UI can combine Chat and Cowork and list their histories together, while Code stays separate; the actual started mode can depend on the device's Cowork VM. Preserve mode/source-store identity, not just a UI label. Current [extensions documentation](https://claude.com/docs/third-party/claude-desktop/extensions) separates managed MCP servers, organization plugin distribution and per-user in-app extensions. Desktop records user-created/uploaded Skills and directs delivery through organization plugins/marketplaces; plain `.claude/skills` filesystem Skills are documented for Code sessions. The candidate's one-path “Claude Desktop / Code” row therefore cannot certify Skill discovery in all three 3P modes. No Desktop profile, local store, API key, or provider was accessed in this review.

The official migration guide documents Claude-origin import/copy workflows with omissions; these are not generic ChatGPT/Codex import APIs. A configured inference gateway receives model requests/responses, not all local session events such as permission decisions.
