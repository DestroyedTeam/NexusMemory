## Product and data boundary

- The product is a local document-processing/plugin bundle for PDF, DOCX, XLSX, PPTX, Markdown, OCR, document QA, and flipbooks. Its cross-Harness story is distribution of document skills and scripts, not chat/session migration.
- `.agents/plugins/document-os/plugin.json` registers `document-router`, `document-qa`, and `flipbook-generator`, with a brand-identity skill dependency. There is no native transcript importer, session archive reader/writer, Project/Section/parent-child model, or MCP server implementation in the pinned source.
- `export_cross_harness.ps1` recursively copies skill files into Claude Code global/workspace `.claude/skills`, OpenCode `~/.config/opencode/skills`, and an Antigravity path. It does not convert chat history, project or section hierarchy, user memory, MCP configuration, plugins, attachments, tool calls, branches, schedules, or usage/token metadata. The README's broader list of Harnesses is not evidence of target-native session fidelity.
- The script's `ValidateSet` accepts `Universal`, but its dispatch branches handle only `ClaudeCode`, `OpenCode`, `GlobalAntigravity`, and `All`; selecting `Universal` has no matching copy branch. This is a static control-flow finding; the potentially no-op mode was not executed.
- The POSIX installer creates a Python venv and installs unpinned latest package versions. `--global` copies the plugin to the Gemini/Antigravity directory only. The export uses `Copy-Item -Force` and has no visible dry run, target backup, conflict report, transaction/rollback, post-copy verification, or session-data safeguards.
- A corrected static file scan found no `conversation`, `session import`, `chat history`, `project hierarchy`, `section group`, or `MCP server` references in the local repository. The README's “MCP & deterministic tooling harness” framing did not correspond to an MCP server implementation in this checkout.
