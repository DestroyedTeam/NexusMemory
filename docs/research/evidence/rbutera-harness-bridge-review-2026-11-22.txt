## Source findings

- README configures Claude Code to call Codex or Codex to call Claude. Codex threads use the native persistent `threadId` and can be resumed. Claude-side `threadKey` maps to a Claude session ID through an in-memory `SessionRegistry` Map; that relation is not persisted across server restart.
- The MCP task inputs do not accept sandbox/approval policy controls. The CLI backend builds Codex args with `--dangerously-bypass-approvals-and-sandbox`; the app-server backend starts/resumes threads and turns with `danger-full-access` / unrestricted sandbox policy. This is unsafe as a default when caller trust does not imply permission for unrestricted local execution.
- Source contains generated app-server protocol types resembling Codex migration/session descriptors, but searched runtime modules contain no `externalAgentConfig/detect` or `externalAgentConfig/import` invocation. A type declaration is not a migration feature.
- No ChatGPT Projects, Section Groups, ChatGPT/Codex Session graph import, Claude Desktop Chat/Cowork/Code session store, skills/MCP/plugin resource transfer, attachments, usage ledger, schedule, or project membership adapter is implemented.
