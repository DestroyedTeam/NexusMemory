## Product scope

Raycast extension that browses Skills from skills.sh or GitHub, discovers SKILL.md files, and installs to 40+ configured AI-coding-assistant skill paths via symlink/copy. A global ~/.agents/.skill-lock.json tracks source URLs, git commit hash and timestamps for update detection. It is not a harness state migrator: no Projects/Section Groups, session/conversation records, parent/branch/turn/subtask graphs, transcripts, attachments, token use, scheduled tasks, MCP/plugin configuration or memory import/export. No Claude Desktop Chat/Cowork/Code mode-specific adapter; Claude Code is only one Skill directory target, with no API-Key/gateway functionality.

The README says users can choose global or project scope, but pinned src/commands/install-flow.tsx declares scope as the literal global value, comments out the scope-selection UI, explicitly skips it, and passes global:true to installSkillForAgent. Thus current UI installation is global only.

## Dynamic installer probe (synthetic temporary files only)

A temporary CJS harness transpiled the pinned src/installer.ts, src/agents.ts and src/constants.ts via the installed TypeScript compiler, then invoked installSkillForAgent with global=true and mode=copy. All test paths were under /private/tmp/nm-agent-skills-manager-review. Input skill directory contained SKILL.md and an external.txt symlink pointing to a separate synthetic marker file; fake target ~/.claude/skills/probe-skill already contained unmanaged.txt. Result: success=true; copied external.txt contained the marker from outside the source skill directory; pre-existing unmanaged.txt did not survive; sanitizeName(../../escape) returned escape. No user data, credentials or Raycast production UI were touched.

Source cause: copyDirectory uses fs/promises cp with dereference:true; cleanAndCreateDirectory unconditionally rm-recursive/force deletes the destination before writing. This demonstrates arbitrary external-file reads from malicious skill symlinks when the user installs such a repository, and destructive replacement of an unmanaged skill directory. It does not demonstrate network exfiltration or real credential access.

## Decision

Low-level SkillsPlane adapter reference only. Positive: broad agent path table, canonical skill store, symlink/copy support and source commit lock metadata. Not a Nexus Memory session/project hierarchy implementation. Required hardening before adopting code: reject symlinks or enforce realpath containment during source copy, maintain managed-file ownership/backup and atomic replacement, implement project scope before claiming it, and explicitly separate Claude Code from Claude Desktop modes.
