## What it is / is not
- README calls it a public, stateless, skills-only plugin. It ships exactly one `skills/manage/SKILL.md`, no preset third-party skills, no shared user state and no backend. The skill has DISCOVER, STATUS and approval-gated MUTATE workflows for GitHub-hosted `SKILL.md` items. It can optionally use a verified user-owned USER/PRIVATE Plugin Creator collection with `sources.json` v1; the public plugin itself is not a repository/session database.
- It is a Codex/ChatGPT plugin/skill manager, not a Harness interchange or migration product. No chat/session parser, Project/Section/Session schema, parent-child/branch graph, media/attachment transfer, token-usage records, memory/schedule migration, native restore adapter, Claude Desktop Chat/Cowork/Code adapter, or local Claude Code target adapter exists. The only Python product code is `scripts/validate.py`, a source-package/manifest validator; runtime actions depend on whichever host tools are available. README explicitly says it does not E2E-test conversations, installations, Plugin Creator writes or activation.
- Useful design concepts only: separate read-only discovery from mutation; compare full relevant inventories; pinned source revisions; preserve local edits; one approval for a concrete write plan; truthful `Unavailable`/`Not checked` status. These are ResourcePlane UX/security patterns, not a transferable SessionGraph.

## Disposition
Do not adopt as a migration dependency and do not describe it as Cloud/Claude session support. Retain as a narrow design reference for a future Skill ResourcePlane. It cannot satisfy the user's request to port ChatGPT Projects, Section Groups, Destruction Era session hierarchy, or session contents to Claude Desktop's three separate modes or local/self-hosted Claude Code.
