IMPLEMENTATION / DOCUMENTATION GAPS
- README describes budget-aware injection respecting remaining context-window tokens. The reviewed source calculates estimatedTokens only from the existing messages (roughly chars/4) and caps retrieval by result count topK; it does not compare retrieved snippets against a remaining token budget.
- README describes hybrid BM25 + semantic retrieval. The repository itself delegates to an external qmd-shim.js and its source comment calls the invoked QMD search command BM25 with no LLM expansion. Hybrid/semantic behavior is not established by this implementation and depends on the external shim/QMD runtime.
- README advertises graceful/silent passthrough. A timeout is caught by assemble() and emits console.warn before returning the base messages; a nonzero child exit resolves as an empty result. This is not a session loss issue, but the wording is broader than the code.
- The retrieved snippet is passed into a system-prompt addition; the code has no explicit trust label, source approval, redaction, or prompt-injection boundary. This is a design/security concern inferred from source, not an exploited vulnerability.
- qmdShimPath is executable Node code and spawn inherits process.env. There is no bundled shim, signature/provenance lock, or output-size cap. The code passes argv without a shell, but prompt text is included as a process argument.
