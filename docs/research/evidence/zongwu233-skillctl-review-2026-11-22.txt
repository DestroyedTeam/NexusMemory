## Functional scope and model
Commands inventory SKILL.md directories, rank textual skill-description overlaps against a task, compute a description-token budget, apply enable/disable profiles, run an install scanner, copy a selected Skill, and prune broken links/duplicate inode links/empty directories (dry-run by default).
The directory inventory covers Claude Code, Codex (including a labeled Codex .system scope), OpenCode, Pi recursive collections, and OMP. It models a skill's name/path/runtime/scope/enabled state/description/body lengths/frontmatter flags. Project detection is filesystem-root based; it searches configured global/project paths. It has no ChatGPT, Claude Desktop Chat/Cowork/Code adapter, Section Group structure, Conversation/Session/event/branch/subtask graph, attachment/media store, native session restore, model/token usage history, MCP/plugin import, independent memory, or schedule model.
Token accounting is explicitly heuristic: len(text)//4 and counts skill descriptions against a description-token threshold. Body handling reports words/lines and a per-Skill redline; it is not a tokenizer nor per-session consumption measurement.

## Source-level strengths worth retaining independently

## Reproduced implementation and safety findings (all in disposable temp directories)
1. Codex profile scope leaks to user scope. Running use <profile> --project for a Skill discovered only under a temp repository's .codex/skills returned 0 but wrote the rule to the temp HOME/.codex/config.toml; it created no repository .codex/config.toml. Code filters records by project_only but set_codex_config always targets HOME/.codex/config.toml.
2. Codex settings rewrite discards existing skill blocks. Starting with model = "gpt" and a disabled [[skills.config]] path="/keep-disabled", set_codex_config([], ["/new-disabled"]) preserved model but replaced the full skills.config array with only /new-disabled. README profile example says names not listed are left untouched; current behavior contradicts that statement and may re-enable/forget prior disabled skills. Existing test_codex_blocks_roundtrip asserts this replacement, so the suite encodes rather than catches it.
3. Malformed Claude settings are overwritten. _read_json treats JSONDecodeError as an empty object; a synthetic partially-written settings.json passed to set_claude_overrides was replaced by a valid object containing only skillOverrides. The operation has no backup/atomic replacement path.
4. Scanner output fails open for malformed JSON plus exit 0. A temporary fake scanner wrote non-JSON text and exited 0; run_gate returned ok=true / SAFE with no error. The real Skillspector was unavailable, so this is a wrapper behavior probe, not a claim about Skillspector's own output.
5. Install follows a symlink outside the source root. A temp Skill with a relative symlink to a sibling synthetic file was copy-installed; the destination entry became an ordinary file containing the target bytes. shutil.copytree(..., symlinks=False) dereferences rather than rejects such links.
6. --force is delete-first, not transactional. With an existing destination marker in a temp tree, an injected copytree OSError after the force removal left both the destination and marker absent. The probe verifies operation ordering and failure-state loss; the copy error was injected, not an OS-level disk-full simulation.
7. SkillSpector is an unpinned external executable configured by name/path. Missing scanner is an error; no actual scan verdict is claimed here.

These are local probes against pinned source, not upstream CI and not live Harness data. Workaround ideas for Nexus must be implemented independently: preserve unmanaged config blocks, make scope-aware writers, stage-and-verify before replacing, reject symlink escape, validate scanner output fail-closed, and record exact source/version/digest.
