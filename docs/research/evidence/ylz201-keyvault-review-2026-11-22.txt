## Scope and product fit

The current `main` checkout is a local encrypted secret vault with a CLI, Python SDK, and stdio MCP server. It imports/exports `.env`, injects secrets into a process environment, scans `.env` candidates, and supports global/project scopes. It contains no ChatGPT export parser, Project/Section/Session graph, conversation event/media/token serializer, hierarchy-preserving archive, Claude Code transcript writer, or Claude Desktop Chat/Cowork/Code session writer. A Claude Desktop `claude_desktop_config.json` example only installs this MCP server; it does not move or resume conversations.

Current-main MCP policy is restrictive by default: list/get/set/delete/global/all-scopes/all-keys are false; project scope is required unless explicitly relaxed; arbitrary keys require `KEYVAULT_MCP_ALLOWED_KEYS` or `KEYVAULT_MCP_ALLOW_ALL_KEYS=1`. If `secrets_get` is deliberately enabled, it returns the plaintext secret as MCP text. This is a secret-provisioning interface and must not be confused with migration of a credential reference or session.

The vault encrypts values and metadata with Fernet (AES-128-CBC plus HMAC-SHA256); it uses an OS keyring when available and otherwise `~/.keyvault/master.key`, with owner-only directory/key/database permissions. The code blocks silent master-key regeneration when data is present. This is an adjacent local SecretPlane pattern, not a transfer format.

## Current main vs open PR #1

GitHub PR #1, “KeyVault 0.2 — independent Agent Credential Gateway,” remains **open and unmerged**. Its head is `a515e4fbb3d83f7815c9fe21acd0f8b93e8a0956`; it must not be attributed to current main. Current main removes the gateway implementation/docs/tests present on that PR branch, including `keyvault/gateway/*`; it also has no `.github` workflow directory. The passing historical PR Actions run applies to the PR synthetic merge commit, not current main.

The unmerged PR is a POSIX local reference gateway, not a general inference gateway or a migration engine. Reviewed branch design:

- A separate administrator/client boundary over bounded authenticated Unix-domain RPC; client tokens are hashed in state, client/workspace identities are checked, and state files are owner-only with symlink rejection.
- Administrators register immutable fixed HTTPS GET operations and grant a specific client bounded, expiring, revocable use. Agent requests cannot choose a URL, method, headers, body, or shell command.
- Credentials are resolved server-side by exact project/key lookup. Grant state is bound to a credential revision; changed credentials invalidate the grant rather than silently following a rotation.
- SQLite commits a request UUID and quota reservation before making the external request. Replays do not re-send; an interrupted/ambiguous operation is `EFFECT_UNKNOWN` and cannot be retried with a new use automatically.
- Transport validates public DNS answers, connects to the selected numeric address with hostname-verified TLS, rejects redirects and proxy environment use, bounds response size/time, and projects a small allowlisted typed output. The agent receives projected fields, not the upstream secret.
- The interface is fixed GET / narrow returned data; it is not a Claude Desktop inference gateway, does not provision Desktop's `inferenceGatewayBaseUrl` / `inferenceGatewayApiKey`, and does not restore a session.

## Nexus recommendation

Keep credentials external to the canonical migration bundle. Store an opaque credential locator/reference and required target-side re-link action if useful; never copy source API keys, OAuth tokens, MCP auth or permission grants into a destination transcript or session. A SecretPlane may optionally learn from the *design intent* of isolated credentials, revision-bound grants, least privilege and no-secret audit outputs, but candidate implementation is current-main local vault code plus an unmerged alpha PR and is neither an inference gateway nor a transcript importer. Do not advertise its PR as a released capability.
