What it does
A local TypeScript CLI named abridge reads persisted Pi, OMP (Oh My Pi) and Codex CLI session JSONL, normalizes sessions into a canonical representation, exports a checksum-verified .acx archive, prepares handoffs, and supports version-pinned native storage imports for Pi 1.5.1 and OMP 18.16.0. It has two distinct profiles: archive preserves much more source/event/raw data with best-effort redaction; context-only generates a new semantic checkpoint. Transfer profile and recovery mode are separate. It is a useful adjacent session-migration reference, not a ChatGPT/Claude migration implementation.

Data model and fidelity
- CanonicalSession has source agent/id/version/digest/path, title, cwd, selected leaf, canonical events with parentId/ordinal/raw, derived context, unresolved tools, issues and security profile. Pi/OMP parser accepts explicit event parent edges and branch leaf selection; the archive keeps the event graph, while derived context projects the selected branch after reset/context-edit/compaction handling.
- Codex parser reads selected rollout record kinds (session_meta, response_item, event_msg, compacted, turn_context), deduplicates event mirrors by identity and handles thread rollback. It is a linear rollout projection; its decoder rejects a requested tree leaf. Codex destination Structured import is explicitly unsupported; it only produces PREPARED handoff. Local Codex CLI is not ChatGPT Projects/Section Groups.
- Native Pi/OMP target creates a new session identity under explicit OUTPUT, maps user/assistant messages, and maps summaries/custom/tool records to inert custom_message history. It linearizes the selected source branch; the original .acx remains bundled as a sidecar. It does not restore source session identity, exact branch graph as live target branches, provider replay, system/developer/runtime state, approvals, subagents, tools, permissions, Skills, MCP/plugins, memory, scheduled tasks, files or attachments. Resource references or unknown semantics can block structured import.
- NATIVE_CONTEXT_VERIFIED proves version-pinned storage cold-open and context projection, not true model continuation or successful target TUI resume. Resume only prints argv, with tools/extensions/skills/context files disabled; real TUI, model next-turn, provider interoperability and production workspace correctness remain unverified.
- Context-only profile is intentionally lossy: fixed semantic fields (goals, constraints, background, source-stated facts/decisions/artifacts/progress/next steps/risks), no source IDs/path/event IDs/raw/tool details/usage/branches; all claims require review. Default extraction is no-LLM single-line labels; unlabelled natural-language context may be missed and goal/constraint contradictions are not resolved. It fails without an explicit goal and supports an explicit user-supplied checkpoint. It is not a general natural-language summarizer.

Security and operations
- Good controls include read-only source snapshots, source stability check, file/record size limits, fail-closed unknown semantics/resource references, explicit pending action outcomeUnknown, inert history warnings, archive member allowlist/hash/size/ratio validation before inflation, no arbitrary-path extraction, exclusive no-overwrite publishing, idempotency receipts, and separate output directory.
- Best-effort secret redaction removes listed credential keys and a few known token patterns/private provider carriers; the README/code explicitly disclaim secret-free guarantees. Archive and native output are not encrypted; workspace paths, code, personal text, custom data and unrecognized secrets can remain. Manual review is required before sharing. Attachments/assets are not bundled.
- macOS arm64 native workers use pinned SessionManager storage modules, isolated HOME/XDG/agentDir, sandbox-exec network denial and write-denial outside the owned output root. The sandbox still permits file reads; it is not full read isolation. Native stage depends on internal package paths pinned to exact versions and needs runtime installation. Staging interruption is fail-closed but there is no multi-object transaction/automatic reconciliation.

Disposition for Nexus Memory
