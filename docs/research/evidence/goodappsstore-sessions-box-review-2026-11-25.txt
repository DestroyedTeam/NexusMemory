## Product and data boundary

- Sessions Box is a local-first Tauri desktop **session history browser/indexer** for coding-agent CLIs. The Rust importer discovers nine source families: Codex, Claude Code, OpenCode, Pi, Command Code, Muse, Hermes Agent, Cline and Antigravity. It syncs local JSONL transcripts and selected local SQLite stores into its own SQLite library; source agent stores are read-only.
- It directly covers **Claude Code local** history and can invoke `claude --resume <id>` to resume in the original CLI/workspace. It does **not** read Claude Desktop Chat/Cowork/Code session stores, ChatGPT/ChatGPT export data, or third-party gateway profiles. `claude --resume` is a source CLI continuation command, not a target-native importer.
- The local normalized schema has `agent`, `workspace` (path), `repository`, `model`, `session`, `session_context`, `entry`, `content_part`, `tool_invocation`, `file_activity`, tags, stars, analytics and sync checkpoints. Entries can retain `parent_entry_id`; the session entity has no native parent/child-session graph and there is no Project/Section Group entity. Workspace path, flat session rows, bookmarks and tags are not a native nested project/section/session hierarchy.
- The importer preserves raw source JSON alongside normalized content/tool calls/results, model/context fields, and reported usage for browsing and analytics. Unfamiliar/media blocks can remain in source-shaped JSON, but this is **not** a target-native session writer or proof that media can be rehydrated in another Harness. Export saves full transcript/tool activity as Markdown or JSON. `Export SQLite backup` / `Import backup` is for restoring Sessions Box's own versioned schema, with integrity validation, ID remapping, collision policy, and an atomic transaction—not cross-Harness conversion.
- Resume launches the originating CLI using its source session ID and original workspace. It does not translate a conversation into another tool's native store, copy project/workspace files, transfer Skills/MCP/plugins, or port memory/schedules.
- Sync is incremental and read-only to sources. JSONL/SQLite sources are skipped if size+mtime (including SQLite sidecars) match; no content hash or format-version fingerprint is used, so same-size/same-mtime edits or parser changes may not trigger a rescan. Changed sources are rebuilt; interrupted SQLite batches roll back while completed batches stay available. This is a useful local Archive/Inventory/AnalyticsPlane pattern, not a universal migration format.
- The app's own session database uses SQLite WAL; the source says Unix directory/file modes 0700/0600, but backups and conversations are unencrypted at rest and should be treated as private. Desktop packages are multi-platform; README notes macOS ad-hoc signing (not notarized) and unsigned Windows installers.

Both `npm ci --ignore-scripts` runs succeeded (175 packages each), both `npm run build` commands succeeded (TypeScript plus Vite), and both `cargo check --locked --manifest-path src-tauri/Cargo.toml` commands succeeded.
- Vite reports a 534.03 kB minified JS chunk above its 500 kB advisory threshold (gzip 158.03 kB). This is a performance/splitting warning, not a build failure.
- No unit/integration tests exist in either snapshot, and README states that CI builds do not verify runtime behavior. GitHub release CI is useful packaging evidence, not transcript-ingestion/resume behavioral acceptance. No native runtime was launched against the user's stores.

## Disposition

**VALUABLE_LOCAL_MULTI-HARNESS_HISTORY_HUB; NOT A_CROSS_HARNESS_SESSION_MIGRATOR.** This is a useful MIT reference for local multi-agent discovery, read-only ingestion, normalized searchable transcripts, context/tool/token analytics, source-native resume, and safe backup/restore of the hub's own database. It covers one of the four requested Claude-related routes (local Claude Code) as a source/resume option, but cannot migrate to Claude Desktop Chat/Cowork/Code or restore ChatGPT Project/Section/session trees. Retain as a product/ArchivePlane and local UX reference, not as the migration engine or universal Harness compatibility layer.
