## What is implemented

- A substantial MCP control-plane for spawning, messaging, polling, waiting for and terminating local Claude Code / Codex child agents; host instructions include Claude Code, Codex, Gemini CLI, and Claude Desktop MCP registration. Claude Desktop installation is explicitly **MCP-only**: there is no per-turn `UserPromptSubmit` hook/injection on Desktop. That does not constitute support for Claude Desktop Chat/Cowork/Code history migration.
- `launch_agent` starts a new interactive child runtime and returns a random `agent_id`; `send_message` enqueues input on that live driver. `AgentState` is stored in a process-local `Map<string, AgentState>` with provider/model/status, process/driver facade, stdout/stderr buffer, cwd, timing and liveness fields. The state has no durable parent/child edge or source transcript identifier; spawn depth and a first-line parent marker are control hints, not a conversation graph. Turn output is only exposed through bounded poll/wait tails/final output, and agents are evicted after retention/termination rules.
- Interactive Claude uses the Claude Agent SDK; Codex uses the app-server `thread/start`/`turn/start` protocol with `ephemeral: true`. Those are fresh runnable sub-agent sessions, not writers that reconstruct an imported ChatGPT transcript/branch tree. The Code/CLI runtime's provider thread ID is not a portable `ConversationSession` identity.
- Direct API providers are a separate path for the product's own sub-agent tasks: `providers.jsonc` supplies `api_style`, `base_url`, model and `key_env`, with the secret in local `.env`. `provider-client.ts` makes a single non-streaming POST to `/v1/messages` or `/v1/chat/completions`, using Bearer auth and normalizing response text. It accepts `messages`/`tools` in the request, but does not expose a persistent transcript/session import-export API, message event ledger, provider thread id, attachment bridge, or client-managed Claude Desktop session writer. This is not Claude Desktop's third-party-inference session storage and should not be conflated with the user's API-key/gateway target.
- The project has useful durable checkpoint primitives: `handoff.ts` stores one compact text handoff per project/cwd identity with `created_by_session`, `read_by_session`, timestamps, version/generation and lifecycle; primary text is limited to 4,000 characters and optional overflow to 8,000. Hook state also writes one latest metering JSON sample per session key, including harness, model, transcript `source_ref`, input/output/cache token counts, context-window size, used tokens/percentage, sequence and compaction-generation proof; each turn overwrites the previous sample and the record expires after a 30-minute TTL. This is a compaction-resume summary/telemetry mechanism, not a full audit-grade token-cost history or raw conversation archive.
- Swarm stages are process-memory state; no durable session-parent tree is serialized. No ChatGPT Project/Section/group importer, chat-message/turn/fork/subtask graph, attachments/media converter, MCP/plugin config transfer, independent memory import, schedule/task transfer, or cross-harness session migration writer was found in the inspected source/API. Therefore no migration accuracy score applies.

## Disposition

**Keep as a high-value adjacent OrchestrationPlane / checkpointing / provider-routing reference; exclude as a cross-harness Session migration engine.** Useful patterns for Nexus include host-specific source readers for per-session usage signals, strict process lifecycle and permission gating, compact explicit handoffs, and an internal API-gateway adapter boundary. But all actual provider sessions remain local runtime objects, while the durable handoff is a short summary rather than a transcript or project tree. The direct API path's Bearer-auth Messages/Chat-Completions contract is not proof of compatibility with every third-party gateway or Claude Desktop's own development-mode endpoint/session archive. Local test portability and two integration failures warrant follow-up before adopting code; no product behavior or migration fidelity was claimed.
