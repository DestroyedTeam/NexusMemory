## Verdict

High-value adjacent reference for local project journaling, plans, file verification and agent activity observation. Not a ChatGPT Project/Section/Session importer, generic conversation archive, Claude Desktop Chat/Cowork/Code importer, or API-key/provider-gateway migrator. Keep out of the core migration engine and accuracy claims; consider only as a design reference for a separate project-memory/journal plane.

## Source and model findings

- `.oculpm/journal/` Markdown is the durable work-record source of truth; planner files describe plan and task state; SQLite is a derived cache. A journal entry captures a concise task summary, structured metadata and files, not a full turn-by-turn transcript.
- The code's watcher `Session` is an app-side work-activity aggregate (start/end, active-window time, file-change counts, Git heads, agent label, agent conversation IDs, linked journal entries). `agent_sessions` is a list of IDs, not parent/child/fork edges. `FileChangeEvent` tracks file operations/hashes, not conversation messages or tool-result trees. The separate application-window `Session` means the window/project/focused-state snapshot; don't conflate these meanings with a native conversation.
- Claude Code transcript parsing is used to identify successful file-edit paths for verification; it does not ingest or re-emit the full conversation. `SessionId::imported()` is defined/tested, but focused source reference scan found no production caller. `ManualEntryDraft.created_at` enables backdated manual journal entries; the Tauri command is still a manual-entry path, not a transcript/export importer.
- Integrations are uneven: README describes level-3 hooks/MCP/rules observation for Claude Code and Codex, while Gemini CLI/Cursor/Copilot/Windsurf/Cline/Aider/Zed/Antigravity/pi are level-1 rules/context paths. Claude Desktop MCP one-click registration was removed in v4.0 after no actual connection records. No mode-specific Chat/Cowork/Code session adapter was found.
- Workday/category folder structure and planner hierarchy offer useful project-memory organization ideas, but there is no portable native Projects/Sections/thread/branch/subagent graph or generic source/target matrix.

## Privacy/security probe (synthetic only)

The shipped Claude Code hook reads complete event JSON from stdin and appends the unredacted payload to `.oculpm/hooks/claude-events.jsonl`; the JSON can contain `prompt` and `last_assistant_message`. The app parser consumes known metadata fields but unknown JSON fields do not prevent the raw full line from first being written. I ran the actual hook command with a temporary project, synthetic canaries only, and explicit `umask 022`: both subprocesses exited 0 with empty stdout/stderr; canaries remained in plaintext in a 541-byte file with mode `0644` and parent directory `0755`. No real prompt, session, credential, network call or user project was used. `.gitignore` excludes this inbox from Git commits but does not enforce private file modes or encryption. Inbox compaction is conditional: it truncates only after all lines were consumed and size is at least 1 MiB; there is no time-based retention in this path. The transcript parser and this raw hook inbox are separate privacy surfaces.
