## Implemented reader and transcript model
- This is a cross-store **local CLI reader**, not a destination/importer. Built-in stores are only Claude Code CLI, Codex CLI/Desktop rollout JSONL, and DeepSeek Harness (DSH) compressed JSONL. It does not read ChatGPT, Claude Desktop Chat/Cowork/Code, Cursor, OpenCode, Goose, etc.
- Adapter interface is Discover + Load -> harness-neutral Transcript. Transcript contains a single source ID, source file path, CWD, title, start/end times, model, ordered Turns, aggregate Usage and a Malformed count. Turn contains role, timestamp, blocks, model and tool-call count; Block supports only text, thinking, tool_use and tool_result. This is useful reader architecture but not a cross-session graph.
- Claude Code reader scans top-level JSONL files under ~/.claude/projects/<slug>; the source comments say side-agent sidechains are in sibling directories, but Discover skips directories, so sidechains are not enumerated. Its CWD is decoded from a lossy path slug. Claude adapter extracts text/thinking/tool-use/tool-result and usage, but typed image/file/media blocks are not represented in Block and are dropped.
- Codex reader walks ~/.codex/sessions/**/rollout-*.jsonl; it keeps user/assistant/system text, plaintext reasoning summaries, tool input/output, timestamps/CWD/session ID and final cumulative token usage. It intentionally drops developer-role harness instructions. Tool calls and outputs become separate Turns without call IDs/parent edges. Some non-text content blocks are not mapped.
- DSH reader handles session.v3.jsonl.zstd and legacy session.jsonl.zstd, title/CWD/inbox splices, assistant text/reasoning, tool calls/results and some token fields. It has an in-repo Zstandard decoder plus a documented external-zstd fallback for FSE-compressed Huffman weights. This parser flattens inbox splices and tool activity; it has no task/parent edge model. Only the adapter path is read-only; explicit export writes a separate file.
- CLI provides ls/search/show/stats/sources and JSON/Markdown export. Search is case-insensitive raw substring prefiltering, not ranked/full-text retrieval; compressed stores bypass byte prefiltering and are parsed. There is no MCP server, Skill, project/section mapping, session import/resume/write, schedule transfer, plugin/resource installer or rollback into a target Harness.

## Fidelity, scope and privacy limits
- No Project or Section/Section Group entity, stable cross-session parent/fork/subagent graph, attachment/file bytes, image/audio/video blocks, native event IDs, tool-call correlation IDs, schedule/Skill/MCP/plugin context, credentials or target resume handle. JSON/Markdown are projections of the in-memory model, not a lossless native archive or versioned interoperability schema.
- Source CLI is described as read-only, but full transcript content includes reasoning/tool I/O and absolute local source paths. Synthetic export to a user-supplied path was created with mode 0644 under this environment's default umask. Handle export artifacts as sensitive and use restrictive directories/umask.
- CWD slug reconstruction for Claude is explicitly lossy. In synthetic integration, ls --json also showed Codex title/CWD empty and a filename-derived UUID; show loaded the transcript and exposed the actual session_meta ID/CWD/title. Cause in source: JSON list skips the transcript-loading title path, while Codex Discover does not load session metadata.
