## Product scope and code-level fit

- The actual implementation is a four-target local/global `SKILL.md` manager: `claude`, `codex`, `copilot`, `gemini`. It supports registry lookup, GitHub shallow clone, heuristic scanning, copy into agent path, a `skills.lock.json` with only `name/sourceUrl/commitHash/installedDate`, list/update/remove, and minimal frontmatter validation.
- It does not define/import Projects, Sections/Groups, sessions, transcripts, event trees, branches/subtasks, images/files/tool results, MCP servers, plugins, memories, schedules or token usage. No Claude Desktop Chat/Cowork/Code adapters exist. It is therefore only an adjacent Skill catalog/install UX reference, not a Nexus Memory migrator.
- `src/lib/agents.ts` itself comments that native paths need official-doc verification; CodeGraph found no tests covering `agentPaths`. Candidate paths are Claude `.claude/skills` / `~/.claude/skills`; Codex `.codex/skills` / `~/.codex/skills`; Copilot `.github/copilot/skills` / `~/.copilot/skills`; Gemini `.agents/skills` / `~/.gemini/config/skills`. Current official CLI references document Codex `.agents/skills` / `~/.agents/skills`, Copilot `.github/skills` and/or `.agents/skills`, and Gemini `.gemini/skills` or `.agents/skills` (user `~/.gemini/skills` / `~/.agents/skills`). Thus at least the Copilot project and Gemini global path differ, and Codex path conventions need explicit versioned tests; do not count a static table as a verified live adapter matrix. Claude Code's `.claude/skills` location aligns for local CLI. Current Claude Code docs also distinguish local `~/.claude/skills` from Cowork/cloud sessions, which load account-synced Skills; that is not a proof of the third-party-provider Desktop store's behavior, but demonstrates why Desktop modes require separate probes.

## Reproduced code defects (temporary data only)

1. **Shell command injection risk in direct GitHub URL handling.** `src/lib/installer.ts::installSkill` parses untrusted owner/repo text from a URL, constructs `git clone --depth 1 https://github.com/${owner}/${repo}.git "${tempDir}"`, then calls `execSync(commandString)`. A disposable Vitest probe supplied `https://github.com/owner;printf INJECTED/repo`, mocked `child_process.execSync`, and observed the shell command string preserve `;printf INJECTED`; the mocked process created only a temporary source fixture, and no shell command was executed. Node's official child_process docs state that `execSync` is shell-backed and warn against unsanitized input. Use `execFileSync('git', ['clone', ...])` with validated owner/repo and explicit path containment instead.
2. **Delete path traversal in `skillhub remove`.** `src/commands/remove.ts` joins user `<name>` directly to the skills root and recursively removes the result without verifying it remains under that root. A built CLI was run from a fresh disposable temp cwd with `remove ../../victim`; command exit 0, stdout was `Deleted skill folder for '../../victim'.\nSuccessfully removed skill '../../victim'.\n`, stderr empty, and a synthetic sibling `victim` directory disappeared. The temporary parent was then deleted. A hostile/accidental name can delete files outside the Skills directory, within the caller's filesystem permissions.
3. **Destructive overwrite on copy failure.** `installSkill` removes an existing Skill directory before copying its replacement. A second disposable Vitest probe mocked `fs.cpSync` to fail after the old destination had been removed; the test observed old `SKILL.md` absent and a newly-created empty target directory. This is user content loss.
4. The advertised scanner is heuristic and warning-only: it checks only two command patterns (`rm -rf`, `curl|wget ... | bash|sh`) and four secret patterns, skips files over 1 MB after a warning, and `--yes` bypasses the confirmation. This is not a security boundary for untrusted Skill content.
5. URL path `/tree/<branch>/<subfolder>` captures but does not use `<branch>` in the clone command; Git clones the default branch. The recorded source URL can therefore describe a different branch than the installed content.

## Disposition

Exclude from candidates for Projects/Sections/Sessions migration and do not recommend installing from arbitrary GitHub URLs in its current state. Keep only the UX concept of a small Skill registry/lockfile and four-path adapter as a low-confidence reference. Before production use, replace shell string execution with argv-only Git, enforce path containment for install/remove, stage-and-swap with rollback, validate requested refs/commit hashes, make warnings explicit but not falsely “safe,” add failure-path security tests, reconcile package name/version/license metadata, and verify every path against the versioned vendor docs and a real disposable host installation.
