Nexus Memory GitHub candidate review — yeasy/ask (ASK: Agent Skills Kit), 2026-11-20

DISPOSITION
High-value adjacent reference for the **Skills plane** (multi-agent install, project/global target paths, lockfile/provenance, skill auditing and cross-platform packaging). It is not a Project/Section/Session converter, memory migrator, MCP configuration manager, or Cloud API-key conversation writer. Keep it as a Skills adapter reference and keep its capability separate from the session-migration score. MIT license.

IMPLEMENTATION / SCOPE
- ASK searches sources/registry, fetches one skill directory via HTTPS/sparse Git checkout, validates source path/ref, copies files into selected agent skill directories (symlink with safe copy fallback where supported), and records the upstream source/commit in the lockfile. `ask lock-install` restores pinned versions. This synchronizes a shared Skills document; it does not translate the meaning of harness-specific hooks, commands, plugins, MCP server configuration, profiles, memory, or access scopes.
- The installer supports 19 agent path targets at the reviewed commit: Claude Code, Cursor, Codex, OpenCode, Antigravity, Gemini CLI, GitHub Copilot, Windsurf, Amp, Goose, Kilo, Kiro, Roo, Trae, Droid, ClawdBot, Neovate, CodeBuddy and OpenClaw. This is not the same thing as compatibility with each agent’s full configuration or hosted-chat environment. In particular, a `.codex/skills` / `.claude/skills` file install does not create or import a ChatGPT/Claude **Cloud Session**.
- MCP appears as a skill search/install example (e.g. `mcp-builder`), not as a parsed `mcpServers` config. Repository code contains no conversation/transcript export, chat-session model, Section Group hierarchy, attachment-transfer route, API-key session writer, scheduler migration, or destination Cloud API-key integration. A static scan of `cmd`, `internal`, and `docs` found no conversation/transcript/ChatGPT-session flow.
- The skill scanner uses metadata validation and content rules for suspicious commands, secrets and other patterns; it produces findings/SARIF/HTML reports. This is static analysis and provenance/locking around file installation, not a sandbox for code or instructions after the consuming agent loads them. Treat installed skills as untrusted source content and apply the Nexus policy/consent step independently.
- `ask serve` binds `127.0.0.1`, checks Host is loopback and limits CORS to local origins; no login/session authentication was found for the local UI. This is a local-desktop convenience boundary, not a remote multi-user/cloud control plane. Do not expose the port as a service.

RECOMMENDATION FOR NEXUS MEMORY
Separate the Skills plane from session migration: ASK is a plausible integration/reference for fetching immutable skill packages, explicit source/commit provenance, project/global installation, target directory capabilities, dry-run/security findings, cross-platform packaging and reproducible lockfiles. It is not an implementation for the requested Destruction Era Projects/Section Groups/Sessions. For Nexus, adapt the content-addressed source record and per-harness support matrix, but preserve per-harness exceptions and list unsupported features; never treat “same SKILL.md copied” as proof of MCP/plugin/session compatibility.
