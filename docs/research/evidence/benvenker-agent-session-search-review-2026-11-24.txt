## Product capability and migration boundary
- This is a local lexical **read/search** layer over raw session files via FFF, with CLI, one managed MCP tool (`search_sessions`), a separate opt-in raw FFF MCP lane, doctor diagnostics, and an optional cass/cm shim. Built-in roots are Codex, Claude Code, Pi, Cursor, Hermes, Gemini CLI, and Pool; users may configure custom text roots.
- Search returns source/root and canonical absolute path, match groups, bounded previews/snippets, query/pattern lineage, and an evidence-follow-up payload. It derives a Session ID only when a UUID appears in the file basename. It does not parse or emit a complete Conversation/Project/Section/Session graph, message event order, parent/fork/subtask lineage, attachments, tool results, token usage, memory, Skills, MCP/plugins, or schedules.
- No built-in ChatGPT source exists; source code contains no ChatGPT, Cowork, or Claude Desktop adapter names. It has no importer or target writer for ChatGPT exports, Claude Desktop Chat/Cowork/Code, or local/self-hosted Claude Code API-Key/gateway sessions. A custom root can search an export as text but does not migrate it.
- The optional cass shim supports a narrowly scoped single-file export to stdout as markdown/text (8 MiB ceiling) for simple Claude/Codex/Pi/generic message records. It is not a general export API and does not write to a target Harness. Synthetic ChatGPT `mapping`-shaped export returned an empty-session error instead of reconstructing messages.
- Disposition: high-value adjacent local-session discovery/read adapter; not a Nexus migration solution. Keep its search/result/evidence contract as prior art, but keep the canonical archive and importer separate.
