## External adapter and duplication finding
The README claims “Community provider adapters” follow a versioned external-process protocol. That overstates the implementation: `docs/PROVIDER-ADAPTER-CONTRIBUTOR-GUIDE.md` says RFC-0002 is Draft and the external-process boundary is planned, while the current `ProviderAdapter` trait is an in-process Rust trait (`provider_id`, `manifest`, `probe`, `parse`, `probe_source`, `parse_source`). The only published schemas are Robot and handoff; there is no external adapter manifest schema, loader or process bridge in the crates. Do not cite this repository as proof of an extensible arbitrary-Harness plugin runtime.

The same-family comparison with #255 shows #255 is a later, more developed snapshot: it has 8 additional crate files and 39 changed shared crate files; its README documents an available 0.1.0 release and post-release main, while this AgentSessions README still says 0.1.0 is planned. The skill files differ in six sections; the later #255 skill adds stricter resume preview/approval wording. Treat the two GitHub rows as one close architecture family in product-count summaries, while retaining separate repository evidence and version-specific findings.
