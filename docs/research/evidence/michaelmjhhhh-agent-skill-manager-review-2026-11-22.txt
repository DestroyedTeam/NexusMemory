## Native behavior and boundaries

- Installed skills are browsed locally; categories/favorites and saved install commands belong to the app's separate bookmark collection. Import merges by UUID, existing local entries win on collisions; records do not represent native Session state. Collection writes use atomic JSON, invalid data is surfaced without overwrite, and export rejects the active collection path and symlink aliases.
- A saved install command is shown in a confirmation dialog with the selected working directory. The user must choose Run or Copy command & open. The app passes AppleScript values as argv rather than embedding the command in the AppleScript source, but the command itself runs in a new terminal with the user's permissions. The README says the app does not check installation success; no test actually executes a saved command. Treat imported command strings as untrusted and never auto-run them.
- Removal is an explicitly confirmed move to macOS Trash. The guard requires one top-level entry under the configured root, rejects home/root as source roots, pins root/entry device+inode with `lstat`, and trashes a symlink itself rather than resolving/deleting its target. A selected nested file removes the whole containing skill folder; a standalone Markdown file removes only itself. The source notes a remaining path-based TOCTOU race.
- The scanner is lazy and bounded (64 KiB metadata read, max depth 12, first 500 entries per directory), tracks symlink cycles, and reports omitted/unreadable data. This is performance and local-files UX evidence only, not migration fidelity.
- No code recognizes the Claude Desktop 3P `Claude-3p` application data tree; current sources only configure `~/.agents/skills` and `~/.claude/skills`. The target modes Chat/Cowork/Code and local desktop session hierarchy are outside its model.
