## Disposition

**Reject as a Nexus Memory migration product and do not install untrusted resource repositories with this implementation. Retain only its simple ResourcePlane manifest/profile idea.** The program is a small Python CLI that stores reusable resource files and copies them into Codex or a generic .claude tree. The data model contains Resource and InstallPlan, while profiles are flat lists of resource IDs. It does not model ChatGPT/Codex Projects, Section Groups, sessions, parent/child/fork/subtasks, transcripts, images, files, links, tokens, schedules, persistent memory, or migration lineage. It is not a Claude Desktop third-party-gateway writer; it has no separate Chat/Cowork/Code modes or local/self-hosted Claude Code session importer.

## What it actually supports

- The CLI exposes list, validate, doctor, sync, add, and install. The manifest describes id/name/type/description/supports/files/tags/variables/templates/source/version. A profile simply selects resource IDs; it is not a nested project/session graph or cross-Harness canonical archive.
- Current adapter registry is exactly codex and claude. Both copy skills/agents/commands/hooks/roles into generic directories. Codex additionally renders a codex_config template into config.d/*.toml. ClaudeAdapter has no MCP handling. The sample Postgres MCP is marked codex-only; a disposable install wrote five Codex files including config.d/sample-postgres-mcp.toml, versus four Claude files and no Claude MCP config. This is copy/installation, not semantic conversion or round-trip preservation.
- The npm entrypoint shells out to Python; source supports a resource repository and manifest/profile workflow, not session-store export/import. There is no uninstall command, no transaction, no backup, no install diff/rollback, and no version lock or source digest. README itself says uninstall and richer safeguards are future recommendations.

## Reproduced correctness defect — built-in profile is broken

The shipped profiles/bootstrap.yaml refers to sample-skill, sample-reviewer, and sample-postgres-mcp. The actual repository contains firecrawl rather than sample-skill. agentkit validate and doctor both returned success (doctor reports six resources and Validation: OK) because Repository.validate checks resource manifests/files/templates but not profile references. Running the documented bootstrap profile returned exit 1 with an uncaught ValueError: unknown resources: sample-skill. The project test test_profile_expands_to_resources uses a valid temporary fixture and does not catch the broken shipped profile.

## Reproduced install security/atomicity problems (temporary synthetic fixtures only)

1. Path escape: a disposable manifest with resource id ../../outside and a synthetic SKILL.md was installed into a temporary target directory via the shipped Node/npm CLI entrypoint. The command returned exit 0 and wrote SKILL.md to a sibling outside directory, not beneath the selected target. The escaped file stayed inside the dedicated temporary probe tree; no user paths or data were touched. Source uses target / resource-type-directory / resource.id / file_name without path-containment checks. If a user installs a repository containing an untrusted manifest, this is an arbitrary write outside the chosen agent root.
2. Partial write: a synthetic two-file skill was installed with a pre-existing regular file blocking the second file's parent directory. The command printed both WRITE actions, then exited 1 with FileExistsError; the first file remained installed and there was no rollback. Both conflict and leftover were under the temp probe directory.
3. Profile reference validation and path-containment tests are absent. The install plan is applied directly, sequentially and without backups; target files may also be overwritten by writes.
