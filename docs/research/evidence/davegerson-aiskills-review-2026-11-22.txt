## What it implements / relevance

There are two original skills and static setup templates for Claude Code, Google Antigravity, and Codex:

1. `program-docs`: asks an agent to create a dated Markdown program folder with brief, architecture map, append-only owner decisions/defaults, status, track seams and handoffs. Useful as a **human-readable continuity sidecar** and project governance process; it does not parse/import/export Harness sessions, chats, parent-child conversations, attachments, or tokens, and depends on an AI/agent following the instructions.
2. `build-status-artifact`: turns project documents into a Claude `Artifact`/`ArtifactData`-backed interactive status page with JSON documents, update batches, and owner question/answer loop. Its runtime is `window.claude` plus Claude Artifact/ArtifactData, not a generic API adapter, portable canonical memory store, or ChatGPT/Codex session writer. Example Orchard seed validates as 59 writes in two batches (50 + 9).

Setup snippets provide Claude Code instructions/settings/statusline hook, Antigravity instructions/skills.json/MCP config, and Codex AGENTS/config. Installation is manual/plugin/skills.sh/symlink guidance. This can seed a **resource/config plane**; it is not automation that discovers, translates, verifies, or rollback-transacts a Harness installation. Dependencies (Agent Baton, other Skill suites, MCP) are linked, not vendored.

The statusline hook reads Claude Code's current statusline JSON (model, cwd, session id, context usage, cache, cost, rate limits, task/todo metadata), executes local `git status`, and writes only a compact context-usage bridge JSON in the OS temp directory. It does not load transcripts or preserve Session events/branches; source has no network call. This is at most a live session telemetry surface.

The confirmed destination remains Claude Desktop third-party-gateway **Chat, Cowork, Code—all three separately**, plus local/self-hosted Claude Code. No content in this repository validates any of those Desktop modes, API-Key gateway session stores, or Anthropic-hosted Cloud. Do not infer ChatGPT Project/Section import from the phrase “multi-session” in the README.

## Isolated runtime probes — synthetic temp files only

`skills/build-status-artifact/scripts/make_batches.py` reads `file` from each seed `manifest.json` row as `seed / row.file`, then places the resolved path in an ArtifactData batch. It checks JSON size/depth/collection/doc id but does not constrain the file path to the seed directory. In a TemporaryDirectory, the manifest row `{collection:"meta", doc_id:"now", file:"../outside.json"}` referenced a sibling synthetic JSON file. The actual script returned exit 0, stdout `1 writes (set 1) in 1 batch(es); all valid`, and wrote `file_path` pointing outside the seed. Reopening that referenced file yielded only the synthetic marker `NEXUS_OUTSIDE_SEED_SENTINEL`. No ArtifactData request was sent. If a user/agent submits that generated batch, a crafted manifest can direct a local file read/upload outside the reviewed seed; validate resolved paths before creating ArtifactData batches.

`make_harness.py` uses the same unvalidated manifest-relative join when embedding seed JSON into a generated HTML test page. A second disposable manifest referencing `../outside.json` caused the generated `h-light.html` to contain the sibling synthetic marker; command exited 0. No private files or network were involved.

## Disposition

Keep as a useful **process/governance sidecar** reference: append-only decision log, verified code map, per-track ownership/seams, status snapshots, and a user-visible decision loop. It is not a deterministic cross-Harness memory/session transfer engine, not a substitute for the user's own source session graph, and not a source for native Claude Desktop mode compatibility. Harden both script path checks before using seed data that is not locally trusted; repair the tested Claude marketplace manifest validator mismatch and re-run current CLI validation. For Nexus, represent this kind of authored program context separately from original Session/Event history so a README/decision log is never misrepresented as a restored transcript.
