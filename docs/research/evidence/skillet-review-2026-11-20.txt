WHAT THE CODE DOES
- README describes a one-binary, no-backend registry/package manager for SKILL.md skills, MCP servers, and Claude Code commands, hooks, subagents and output styles; README claims a curated registry of 370+ entries. The default skill destination is `~/.claude/skills`; `--target agents` uses shared `~/.agents/skills` (README lists Cursor, Codex, Gemini CLI and GitHub Copilot as readers).
- MCP implementations are explicit per-client writers in `internal/install/mcp.go`: `claude` writes the project `.mcp.json`; `cursor`, `windsurf`, `gemini`, and `cline` use their own JSON config paths/key variants. The map contains five clients, not a Claude Desktop config adapter. `InstallMCP` merges one named server into the existing JSON map; tests exercise preserving unrelated keys, list/remove, and unknown-client rejection. JSON values are kept with `UseNumber` and writes are atomic, though formatting/key order may change. This proves config-file manipulation, not that a live host activates a server. Codex is only listed as a shared Skill directory target, not a supported MCP config client.
- Lock/install behavior: registry entries, install manifests and `skillet.lock` store artifact kind/path/repository, requested ref/resolved commit, checksum, and hook provenance. `install --frozen` verifies the local install against the lock; restore prunes only Skillet-managed installs with provenance records and leaves hand-placed files alone. Source has traversal/symlink-escape and lock restore/frozen tests. This is resource provenance, not a chat/session serialization. Compatibility policy documents 1.x stability for commands, registry schema, manifest/lock formats and install paths.
- Security policy explicitly treats Skills as code running with agent privileges; unpinned third-party content can change, pinning does not create a transparency log, lockfiles are untrusted inputs, and community skills are not curated. The security policy says community scans may be missing/unreachable and cover current content, while lockfiles pin commits; users should review lockfiles like code.
