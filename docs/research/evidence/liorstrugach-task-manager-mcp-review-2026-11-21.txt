FUNCTIONAL SCOPE / DATA MODEL
- A small local Terminal Task Tracker with Task list, one Project Plan, notes, CLI/TUI and a generic MCP server. Default files under ~/.tasktracker: tasks.json, plan.json, notes.txt. Tasks are a flat array (id,title,description,priority,status,created_at,updated_at); plan steps are a separate flat ordered list (id,name,description,details,order,completed,timestamps). There is no Project ID / Section Group membership, no task parent/child edge, no conversation/session object or event log.
- MCP README lists resources tasks://all, tasks://{task_id}, plan://all, plan://{step_id}, notes://all; tools manage tasks, plan steps, notes, export and import; prompts only create a task or plan. The CLI/API data archive has exactly the keys tasks, plan, notes. Synthetic local round-trip preserved those fields. An empty object import returns success and clears tasks/plan; no backup/merge/schema validation is performed. Export/import is only TaskTracker's own application data, not ChatGPT/Codex conversation or project-session migration.
- MCP README documents mcp install mcp_server_fixed.py for Claude Desktop. It is local MCP setup, not a remote API-key service, mode-specific Claude Desktop session importer, or Claude Code API-key conversation writer. No scheduled-task, memory, plugin, attachment or token-usage transfer exists in the reviewed implementation.
