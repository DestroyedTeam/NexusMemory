Architecture & Claude Desktop 3P / Nexus scope assessment
- Hard-coded legacy macOS standard Claude paths (`cowork:16-19,625-627`):
  - Scans `~/Library/Application Support/Claude/claude-code-sessions` and `~/Library/Application Support/Claude/local-agent-mode-sessions` (overridable via `--data-path` on read commands, NOT on `migrate`).
  - Zero support for Claude Desktop 3P (`~/Library/Application Support/Claude-3p/`), device `ant-did` + org scoping, 3P local Chat vs Cowork distinction, Windows, or Linux.
- Unsafe `cmd_migrate` (`cowork:623-644`):
  - Hard-codes `~/Library/Application Support/Claude` and creates a symlink `claude-code-sessions -> local-agent-mode-sessions`.
  - On current Claude Desktop (standard and 3P), `claude-code-sessions` holds Desktop **Code** session metadata while `local-agent-mode-sessions` holds **Cowork** (and 3P Chat) sessions; symlinking them together conflates two distinct lanes and risks corrupting Desktop session stores.
- Lossy `parse_audit` (`cowork:87-179`) and CLI/Web discrepancies:
  - Silently drops all entries with `parent_tool_use_id` (subagent / nested tool turns).
  - Silently drops all `tool_result` blocks (contradicting `docs/PRD.md:81`).
  - Silently drops non-`text` user content blocks (images, attachments).
  - Silently drops non-`success` `result` events (errors, max-turn stops, interrupts, compactions).
  - Truncates thinking blocks (200 chars in CLI text, 2,000 chars in web UI) and Bash commands (80/100/120 chars); ignores `local_<uuid>/.claude/todos/*.json` despite documenting it in `docs/PRD.md:51`.
  - `cmd_stats` (`cowork:481-558`) accepts `--format json` (`cowork:712`) but completely ignores `args.format` and prints human text.
  - `cmd_unarchive` / `cmd_unarchive_all` (`cowork:585-616`) rewrite `local_<uuid>.json` directly in-place (`open(..., "w")`) with no backup, no dry-run, no confirmation, and no atomic write.
  - `cmd_serve` (`cowork:663`) passes `args.data_path or DEFAULT_DATA_PATH` (`DEFAULT_DATA_PATHS[0]` = `claude-code-sessions`) to `make_handler`, bypassing dual-path discovery and crashing with `FileNotFoundError` when only `local-agent-mode-sessions` exists.

Nexus reuse boundary
- Minor read-side schema reference only: Cowork sidecar metadata keys (`processName`, `userSelectedFolders`, `isArchived`) and VM `/sessions/<processName>/...` path mapping shape.
- Strict negative lessons for Nexus architecture/security gates:
  1. Never symlink or alias `claude-code-sessions` (Code) to `local-agent-mode-sessions` (Cowork/3P Chat).
  2. Never check path containment with bare `str.startswith(realpath)` or allow `os.path.dirname(selected_folder)`; enforce `Path.resolve().is_relative_to(allowed_root.resolve())` strictly on explicit roots.
  3. Never serve workspace HTML/SVG files inline on a local viewer origin without sandboxed CSP (`sandbox` / `Content-Disposition: attachment` / `X-Content-Type-Options: nosniff`).
  4. Never drop `parent_tool_use_id`, `tool_result`, non-text blocks, or non-`success` results in canonical parsers; never mutate target JSON files non-atomically without backup and dry-run.
