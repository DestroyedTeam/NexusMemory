## Architecture and useful prior art

Each benchmark cell launches a native harness process in its own local code checkout and harness home. A hash-chained run ledger records benchmark lifecycle facts; cell archives are content-hashed and verified before teardown. The archive walker records symlinks without following them and excludes caller-specified credential basenames. `snapshot_cell` snapshots only the cell's `ws`; full `archive_cell` copies the cell folder. These patterns are useful for Nexus's consented source snapshot, provenance and integrity-verification layer, but they preserve a benchmark cell, not a portable multi-harness session graph.

`src/harness_bench/telemetry` is particularly relevant observability prior art. Its anti-corruption layer reads native records from Claude Code JSONL, Codex rollout JSONL, Copilot session storage, Antigravity and Grok-related stores, then projects measured facts such as `ModelCall`, `ToolCall`, `ProviderError`, `MissingField`, `ServedSettings`, `ReasoningItem`, `PromptPart` and `HarnessEvent`, with native ordinals and source session IDs. It treats absent data as “not recorded” rather than a fabricated zero, bounds line/file sizes, and records malformed/truncated data. This can inform Nexus source-readers and capability/fidelity reporting.

The projection is deliberately not a lossless conversation interchange. `Extraction` keeps one `first_user_text` plus selected usage, tool, reasoning/prompt/harness facts; it does not model every user/assistant message, image/file attachment bytes, source Project/Section IDs, actual parent/fork/subtask edges, or target resume handles. The broader `ProcessTrace` is used for benchmark process metrics, not as a universal conversation envelope. The five adapter files do not comprise five verified end-to-end migration integrations: the README identifies the current walking skeleton as Claude Code and Codex; it explicitly leaves several benchmark features (including Copilot and resume) as later phases.

CLI `--help` lists validation, plan/run/status/stop/answer/grade/report/verify/teardown, campaign, discriminate, interactive and tools commands; it exposes no cross-harness conversation import/export or target-session restore command. `resume.py` resumes/reconciles a benchmark run from its own plan, event, archive and cell ledgers—it is not native harness conversation resume. “Project”/“cell” means benchmark task checkout, and “session” often means one benchmark repetition or one harness run, not ChatGPT/Codex project/Section membership.
