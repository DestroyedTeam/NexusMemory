WHAT IT TRANSFERS
This is a macOS-only Rust CLI/stdin MCP manager for named, persistent local Chrome user-data profiles and session-owned browser tabs. Explicit `profile export`/`profile import` transfers one **ABM-managed Chrome profile** between Macs; it is not a Harness conversation/session/project migrator.

- Export can capture available cookies from the managed Chrome profile directories, including session cookies with explicit `--stop`; it leaves the source browser stopped. The passphrase-protected `age` archive contains persistent browser files such as bookmarks, history, preferences, local/session storage, IndexedDB, service worker and extension data, plus available portable cookies. A user’s regular Chrome profile is neither adopted nor read.
- The archive is gzip/tar inside authenticated age encryption (scrypt work factor 18). Export streams without a plaintext archive or cookie sidecar, refuses overwriting and manager-runtime paths, and checks ignored/untracked destinations inside Git repos. Import uses private 0700/0600 staging, authenticates/extracts before publishing, rejects traversal/links/special files/duplicates and expansion bombs, and restores portable cookies via destination Chrome so that Chrome re-encrypts them for the destination OS. It refuses existing profiles. Source security checks and archive parsing are substantive, not just README claims.
- It is Mac-to-Mac only. Cookies are not proof of login; device-bound sessions, Keychain passwords, passkeys, MFA, expiry/revocation, and site risk checks can require reauthentication. Incognito/page-memory state is not transferred. The encrypted password database files may copy as browser data, but their OS-protected password contents are not made portable and no Keychain keys are extracted. Real accounts and physical second-Mac transfer were not tested.
- It does not transfer ChatGPT/Codex project/session objects, Claude conversations, Projects/Section Groups, message trees, subtasks, token usage, Skills, plugins, memories, schedules, API keys, or MCP settings. It only prints `claude`/`codex`/`antigravity` MCP config snippets for manual merge; it does not edit agent settings. It explicitly excludes manager records, tab grants, registry, machine-specific native messaging registrations and Chrome runtime links.
- Its MCP session is a browser-control identity (open/list/navigate/read/click/type/close) bound to one process/browser run, not a conversational Session. CDP is unauthenticated local control: the documented boundary protects cooperating clients, not against another process running as the same user. It is not an OS sandbox or network/SSRF boundary.
