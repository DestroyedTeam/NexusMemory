## What it implements

A native SwiftUI macOS manager for local Skills, global instruction files, selected agent configuration, safety-reviewed filesystem changes, local profiles and CLI/stdio-MCP management. README requirements are macOS 26+, Xcode 26+ and Swift 6.2+. It reports that automated grouping, plugin installation, and general MCP/hook management are not implemented. Its own README warns that discovery/enabled state does not prove an agent loaded a Skill into a conversation.

Source confirms `SkillGroup` is a `Codable` record of `{id, name, symbol, skillIDs}` stored under `AppPreferences.groups`; active group IDs and group selection mode drive enabling/disabling installed Skill paths. A `WorkProfile` contains a name/note and `ProfileMember` snapshots (`id`, name, path, agent name), not Projects or sessions. The app's “history” page is inspection/change activity. No conversation, transcript, ChatGPT Project/Section, session-parent/child, branch, attachment, schedule or generic import/export data model was found. The word “group” is therefore not evidence of ChatGPT sidebar Section Group compatibility.

The bundled local MCP is intentionally a Skills manager, not a session writer. Its eight tools are `status`, `list`, `show`, `check`, `groups`, `plan`, `request`, and `requests`. `request` queues a local Skill enable/disable intent for human approval in the app; there is no apply tool in MCP. The README says the app does not sign in to a model provider or read agent credentials. It manages Skills, some global instruction files and agent CLI/MCP registrations, not Claude Desktop 3P Chat/Cowork/Code conversations or API-key migration.

## Disposition

Keep as a useful **local ResourcePlane/management UX and transaction-safety reference** (grouped Skill activation, managed configuration, human-reviewed plans, backup/journal/recovery, local MCP). Reject it as a ChatGPT/Codex Projects/Sections/SessionGraph migration engine and as evidence that a Skill group represents a chat Section. It has no session/import writer, no target-native Chat/Cowork/Code 3P resume test, and no transcript or attachment transfer. Do not count it as a fidelity-compatible adapter.
