## What this candidate actually provides

Connections Manager is a Windows x64 ECPA plugin/helper for named Cloudflare/GitHub/Portainer connections, local Windows Credential Manager storage, project-directory assignments, agent/client setup and an optional separate central MCP gateway. Its Project assignment is an existing absolute local path with nearest-parent resolution for connection selection; it is not a ChatGPT/Codex Project object, a Section Group, or a session parent/child graph. Data-directory JSON can be moved but vault credentials do not follow; credentials must be entered again on the destination. The shared gateway/provider routes are a separately installed Windows runtime, not a ChatGPT/Claude Desktop conversation importer. Provider model routing through CLIProxyAPI authentication and MCP service grants are explicitly separate.

The source workspace includes two separate plugins that are more relevant to Nexus Memory than the Connections Manager release alone:

- MCP Manager edits individual Claude Code and Codex configs (~/.claude.json and CODEX_HOME/config.toml). It can explicitly copy supported local stdio and Streamable HTTP fields between these formats. It uses previews, per-file version checks, backups, conflict prompts and reviewed restore; it preserves unrelated entries/settings. Client-specific or unsupported fields (for example token environment references or tool restrictions) block translation instead of being silently dropped. The server command is never executed or connectivity-tested. Full-file previews can contain credentials; plugin config backups are local plaintext. These are strong narrow-transfer/data-loss-control patterns, not transcript migration and not ongoing synchronization. The docs name Claude Code, not Claude Desktop Chat/Cowork/Code, and do not include ChatGPT as a source/destination.
- Agent Skills is another separate plugin that views/creates/edits one local SKILL.md at a time, with minimal YAML metadata validation, preview, backups and restore. It scans one level, max 500 entries, across Claude Code and Codex roots plus an optional extra root. Supporting scripts/references/assets remain untouched; no remote Skills installation, bundle copy, or guarantee of target discovery is claimed.
- The gateway-side MCP import accepts only claude, codex, or native gateway configuration, and creates a disabled credential-free draft. It refuses literal environment/header secrets and unsupported client-specific fields for review; this is safer than blindly copying a full MCP config, but it is still only server-definition import.

## Fit to the user’s end state

No importer was found for ChatGPT/Codex Projects or Section Groups; session/conversation/event or parent-child/fork graphs; transcripts, branches, images/attachments/links, usage/tokens; scheduled tasks; or Harness memory. No session/history adapter exists for local/self-hosted Claude Code. Claude Desktop third-party-gateway Chat, Cowork and Code are not config targets here. Therefore, reject as the requested cross-Harness Project/Session migration engine, but retain as a high-value adjacent architecture/reference for MCP config translation, explicit loss rejection, target snapshots and rollback, SKILL.md file management, per-client grants, and secrets kept out of portable config. Connections Manager alone should not be described as a Harness migrator.
