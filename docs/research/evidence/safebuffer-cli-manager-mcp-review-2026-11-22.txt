## Source-level behavior and security boundary

- MCP execute tool accepts `cmd: str` (server.py lines 590–639). The manager sees a string, sets `shell = isinstance(cmd, str)`, and passes it to `subprocess.Popen(..., shell=True, stdout=PIPE, stderr=PIPE, text=True)` (lines 310–330). No allowlist, sandbox, per-call approval, cwd, timeout, env policy, or resource limit on output is enforced. The README's trusted-agent/sandbox warning is advisory only.
- The global `_process_manager` holds process records in a Python dict (line 584), so state is server-process-local and disappears on restart. The server is not a durable session store. One shared registry has no per-user namespace in source.
- Status/result tools expose command text plus stdout/stderr/return code (lines 353–413, 649–691); the launch path logs the full command (line 346). There is no redaction layer for credentials accidentally placed in command arguments or output.
- Default capacity is 100 process entries (constructor line 258); completed entries age out after an hour from creation (cleanup loop lines 539–580). `communicate()` collects complete output before storing it; no output-size ceiling is defined. This can create memory pressure for high-output commands.
- `cleanup()` terminates/kills only the Popen process object, not an explicit process group. Inference from the shell-based execution path: on platforms where `/bin/sh -c` or another shell spawns grandchildren, terminating the shell may not terminate every descendant; this was not dynamically tested.
