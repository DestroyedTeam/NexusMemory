## Product scope and reuse boundary
- README describes a dependency-free Go CLI for installing agent Skill directories from GitHub subdirectories. The source’s state model is `.manifest.json` (declared source/target), `.lock.json` (resolved commit and normalized content hash), installed files on disk, and derived cross-namespace symlinks/mirrors. It recognizes directories such as `~/.agents/skills`, `~/.codex/skills`, `~/.claude/skills`, OpenCode and OMP. Its operations are list, sync/install, update, doctor, info and shell completion.
- This is an adjacent **Skill resource inventory/synchronizer**, not a conversation or Harness migration engine. No ChatGPT export reader, Project or Section Group representation, Session/Event graph, message parent/child/subtask relations, branch handling, attachment/media transport, token/use metadata, schedules, memory import, MCP/plugin migration, or Claude Desktop Chat/Cowork/Code session adapters were found. It cannot migrate Destruction Era session contents or assert a post-migration fidelity rate.
- Useful ideas only: separate desired/locked/on-disk/mirror state, immutable commit and content pins, and a machine-readable drift report. Important guardrail: `skills sync` explicitly restores content changed from its locked hash, so it overwrites local edits in a managed Skill directory; do not adopt that overwrite policy for user-authored memory/session data.

## Reproduced security behavior — isolated temporary copy only
`cmdSync` validates an explicitly selected skill name, but its full-manifest branch passes each manifest entry into `InstallAll` without applying `validateSkillName`. I ran the synthetic regression probe against a disposable source copy under `/tmp/nm-cagedbird-path-probe`; it used only `t.TempDir()` paths and a fake source. Command: `rtk proxy env PATH=/tmp/nm-go1.27.4/bin:$PATH go test -run TestManifestNameTraversalOutsideTarget -count=1 -v` → exit 0 (the test passes because it detects the vulnerable behavior). Literal observed lines:

```text
=== RUN   TestManifestNameTraversalOutsideTarget
  ✓ ..
  0 up to date, 1 installed, 0 failed
    path_traversal_probe_test.go:23: manifest_name=".." target=/var/folders/62/8__6fhqd5dq7bh2cgp2_75lh0000gn/T/TestManifestNameTraversalOutsideTarget4229850066/001/managed/skills escaped_skill=/var/folders/62/8__6fhqd5dq7bh2cgp2_75lh0000gn/T/TestManifestNameTraversalOutsideTarget4229850066/001/managed/SKILL.md sentinel_removed=true
```

A manifest skill named `..` escaped the configured `managed/skills` target and replacement removed a synthetic sibling sentinel. No user files were touched. This makes untrusted manifests unsafe to apply as-is; validation must happen before path resolution or filesystem mutation.

## Disposition

Keep at most its pinned resource inventory/drift-report concepts for a separate ResourcePlane, after fixing manifest traversal and designing non-destructive conflict handling. Mainline CI passing does not mitigate the reproduced path escape.
