WHAT IT ACTUALLY DOES
- One local store under ASM_HOME (~/.asm by default) contains Skill/Plugin files and MCP config/binaries; agent profiles project Skill/Plugin symlinks and inject MCP entries into native config.
- Built-in Agent enum is exactly Claude, Codex, Cursor, Gemini. Skill path support is broader than the management logic; MCP discovery/injection and plugin scans are explicitly implemented only for Claude and Codex.
- The generic migrate operation scans unmanaged Skill/MCP/Plugin packages, imports packages into ASM, and projects them back. This is package/resource migration only: it contains no provider transcript reader or writer, Project/Section Group hierarchy, Session/Message/turn/fork/subtask model, branch graph, attachments, token usage, schedules, memory, or source-side conversation archive.
- No Claude Code session history and no Claude Desktop Chat/Cowork/Code/API-key gateway session adapter. The function MCPConfigPath returns a Claude Desktop config filename but CodeGraph callers show it is only used in unit tests; runtime migration scans ~/.claude/settings.json and Codex config.toml, and injection writes those paths. It is not a Claude Desktop adapter.
- Positive design patterns: central content store and link records, separate packages by kind, explicit dry-run of unmanaged package migration, and an eject command intended to restore materialized package copies. Treat these as concepts only, not code to reuse.

CONFIRMED SAFETY FINDINGS — TEMPORARY FIXTURE ROOTS ONLY
1. MCP local-binary path boundary:
   - Source localBinaryPath uses strings.HasPrefix(command, agentHome), not a separator-aware relative-path check. migrator.Apply copies the resulting file into ASM and then calls os.Remove on the original before native-config injection has completed.
   - A checksum-verified v0.1.2 release binary (asm v0.1.2, short commit 2537ee2; the same full HEAD as the clone) was executed against a temporary HOME. Fixture agent home was /.../home/.claude; MCP command path was a sibling /.../home/.claude-shadow/mcp-helper. It passed the string-prefix check. Command: asm mcp migrate --agent claude.
   - Literal result:
     {"checksum_verified":true,"binary_version":"asm v0.1.2 (commit: 2537ee2, built: 2026-04-22T07:27:09Z)","mcp_prefix_probe":{"exit_status":0,"path_shares_prefix":true,"outside_original_binary_exists":false,"binary_copied_into_asm_store":true,"stored_config_mode":"0644","fixture_env_value_plaintext_present":true}}
   - No actual secret was used; the fixture env value was “not-a-secret”. The temporary HOME tree and downloaded binary were removed.
2. Store ID traversal:
   - store.PackagePath joins ASM_HOME/store/<kind> with raw package ID, and the CLI accepts --id without validation.
   - Using the same verified release binary and a local fixture directory, asm skills install <fixture> --id ../../../../escaped-package exited 0 and copied payload.txt to a temporary sibling outside ASM_HOME.
   - Literal result:
     {"exit_status":0,"id":"../../../../escaped-package","target_outside_asm_home":true,"payload_written_outside_asm_home":true}
   - The escaped output remained inside the temporary root and was deleted with that root.
3. MCP config confidentiality/transaction:
   - MCPServerConfig has Env string values. InstallMCPConfig stores config.json as plaintext with requested mode 0644 under a directory created 0755; the temp POC observed actual 0644 and confirmed a dummy env value persisted. Effective access still depends on the parent directory permissions/umask.
   - migrator.Apply removes the original local MCP binary before the following enable/config-injection step. If a later step fails, there is no rollback of that removed binary. Static ordering observation; no forced post-deletion failure was run.
4. Plugin migration similarly trusts installPath from Claude's installed_plugins.json and EnableAtPath recursively RemoveAlls that path before creating the store symlink. This is a static boundary concern; no plugin deletion POC was run.
