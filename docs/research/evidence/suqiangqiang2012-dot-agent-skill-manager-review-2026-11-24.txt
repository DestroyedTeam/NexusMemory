## What the candidate is

An Agent Skill package lifecycle system distributed as a SKILL.md skill plus Python standard-library scripts. It checks stable GitHub releases, installs a compatible package, detects local changes, lists versioned backups, rolls back, validates canonical skill source, prepares platform ZIPs, and uses separate exact confirmation tokens for Draft creation and stable publication. Release v0.3.0 contains two target package assets: Codex any-OS and WorkBuddy Windows any-architecture, plus a release manifest and SHA256SUMS.

The core is a good adjacent ResourcePlane design reference: agent+skill scoped state, semver, read-only scheduled checks, published-stable-only installs, SHA-256 verification, ZIP path/symlink rejection, staging and atomic directory replacement, backup of the previous version, overwrite confirmation for locally modified files, rollback confirmation, per-agent OS/architecture/version/dependency declarations, fail-closed adapters, and separately authorized prepare/draft/publish/catalog actions.

## Concrete Codex path compatibility mismatch

Candidate source skill/scripts/skill_manager.py::resolve_install_root chooses CODEX_HOME/skills when CODEX_HOME is present, otherwise ~/.codex/skills. A no-write synthetic probe with HOME=/tmp/nm-asm-codex-path and CODEX_HOME unset printed exactly /tmp/nm-asm-codex-path/.codex/skills.

The current official [OpenAI CLI reference](https://developers.openai.com/api/reference/cli) lists Codex project skills at .agents/skills/ and user skills at ~/.agents/skills/. This candidate's default Codex install path therefore differs from the currently documented discovery path. An explicit --install-root can work around it, but the default adapter needs updating or native discovery evidence before unattended installation. This is a real ResourcePlane compatibility issue, not session migration evidence.
