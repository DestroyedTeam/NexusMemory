## What it does and where it stops
- Electron/Svelte desktop UI manages Skills from three source types: live skills.sh catalog, Git repositories, and local folders. It supports custom `installDir`, global/project scope and multi-select agent targets. Its file providers copy each Skill into a canonical `.agents/skills/<name>` store and create per-agent symlinks there (copy fallback on OSes where symlink creation fails); official source installation delegates to pinned `npx skills@1.5.14`.
- The static `KNOWN_AGENTS` table declares 72 agent IDs, including Claude Code, Codex, Antigravity CLI/App, Cline, Roo, Gemini CLI, Cursor, Copilot, Kiro CLI, OpenCode, OpenClaw, Warp and Zed. The table contains `claude-code` only—no Claude Desktop Chat/Cowork/Code modes. These are per-target Skill path adapters, not semantic converters. Test coverage checks IDs/CLI flags are unique and installation works for a couple of paths; it does not E2E-test all 72 applications or every path/version.
- No conversation/session import/export, Project or Section Group model, parent-child/task graph, transcript/media/tool-call transfer, token usage, memories, schedules, MCP-server or plugin/settings migration. It is a potentially useful Skill ResourcePlane UI/distribution reference only, not a Nexus Memory session migrator or complete auto-support solution.
- Official security-audit data comes from skills.sh. The UI prompts when audit metadata reports medium/high risk; custom Git/local entries may have no skills.sh audit data, so this is not a complete trust policy for arbitrary sources.

## Reproduced failure behavior (temporary filesystem only)
`installFromFolder()` calls `copyInto(source, canonical)`. `copyInto` first recursively removes the existing canonical destination and only then copies the replacement; it does not stage/rollback the old version. I added a transient Vitest regression probe (removed immediately afterward) with an existing canonical `SKILL.md` and a nonexistent source path. `installFromFolder()` rejected, but the old skill was gone. Exact probe observation: `{"old_skill_exists_after_failed_reinstall":false,"old_skill_contents_after_failed_reinstall":null}`; Vitest exit 0 because the test expected to observe the destructive behavior. All files were under a fresh temporary directory and the pinned Git checkout returned to clean status. This is a user-data preservation defect for Skill state, not a Session migration result.

## Disposition
Keep as a useful desktop UX/resource-plane reference for local/Git/skills.sh Skill discovery, a canonical `.agents/skills` library, per-agent paths and previewed symlink reconciliation. Do not treat it as “every Harness” verified: the support table is static and only lightly tested, lacks the three Claude Desktop modes, and has no Session/MCP/plugin migration. Before using its implementation for user-authored content, require transactional updates that preserve the old Skill on failed copy and resolve the two high-severity npm audit findings, then test each claimed target against actual host versions.
