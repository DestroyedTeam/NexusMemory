## Product surface and actual data model

LocalVault creates encrypted named vaults containing secret key/value material. Its “groups” are secret-key namespaces (including dot notation such as `project.API_KEY`), not ChatGPT Projects, Sidebar Sections, Section Groups, workspaces, or session containers. `localvault import` parses `.env`, JSON and YAML secret files; it does not parse conversation/session archives. Personal/team sync uploads encrypted vault bundles and metadata through the InventList vault API, authenticated by the service's bearer token; this is neither an LLM-provider API-key gateway nor a transcript/session cloud. Source code packs `meta` plus the existing encrypted `secrets.enc` bytes into the sync bundle.

The MCP server uses local stdio JSON-RPC. Tools include `list_secrets`, `localvault_build_exec` (returns a command but does not execute it), `get_secret` (requires explicit `allow_plaintext: true`), `set_secret`, `delete_secret`, and `localvault_whoami`. The installer targets Claude Code CLI, Cursor, and Windsurf configuration. Claude Code-only guard hooks scan tool input/output for stored secret strings. No target for Claude Desktop Chat/Cowork/Code was verified. The `SessionCache` symbol is specifically an eight-hour cache of an unlocked vault master key in macOS Keychain or a file fallback; it is not a model conversation Session.

Inspected source confirms Argon2id key derivation, XSalsa20-Poly1305 authenticated vault encryption, X25519 team-key slots, atomic ciphertext writes with restrictive file/directory permissions, and process-scoped secret injection. This is a useful security pattern: store credentials separately from portable context, refer to secrets by names/environment mappings, and require an explicit user action to reveal plaintext. Do not copy secret values, provider tokens, auth tokens, or decrypted session-cache keys into Nexus Memory bundles. Important limitation: the Claude Code guard fails open on errors/locked vaults and is only a defense-in-depth hook; it is not a hard sandbox or a general Harness policy.

## Nexus Memory decision

Keep as a **medium-value adjacent security/MCP reference**, not as a direct migration candidate or shortlisted implementation. Its helpful design cue is a credential plane separated from the conversation/context plane, with references and just-in-time process injection rather than embedding credentials. The project cannot satisfy ChatGPT Project/Section/session hierarchy, Claude Desktop mode, or cross-Harness transcript import/export requirements. Direct adoption is further gated by unresolved license metadata.
