WHAT IT ACTUALLY DOES
This is a Pi-only local search/export/view/resume utility, not a cross-Harness migrator. `pi-export-history` reads Pi session JSONL below `~/.pi/agent/sessions/` and emits Markdown below `~/.pi/agent/sessions-md/`; `-t` emits a separate full corpus that includes tool-result text. Keyword search uses ripgrep; optional `-v` semantic search uses a `qmd` collection. `fzf` selects a result; `ctrl-o` opens a transcript, and `enter`/`resume` maps the exported path back to its original JSONL and invokes `pi --session` in the recorded cwd. This is source-native Pi resume only; it does not create or restore a session in another Harness.

FIDELITY / DATA MODEL LIMITS
- The README advertises text export while excluding thinking blocks, tool plumbing and HTML blobs; default export omits `toolResult`, while `-t` includes it. The Markdown output is a flattened rendered text transcript, not a structured event-preserving interchange format. It does not preserve message/event IDs, parent links/branches, token/cost usage or executable tool state; image/multimodal payloads are not represented in the text export.
- Parent/subagent filtering is path-based: the CLI recognizes `subagent-artifacts/` and `run-N/` and can hide those rows. It does not construct a parent-controlled session DAG or preserve control/task edges.
- Project identity is essentially the session cwd encoded in the Pi session path, not a portable Projects / Sections / Section Group hierarchy.
- No source reader or destination writer exists for ChatGPT/Codex, Claude Desktop third-party gateway Chat, Cowork or Code, or local/self-hosted Claude Code. No Skills, MCP, plugins, memory, credentials/API-key configuration or scheduled-task migration is present.
- Plain local Markdown exports and any qmd index are created under the user's home tree. Do not infer encryption-at-rest or a migration backup policy from the README. No live history, account, clipboard, semantic index, cron job, or API key was accessed here.
