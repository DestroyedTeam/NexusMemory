## Implementation observations

- The README identifies keynv as a self-hosted secrets vault with aliases instead of exposing secret values to agents. Its MCP tools are for vault identity/list/use/redact/test-connection workflows. Its Project term means vault project/environment scope; Session is web authentication/session state, not a conversation transcript.
- The text-surface abstraction scans raw text in supported surfaces including Claude Code JSONL and Cursor logs; it can report match previews and redact text. It is not a semantic event importer/serializer: preserving valid JSONL syntax does not preserve or transform a provider session graph.
- packages/text-surfaces/src/rewrite.ts reads the entire file, redacts the in-memory string, optionally copies a backup, writes a temp file, fsyncs it and renames it over the source. A backup retains the original plaintext secret. The active-file guard can be overridden.
- apps/cli/src/watcher/watcher.ts calls rewriteFile with includeActive true and backup false. The watcher uses a 1-second default debounce. The checked-in source comment explicitly warns that a concurrent append between read and rename can be lost; source/docs also describe no cross-process file lock. Watch tests cover watcher lifecycle and ordinary synthetic fixtures, not a concurrent append race. This is a source-documented data-integrity risk, not a claim that a production user's transcript was damaged. A supplementary probe result was not retained as reproducible evidence, so no runtime reproduction is claimed.
- Do not run scrub/watch against real or user-owned transcripts as part of this research. Any future privacy/redaction use would require opt-in, a concurrency-safe writer/lock or immutable copy, backup handling that does not silently retain secrets, and restore tests.
