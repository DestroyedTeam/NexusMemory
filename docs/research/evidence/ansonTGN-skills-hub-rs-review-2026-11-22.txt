## Implementation reviewed

The repo provides a Rust CLI plus Tauri Desktop for a local central Skill store (`skills/` + SQLite) and syncs `SKILL.md` directories into configured harness paths. `src/tools.rs::builtin_tools()` lists 47 adapters and `tests/core.rs::builtin_catalog_has_expected_tools_and_cursor_forces_copy` asserts that count; the test only spot-checks Cursor and Codex paths. Claude Code is the `.claude/skills` adapter, not Claude Desktop Chat/Cowork/Code or the Desktop 3P gateway. `MCPJam` is another Skills-directory adapter; the implementation does not parse, import, merge, or restore MCP server configurations. No Projects, Sections, sessions, transcript graph, parent/child sessions, interruptions, attachments, media, token-usage ledger, memory graph, plugins, or schedules are modeled.

Source-level fidelity / safety notes:

1. `run_git_clone` performs a depth-1 clone and optionally passes the user-supplied ref to `git clone --branch`. The record retains that supplied ref, not the resolved commit SHA. With no ref, later updates reclone the moving default branch. The Cargo lockfile locks Rust dependencies, not Skill source revisions; reproducibility/provenance must be implemented separately.
2. `sync_dir` with `overwrite=true` removes an existing target before creating the replacement. If the later copy/link creation fails, that old target is not restored. `update_skill` does stage/rename the central managed directory, but then resyncs each existing adapter target with overwrite enabled. This is a source-derived failure window, not an empirically triggered data-loss incident.
3. `update_skill` replaces the central directory before writing its DB metadata; a DB failure after filesystem replacement could leave fresh content with stale metadata. This ordering is source-derived and was not fault-injected.
4. Tool path mappings are static. The 47 count is source/test-confirmed; target correctness across tool versions/operating systems is not implied by the count.
