Retain as an **adjacent GitHub CI skill-dispatch / harness-adapter reference only**. Exclude as a Nexus Memory Projects/Sections/session migration engine. This action installs remote skill bundles, filters configured skills by GitHub pull-request/comment triggers, invokes one of Claude Code CLI, GitHub Copilot CLI, or pi in headless mode, and posts/commits results back to a PR. ## Implementation actually present

1. `src/index.ts` reads `.github/ai-skills.yml`, validates a GitHub PR/comment event, optionally parses `/ai run <skill>`, installs the configured skill bundle through `npx @ai-agent-manager/cli@<agent-manager-ref>`, filters skill definitions by event, resolves per-tool credentials, fetches the PR diff once, and runs matched skills sequentially.
2. Declared consumer tools are only `claude-code`, `github-copilot`, and `pi`; the `agent-manager` provisioner ID for pi is `agents`, while Claude Code and Copilot provision through `claude-code`. README examples use repo scope. Per-skill data is `name`, trigger list, `autonomy` (`observe` / `suggest` / `act`), optional tool/model, Claude dollar budget, and Copilot iteration cap.
3. The prompt is `Use the <skill> skill. Here is the diff: <PR diff>`. It is an event-run, headless diff-review/action prompt, not a conversation archive, continuation graph, or native session transfer.
4. Result routing is `observe` → PR comment, `suggest` → overwrite PR description, `act` → commit/push changes to PR head. The `act` path runs `git add -A`; this is broad worktree staging rather than an output-path allowlist.
5. Claude Code child-process env maps a gateway key to `ANTHROPIC_AUTH_TOKEN`, optional URL to `ANTHROPIC_BASE_URL`, and model to `ANTHROPIC_MODEL`. Copilot uses a fine-grained PAT with Copilot Requests; pi uses `LITELLM_BASE_URL`/`LITELLM_API_KEY`. Credential isolation removes inherited harness-secret variables and creates per-tool environments. This is CI runtime configuration, not Claude Desktop 3P configuration or data conversion.
6. Tool launch is deliberately non-interactive/fully approved: Claude Code uses `-p --dangerously-skip-permissions`; Copilot uses `--autopilot --yolo`; pi uses `-a --no-session`. The README explicitly warns that untrusted PR diffs can prompt-inject `autonomy: act` workflows. The action filters issue comments to PRs and bots, but it does not itself check commenter association/permission; README recommends consumer-workflow gating and warns against `act` on fork PRs. Treat this as a required deployment safeguard, not as a migration feature.
7. Tool CLIs are pinned in the Dockerfile, but `agent-manager-ref` defaults to `latest`; installing from an authenticated bundle uses the `AGENTMAN_ACCESS_TOKEN` environment. Pin the manager CLI version for reproducibility and review the external bundle/CLI supply chain.
