## What ships in `cue-ai` and how it works

The npm package is `cue-ai` 0.10.0 (CLI `cue`, Node >=20); npm `latest` is 0.10.0 and its published `gitHead` is `1737340b888b137dd5c03fe838b0c8544cceb50e`, not this review's newer main HEAD. GitHub Releases still marks v0.9.4 (2026-06-12) as Latest. Thus the package and active branch are one version label but not one commit, and the GitHub Releases badge lags the npm dist-tag.

A project can pin one profile name in `.cue.profile`. The YAML profile can define `agents`, `inherits`/composition, recommendations/conflicts, Skills, MCPs, plugins, env, Codex settings, rules, commands, hooks, Claude subagents, persona, playbooks, quality gates, and evals. Cue resolves the directory profile, materializes a content-hashed per-profile runtime under `~/.config/cue/runtime/<profile>/claude or codex`, then dispatches to the native CLI. Its `cue launch` accepts Claude Code or Codex; it does not launch Claude Desktop. This profile selector/inheritance graph is not a ChatGPT Project/Section tree or Session hierarchy.

There are 11 `AgentKind` IDs. Only `claude-code` and `codex` are full native runtimes. The nine other adapters are Cursor, Cline, Windsurf, Gemini CLI, Antigravity, GitHub Copilot, Roo Code, Amp, and Aider. Their `materializeExternalProfile` path writes profile Skills and MCP settings using native adapters; it does not carry the whole profile semantics (plugins, persona, gates, hooks, Codex-only settings, Claude subagents). Aider's adapter explicitly has no MCP writer. Some adapters express Skills as a single instruction/rules file rather than preserving native skill metadata. This is an adapter architecture reference, not evidence of lossless cross-Harness portability.

## Session/history data actually present

Core shipped analytics is a local `~/.config/cue/analytics.jsonl` event ledger with `start`, `end`, `skill_hit`, `skill_invoked`, `skill_miss`, `skill_gap`, profile, agent, cwd, duration, `session_id`, tool-use ID and, for misses, a redacted prompt snippet. It does not model message turns, parent/child/fork topology, tools/results as a transcript graph, attachments, token consumption or restoration. The local transcript ingest feature reads selected native logs to detect Skill calls/misses; it is an analytics input, not an archive export/import.

The repository also contains `evolution/evolution/core/external_importers.py`: a Claude Code `history.jsonl` importer that extracts displayed user text plus project/session/timestamp, Copilot event importer that extracts user/assistant text pairs, and Hermes JSON session importer. They filter selected secret markers and feed relevance-scored examples into train/validation/holdout **skill-evaluation datasets**. They do not write a target native Session, do not cover ChatGPT Projects/Sections or Claude Desktop, and are not in `package.json`'s npm `files` allowlist. The `.claude/` session-state hooks in this repo likewise produce a compact latest.md/archives for this repository's development workflow; those files are not shipped by `cue-ai`.

## Nexus Memory decision

Retain Cue as a high-value **profile/schema/adapter-pattern** reference. Reuse the explicit capability-oriented adapter approach (native runtime vs partial external config writer), directory-scoped asset bundles, and clear data-plane separation. Do not claim it migrates ChatGPT Projects/Sections, Claude Desktop modes, or Sessions. Its repo-only text extractors may inform optional future parser research, but are not a shipped import component. Model a future NexusMemory adapter's read/write capabilities and lost fields explicitly; never infer session compatibility from profile/Skill/MCP support.
