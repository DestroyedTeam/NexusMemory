## What it actually implements

This is a canonical hub for a selective agent-routing workflow, not a session/project exporter. The hub retains architecture, decomposition, verification and acceptance, and routes implementation among solo, delegate, audit, and full; platform-specific prompt/spec trees are exported one-way to separate Codex, Claude Code and Antigravity repositories. The platform concept is the workflow/harness. Its specs directory holds agent-role contracts, not source Project/Section records. There is no ChatGPT/Codex Project, Section Group, conversation event graph, session transcript, attachment/media archive, user-edit/interrupt lineage, or target-native resume writer.

The valuable part is scripts/sync-spokes.sh (780 lines): manifests declare a small allowlisted set of configuration/plugin paths; the source is the hub and the destination is each spoke. The script validates expected origin and repository root, relative paths/type/symlink containment, declared validators, clean destinations, and ignored files that could be deleted; it preflights all selected spokes and revalidates paths immediately before the first mutation. Its --push mode copies with content checks, runs each native validator, recomputes exact drift, and attempts a scoped rollback if a spoke fails. This is high-quality ResourcePlane/config-export safety prior art for Nexus, not cross-harness session migration.

Important transaction caveats are explicitly documented in source: the second path pass narrows but does not close the TOCTOU window. Preflight is all-selected-spokes-before-writing, but once application begins a failure can leave earlier spokes kept while later spokes roll back/refuse; the output reports the mixed state. It is therefore not an atomic multi-destination commit. Do not overstate rollback guarantees or port the code without re-auditing.
