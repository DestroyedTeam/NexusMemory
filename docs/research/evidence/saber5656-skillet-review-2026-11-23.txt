## What the design actually proposes

An npm CLI package manager for Agent Skills directories (`SKILL.md` plus assets/references/scripts), with v1 adapters for local Claude Code and Codex. Proposed design includes a curated JSON index; owner-bound package IDs; semver ranges; immutable releases; lockfile exact commit plus canonical SHA-256 tree hash; direct/local Git refs; copy-based installation; explicit consent; local state receipts; frozen CI install; search/info/add/update/remove/list/verify/validate/cache; no execution of fetched skill code. Its security model proposes enumerating Git objects with `git ls-tree` and `git cat-file` instead of unpacking archives, rejecting symlink/gitlink/traversal/case-collision/oversize trees, writing only through tracked receipts, and adversarial end-to-end tests. The plan contains 40 granular implementation issues and CI/release gate proposals. These are design intentions, not verified behavior.

The v1 explicitly excludes Claude plugins, MCP servers, `.claude/commands`, agent configs, adapters beyond Claude Code and Codex, private indexes, and cryptographic signing; prompt-injection scanning is deferred. It contains no ChatGPT/Codex Project or Section Group importer, no session/message/tool-event/parent-child/branch graph, no attachment or output payload importer, no schedule importer, and no cross-harness session restoration/resume. Thus it is only an adjacent Skill resource-plane design, not Nexus Memory's requested transfer engine.

These could represent different install integrations or client generations; no implementation/runtime test resolves them in this repository.
