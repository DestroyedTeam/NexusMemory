## Finding and fit

`agents-sesame` is a local, single-machine history index/search/preview/resume TUI, not a cross-Harness importer/exporter. Its flat `Session` record has `id`, `agent`, `title`, `directory`, `timestamp`, `content`, `message_count`, `mtime`, and `yolo`; it has no Project/Section/Section Group or canonical event/branch/parent-child/subagent graph. Reviewed adapters cover Claude Code CLI, Codex CLI, GitHub Copilot CLI/VS Code, Crush, Gemini CLI, Kimi CLI, OpenCode, Qwen Code, and Vibe. Search and `resume` dispatch back to a source CLI; no Claude Desktop Chat/Cowork/Code reader/writer exists. Claude-only `ase relocate` moves Claude Code storage between project directories; it is not harness conversion and does not implement ChatGPT/Codex import.

No ChatGPT export/Project/Section source exists. No writer exists for local/self-hosted Claude Code or Claude Desktop third-party-inference Chat, Cowork, or Code. It does not migrate Skills, MCP servers, plugins, memory, API keys, schedules, attachments/assets, token/cost usage, or session/tool-call fidelity. Keep it as a narrow local-search UX reference only.

## Source-level coverage and limitations

- Claude Code JSONL parsing turns user/assistant text into indexed content, uses first user prompt and cwd as metadata, skips subprocess `agent-*` files and command messages. Non-text blocks and most tool payload details are not preserved as a portable archive.
- Codex rollout JSONL is indexed as a flat search record. OpenCode is read from SQLite; text parts are indexed, tool results are shallow/truncated (up to 200 characters).
- Roadmap lists export, MCP, semantic search, and AI skill/tool integration as future work, not current capability.
- Incremental scan treats an unavailable adapter as deletion of all known sessions for that agent; parse errors may be silently skipped; adapter error callbacks are ignored. Index identity is session ID alone, not `(agent, session_id)`, a static cross-agent collision risk.
- Tantivy stores searchable session text locally without encryption. Index creation does not enforce owner-only modes; recovery/index-wipe behavior and writer-lock removal are broad. Avoid shared hosts until permissions are fixed and verified.
- `ase relocate` writes destination JSONL before moving/copying data and deleting source, rewrites cwd by string substitutions, removes source index metadata without creating target `sessions-index.json`; relocation lacks focused tests.
- `src/update.rs` uses predictable `/tmp/ase-update-<pid>` staging and treats missing checksum as optional; installer guidance uses curl-to-shell. Treat as supply-chain hardening concerns; no exploit was demonstrated.
