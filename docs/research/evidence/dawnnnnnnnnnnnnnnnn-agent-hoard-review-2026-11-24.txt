## What the implementation actually does

AgentHoard inventories local AI coding-agent storage, categorizes disk use, presents risk-tiered cleanup, manages a recycle-bin/restore path and Git worktrees, and exposes Web UI, CLI and stdio MCP entrypoints. README/configuration names 22 agents, but that is local path discovery/cleanup coverage, not 22 import/export adapters.

The source is a flat session inventory, not a portable history model. lib/core.mjs allSessions() (lines 839-855) collects DSH, Codex CLI, Claude Code CLI plus several flat path scans and returns file metadata such as id, directory, size, workspace, archived and pinned. listDshSessions() derives workspace/title from DSH workspace.json and session folder IDs; listCodexSessions() lists JSONL paths; listClaudeSessions() lists ~/.claude/projects JSONL paths. No transcript/event export, parent/fork/subtask edges, message sequence, asset payload, token usage, or cross-tool identity graph is written by this feature.

archiveSessions() (lib/core.mjs:857-879) only changes DSH archivedSessionIds or moves Codex rollout files between local folders; other platforms are rejected. It is a source-local archive/hide action, not a copy or target import. No ChatGPT Project, Section Group, user-supplied ChatGPT export, Claude Desktop 3P Chat/Cowork store, Claude Desktop Code metadata, or Claude Code API-key profile writer exists. No capability found for carrying Skills, MCP configs, plugins, memory, permission grants, connector login, schedules, attachments, tool results, usage or gateway credentials. No user project was migrated.

## Safety review and isolated synthetic probes

The HTTP server defaults to HOST=127.0.0.1 but permits HOST override (server.mjs:14). This limits default network exposure but is not authentication. The handler has no explicit Origin/CSRF/authentication middleware. readBody() parses JSON independent of Content-Type (server.mjs:28-34). POST /api/trash accepts any non-empty list of filesystem paths without confirm and calls moveToTrash(); moveToTrash() rejects roots and already-trashed paths, but does not require a target to be within configured agent roots (lib/core.mjs:631-663; server.mjs:172-179). POST /api/trash/purge also has no confirm check (server.mjs:189-193). MCP confirmation is stronger for space_clean and space_trash_purge, but space_worktree_remove has no confirm argument/check and force can override dirty/unmerged protections (mcp-server.mjs:63-75, 171-174). CodeGraph found no direct covering tests for moveToTrash(), restoreBatch(), or purgeBatch().

In a disposable server with fake HOME/config/data/trash directories and only synthetic files, a request to /api/trash used Content-Type: text/plain, Origin: http://attacker.invalid and Sec-Fetch-Site: cross-site, with a JSON body naming an external-to-configured-roots fixture. Observed: HTTP 200, okCount=1, synthetic file moved; /api/trash/restore returned HTTP 200, ok=1, and restored the exact synthetic-only content. This proves that the local HTTP route accepts a simple cross-origin-shaped, no-confirm mutation against an arbitrary path; it is not a browser exploit demonstration. No real file was passed to this probe.

A second synthetic request moved a fake file and then called /api/trash/purge with the batch basename, same cross-site Origin, text/plain, and no confirm. Observed: move HTTP 200; purge HTTP 200 with {ok:true, freed:424}; batch absent. The first attempt passed the returned absolute batch path and got HTTP 400 {error:批次名非法}; it was corrected to the documented basename. This is an input-shape correction, not evidence that confirmation is enforced.

## Disposition

Count as a reviewed, low-fit local inventory/cleanup manager, not a cross-Harness migration product or evidence that sessions can be moved. The useful boundary is that inventory, archiving, and actual migration are distinct operations. Do not use this server as a Nexus migration dependency or point it at real profiles until all HTTP mutations have explicit confirmation, allowed-root containment, origin/CSRF controls, safe batch/path validation and destructive-route tests; similarly add confirmation to MCP worktree removal. Nexus should default to read-only inventory and staged export, with a separate, user-approved destructive action plane.
