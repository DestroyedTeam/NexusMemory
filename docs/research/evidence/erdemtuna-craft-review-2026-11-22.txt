## Product scope and what is reusable
- `craft` is a Go package manager for Agent Skills, not a conversation/session importer. `craft.yaml` describes local Skills and GitHub dependencies; `craft.pin.yaml` pins resolved commit SHAs and SHA-256 content digests. It supports transitive resolution using Minimal Version Selection, selective subpaths, Skill frontmatter parsing, Git caching, integrity verification, project vendoring to `forge/`, and globally installing flattened Skills.
- Auto-target support is only **Claude Code** (`~/.claude/skills`) and **GitHub Copilot** (`~/.copilot/skills`). `--target <path>` permits a manually supplied destination. README does not list Codex, Gemini, Cursor, Claude Desktop Chat/Cowork/Code, MCP servers, plugins, conversation/session trees, media, token usage, memory stores, or schedules. The tool can move/resolve Skill files only; it cannot migrate the user's Session graph or Project/Section hierarchy.
- Valuable patterns for a separate ResourcePlane: declarative package manifest, subpath selection, MVS, immutable commit + integrity pin, automatic agent detection with a prompt when multiple targets exist, explicit `--target`, and a recovery hint after write-ahead manifest/pin persistence. Project-local dependencies are vendored to `forge/`, distinct from global installation. There is no package registry/publish service; packages are Git repositories.
- Do not call v0.5.0 safe to reuse unchanged: `go-vulncheck` finds multiple reachable advisories in its Git/network stack. A global installer must upgrade the affected modules and verify actual Desktop target semantics before adoption.

## Resolver limit defect
- Pinned source `internal/resolve/resolver.go:320-326` inserts a previously unseen package into `visited`, then checks `len(visited) > maxTotalDeps` where the documented maximum is 200. This admits 201 before rejection. Existing `TestResolveDepthLimit` covers recursion depth, not the total dependency boundary.
- Upstream has one open PR #34, opened Apr 30, 2026, describing the same behavior and proposing `>` → `>=`; it reports no existing test for the boundary. This PR is not merged/released. This is a source+upstream issue report, not independently reproduced in this review.
