## Verdict

Keep as a high-value adjacent reference for portable skills, reproducible dependency locks, MCP config declarations, ownership/drift protection, and transactional installation. Do not adopt it as Nexus Memory's session/project migration engine or claim native-session fidelity.

Its core is a declarative Skillfile.json/lock and package installation graph. It places skills into six coding environments (Claude Code, Codex CLI, Cursor, Gemini, OpenCode, Windsurf); project MCP configuration covers only Claude Code, Codex CLI, and Cursor. It does not model ChatGPT Projects, Sections/groups, Claude Desktop Chat/Cowork/Code native conversation history, parent/child sessions, prompt edits/interruption chains, multimodal payloads, token accounting, scheduled tasks, or source-to-target conversation mapping.

The clarified target includes Claude Desktop Chat, Cowork, and Code. This repository lists Claude Code, not Desktop Chat/Cowork modes. The Claude Code skill path may be reusable in a compatible Desktop Code workflow, but discovery is not inferred from CLI support and was not tested.

## Source-level findings

### Skill/package model
- src/csk/adapters.py defines project outputs for Codex CLI (.codex/skills), Claude Code (.claude/skills), Gemini (.gemini/skills), and Cursor (.cursor/rules); OpenCode and Windsurf use native .agents/skills discovery. The canonical skill store is .agents/skills; project/global outputs are mirrors/links with a .csk-managed.json ownership record.
- Skill manifests, dependency resolution, content digests, lock records, source trust, and checkout/project resolution are useful design material for Nexus's ResourceBundle/ResourceInstall layer. Project alias/branch/task/worktree/path identity describes installation scope, not a provider conversation/session ID.
- Current OpenAI skill installation docs name .agents/skills as the Codex project location; CocoaSkills also mirrors to .codex/skills. Because it writes a canonical .agents/skills store too, this is not assumed to be a hard failure; validate discovery against the exact Codex build before depending on the mirror.

### MCP behavior and boundary
- src/csk/mcp_native.py defines exactly these project files: Claude Code .mcp.json, Cursor .cursor/mcp.json, and Codex CLI .codex/config.toml. src/csk/mcp_project.py limits targets to those three.
- The project path plans declarations, asks for consent, compares native settings with an ownership ledger, preserves unknown/drifted settings, stages updates, and publishes through a transaction. This is a strong reference for idempotent config migration with ownership and rollback.
- It writes/updates MCP definitions; it does not launch services, prove connectivity, authenticate an account, or transfer OAuth/API secrets. README distinguishes config delivery from server runtime/auth. There is no Claude Desktop Chat/Cowork Connector target in the adapter list.
- src/csk/config.py defaults audit to disabled, backend null, and allow_cloud=false. Cloud audit is explicit opt-in; the pipeline rejects non-public sources and scrubs content before cloud requests. A configured command/Codex backend can be used; therefore do not claim every audit is local-only. None of this is a session export feature.

### Safety / compatibility implications
- Skills are executable instructions and may include launchers; content hashes, version pins, source trust, and review-before-install are useful. A manager does not make arbitrary skills safe.
- MCP definitions may refer to env vars/credentials; migrating a declaration is distinct from re-authenticating in the destination. Nexus should export credential references/requirements, never secret values by default.
- Keep skill bundles, adapter installs, MCP declarations, authenticated connector accounts, and conversation sessions as separate records. A skill/MCP profile may be a session dependency, not a substitute for its transcript/graph.

## Nexus Memory disposition
Use CocoaSkills as one adjacent skills/MCP config adapter reference: normalize skill package + manifest + lock; pin source/content; separate adapter install state; diff native MCP config with ownership/drift protection; require consent and transactional rollback; preserve credential references, not values. Do not count it as a Projects/Sections/session migration implementation or a measured accuracy result. Continue the cross-Harness session corpus and independently test Claude Desktop Chat, Cowork, and Code.
