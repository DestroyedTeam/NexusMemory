# Claude Desktop on third-party inference (3P): mode scope and data-plane evidence

Review date: 2026-11-23. User-confirmed target: the **local Claude Desktop third-party-provider/gateway client**, all three surfaces—Chat, Cowork, and Code. This is not an Anthropic-hosted Claude Code Cloud/claude.ai session, nor merely a standalone Claude Code CLI with `ANTHROPIC_BASE_URL`. Read the current official sources as a versioned product contract; exact installed Desktop version, OS, gateway provider and configuration remain to be pinned before any session writer is enabled.

## Official evidence (all links opened 2026-11-23)

- [Claude Desktop on 3P overview](https://claude.com/docs/third-party/claude-desktop/overview) defines 3P as the bundled local desktop web application routing all model inference to a configured provider (including a compatible gateway) or the Anthropic API. It expressly names Chat, Cowork and Code, and says provider inference/billing are separate from app/session persistence.
- [Feature matrix](https://claude.com/docs/third-party/claude-desktop/feature-matrix) says 3P has on-device conversation history, but no sessions in Anthropic's cloud or mobile/claude.ai web access. Do not call this destination “Cloud session” just because inference uses a cloud provider.
- [User identity and local data](https://claude.com/docs/third-party/claude-desktop/data-storage) gives separate OS application-data roots: macOS `~/Library/Application Support/Claude-3p/`, Windows `%LOCALAPPDATA%\Claude-3p\`, Linux `~/.config/Claude-3p/`. The root is version/installer-sensitive and distinct from standard Claude Desktop.
- Within 3P app data, `local-agent-mode-sessions/` stores Chat and Cowork histories as session state plus per-session working directories; those directories may include `uploads/`, `outputs/`, transcript/audit files. Cowork/global and per-project memory are distinct Markdown stores; Code session metadata is under `claude-code-sessions/`, while its transcript is in the shared Claude Code store `~/.claude/projects/`. `~/Claude/` is a shared user-level location used for project files, live artifacts and scheduled tasks. A path reference alone is not an attachment or payload.
- Chat/Cowork `audit.jsonl` contains prompts, responses, tool inputs/results, permission decisions, and session details such as model/token usage. The official page says the audit file is not encrypted and **Code sessions do not write this audit file**. The three surfaces therefore need distinct readers, field coverage and security treatment. Treat tool results, outputs, files, credentials and any returned thinking as sensitive; preserve provenance and avoid exporting them by default.
- [Chat documentation](https://claude.com/docs/third-party/claude-desktop/chat) says Unified Claude is on by default in current releases; a home-screen message can start a Cowork session on a capable device or a Chat conversation on a device without the Cowork VM. It also describes Chat's narrower read-only project-folder access, per-conversation scratch directory, attached files and project-memory behavior. A `mode` label cannot be hard-coded as an invariant across releases.
- [Code documentation](https://claude.com/docs/third-party/claude-desktop/code) identifies Code as the embedded Claude Code engine with a graphical session manager and explains how Desktop's configured provider credentials and inference keys are passed to Code sessions. This is still Code's session store, not the Chat/Cowork audit layout.
- [Import history from claude.ai](https://claude.com/docs/third-party/claude-desktop/import) documents source-specific imports: claude.ai conversations/projects and local earlier Cowork/Code sessions. This is a copy/import path for Claude-owned data; the docs do not establish a generic ChatGPT/Codex archive reader or writer. A source-specific importer is not proof that external Project/Section/session IDs can be reconstructed.
- [Desktop local export/import](https://claude.com/docs/third-party/claude-desktop/data-storage) is designed for another compatible Desktop device/organization. It can include Chats/Cowork/Code, project data, attachments/output files, memory, scheduled tasks, skills/plugins and local MCP settings, but key material/sign-ins need re-entry, and the ZIP is unencrypted. It is not a cross-Harness normalized interchange format.

## Nexus adapter consequences

Maintain three target capability profiles (`claude-desktop-3p-chat`, `...-cowork`, `...-code`) and one independent `claude-code-cli` profile. Shared provider endpoint/credential configuration does not unify their session stores. Keep Anthropic-hosted Code Cloud/Claude.ai Projects as separate products and do not claim third-party/API-key credentials authorize a hosted-session import. Discover version and OS before touching a target; use only a user-authorized export/copy, keep secrets out, store raw payloads with integrity hashes, and verify per-mode native discovery + resume on a disposable app profile. Preserve source Project and sidebar Section relations independently; map to target Projects only where a target-native link exists. The unresolved clauses remain: stable write API/support status, context-menu import behavior, role/tool-result/cost fidelity, plugin/MCP auth, permission approvals, attachments, memory/schedules, and exact mode transitions.

This is a source-backed architecture update, **not** a live Claude Desktop 3P import/resume test. No account, gateway credential, real user session or application data was accessed.


## Supplemental current Help Center cross-check (opened 2026-11-23)

This additional check preserves the user's explicit clarification: **all three Claude Desktop 3P modes—Chat, Cowork, and Code—are in scope**. The active target is the desktop client with a configured third-party provider / API gateway; the API Key selects inference/authentication, but does not itself make the product an Anthropic-hosted Cloud session.

- Anthropic's [Claude Enterprise → Claude Desktop on a cloud provider guide](https://support.claude.com/en/articles/18426225-move-from-claude-enterprise-to-claude-desktop-on-a-cloud-provider) calls this deployment “Claude Desktop on 3P,” says the configured provider receives inference traffic, and describes Chat/Cowork/Code as desktop features with local device history. It specifically lists the native move's source and omissions: the user's own Claude chats/projects and **local** Cowork/Code sessions can be copied; Cowork/Code cloud sessions, original project/attachment file bytes from a user's personal export, memory, personal instructions, Skills, and connectors do not all come across. This workflow is a Claude-origin move, not a ChatGPT/Codex importer.
- The same official guide says Claude Desktop on 3P history is device-local, does not follow the user to another computer without export/copy, and has no mobile or claude.ai web access. Provider/gateway mode therefore needs an explicit local-store adapter and backup/restore verification, not a “cloud session” adapter.
- The [Help Center ChatGPT/other-provider FAQ](https://support.claude.com/en/articles/8114491-get-started-with-claude) says conversation history from another AI provider cannot currently be imported into Claude; the separate experimental memory-import flow is a summary/memory transfer, not an exact transcript import.
- [Cowork project guidance](https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork) describes importing a Claude Chat project into Cowork one project at a time (bulk upload is not supported), transferring its files and instructions; it says Projects are available in Cowork, not Claude Code, and local project files/sessions can remain on-device. [Cowork surface guidance](https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile) also notes cloud Cowork sessions differ from local desktop work and that Cowork can be unified with Chat in the current UI.
- [Claude data export guidance](https://support.claude.com/en/articles/9450526-export-your-claude-data) says personal exports include conversation data but not uploaded original files and cannot be imported to another personal Claude account. Do not confuse this with the Enterprise-to-3P import wizard.
- [Claude Code cloud-session docs](https://code.claude.com/docs/en/claude-code-on-the-web) distinguish local `--resume` from cloud `--teleport`; hosted sessions require claude.ai auth, and cloud sessions are unavailable through third-party providers. A Desktop Code local session is not the same object as a hosted Claude Code Cloud session.

**Adapter consequence:** keep three versioned Desktop target modes (`chat`, `cowork`, `code`) behind a Claude Desktop 3P provider profile, plus standalone local/self-hosted Claude Code CLI and Anthropic-hosted Cloud as distinct target surfaces. Unified Claude may combine Chat and Cowork UI entry points, but the source mode/state and effective data store must remain explicit. No private Desktop store was read or modified; exact app version, OS, gateway and per-mode native-discovery/resume still require a user-approved disposable-profile test.

Under a third-party provider, Claude Code CLI `--cloud` sessions are unavailable; `--resume` does not list them. This is a provider/account boundary, not a claim that local Claude Code transcripts cannot be migrated. Versioned official support pages checked 2026-11-23; verify again against the installed Desktop/CLI versions before enabling target writes.

## Current Claude Code Memory vs transcript boundary — rechecked 2026-11-23

The current official [Claude Code memory guide](https://code.claude.com/docs/en/memory) states that each session starts with a fresh context window; `CLAUDE.md`/`AGENTS.md` files hold written instructions, while Auto Memory holds learnings and patterns. Auto Memory is per repository, stored under `~/.claude/projects/<project>/memory/`, with an index `MEMORY.md` (only its first 200 lines/25 KB are loaded at session start) and on-demand topic files. The guide says this memory is machine-local and not shared across machines or cloud environments. Current [session docs](https://code.claude.com/docs/en/sessions) distinguish resumable conversation transcripts stored as versioned-internal JSONL under `~/.claude/projects/<project>/<session-id>.jsonl`; a session is a saved conversation tied to a project directory, and native `--resume`/branch workflows operate on that object.

The archived `reflect-kb` docs describe a separate, custom global Markdown knowledge base at `~/.claude/global-learnings/` (or `GLOBAL_LEARNINGS_PATH`), plus a GraphRAG index and metrics file. It is neither Claude Code Auto Memory nor session JSONL, and does not reconstruct source session trees. Keep a canonical immutable SessionGraph and store derived MemoryPlane documents as projections with back-references to exact source events. Exact Desktop 3P Chat/Cowork/Code memory stores remain per-mode and must not be inferred from the standalone Claude Code CLI paths above.

## Current first-party storage/topology delta — checked 2026-11-24

The user confirmed the destination includes all three Claude Desktop on 3P modes: Chat, Cowork, Code, plus local/self-hosted Claude Code. This is inference through a configured gateway/API key, not Anthropic-hosted Cloud conversation storage.

The current official [3P overview](https://claude.com/docs/third-party/claude-desktop/overview) states that the bundled local app routes all inference to a configured provider, including a customer-operated compatible gateway, and includes Chat, Cowork and Code. The [feature matrix](https://claude.com/docs/third-party/claude-desktop/feature-matrix) distinguishes on-device conversations from Anthropic cloud sessions: 3P has local history and no Anthropic-cloud session/mobile/web access. Thus “Cloud” here names the inference/provider topology; it does not make Desktop 3P session objects cloud-native.

The official [user identity and local data map](https://claude.com/docs/third-party/claude-desktop/data-storage) documents OS-specific application roots, separate from standard Claude Desktop:
- macOS: ~/Library/Application Support/Claude-3p/
- Windows: %LOCALAPPDATA%/Claude-3p/ (installer/version-specific legacy MSIX paths also exist)
- Linux: ~/.config/Claude-3p/

These stores are not one shared session schema:
- Chat + Cowork: local-agent-mode-sessions/ stores a local_<uuid>.json session-state file and its working directory per conversation/task. The working directory can contain uploads/, outputs/, and audit.jsonl; the latter records prompts, responses, tool inputs/results, returned thinking, permission decisions, model and token usage. Chat/Cowork project memory is separate under spaces/<projectId>/memory/; global Cowork memory is also separate. Cowork VM state and ~/Claude/ live artifacts/project/scheduled-task files must be tracked independently.
- Code: Desktop records in claude-code-sessions/ hold session metadata (working folder/settings/title/summary), while the conversation transcript is in Claude Code's own ~/.claude/projects/ store, outside the Desktop 3P application directory. Code does not write the Chat/Cowork audit.jsonl. ~/.claude/ and ~/.claude.json also contain Code setup (Skills, plugins, hooks, permission/trusted-folder rules, MCP servers) shared with standalone Claude Code CLI. SSH Code has a remote host/data/credential plane.
- Scheduling: Cowork Scheduled and Code Routines represent local scheduled work with a new session per run; the device must be awake/app open unless the deployment is configured to run all sessions on a server. Do not import a schedule as if it were one historic conversation.
- Security/provenance: the Chat/Cowork audit log is unencrypted and contains sensitive full content; some builds may produce per-entry HMAC signatures but the application does not validate those hashes or prove completeness. Local path references, working directories, file bytes, audit events and provenance must be archived separately and re-linked after import. Do not equate OpenTelemetry/gateway request logs with a complete native transcript.

The official [Code in Desktop on 3P reference](https://claude.com/docs/third-party/claude-desktop/code) says embedded Code runs the same Claude Code engine as the CLI but is a separate graphical session manager and inherits Desktop 3P provider configuration. This does not collapse it into the standalone CLI profile. The [scheduled-task reference](https://claude.com/docs/third-party/claude-desktop/scheduled-tasks) details device/app/provider sign-in, retries, missed-run and approval behavior.

The vendor's Claude-origin Desktop import/export/copy is not a ChatGPT/Codex importer. It is version/OS/organization dependent, may require source-account authorization, and has explicit caveats for folders, approvals, provider keys, credentials, plugins and generated artifacts. See the [local-data/export limits](https://claude.com/docs/third-party/claude-desktop/data-storage) and the separate [Claude Code CLI provider migration guide](https://support.claude.com/en/articles/18466061-move-claude-code-cli-users). Use independent, versioned adapters named claude-desktop-chat, claude-desktop-cowork, claude-desktop-code, and claude-code-cli; first probe build, OS, provider/auth topology, actual mode, project/workspace, file trust, and native resume/discovery. This remains documentation/source research only; no local target store, API key, gateway profile, or private session was opened or changed.
