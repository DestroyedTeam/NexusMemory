SOURCE REVIEW / SCOPE
- Product: manage AI-agent skills; shared `~/.agents/skills` canonical library, read-only Skills CLI v3 lock discovery, per-agent installations, project-local Skills under `.agents/skills`, marketplace search/install for skills.sh and ClawHub, and dotagents-backed sync. The README and source are Skills-specific.
- `ProjectEntryJson` = `{path,name,group?,added_at?,last_used_at?}`. `ProjectSkillJson` = `{enabled?,id,name,description?,path}`. `listProjectSkills` scans only `<project>/.agents/skills` and `<project>/.agents/skills-disabled` for folders with `SKILL.md`; `setProjectGroup` sets a plain UI folder label and stores the folder name in settings. This is project-scoped skill placement, not a hosted conversation Project/Section Group.
- `SyncManifest` = `{profile:{id,mode}, agent_policy, skills}`; `SyncSkill` variants are bundled, immutable repository-reference, or skills.sh source. Sync profiles capture skill source/hash and target agent policy, not Sessions, messages, MCP server definitions, plugin lists, scheduled jobs, provider credentials or ChatGPT/Claude Cloud histories.
- Marketplace proxy is for skill catalog/search/file previews; `dotagents` sync and project install functions manipulate skill packages. No chat-session import/export or transcript writer was found in the shared RPC schema, main handlers or sync manifest. Codex appears as an agent target for Skills, not a Codex-rollout reader; no ChatGPT session provider.
- UI is a native cross-platform Electron app. This meets the form factor category, not the requested migration semantics.
