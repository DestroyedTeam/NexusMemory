## Actual model boundary

The product is a team Skill-bundle distribution and installation manager plus an Atlassian Rovo agent provisioner. It obtains a discovery catalogue (`.well-known/agents/discovery.json` or `.agents/discovery.json`), authenticated/versioned bundles, optional Git/zip sources, and installs Skills into repo or system paths. The six actual Skill provisioners are `agents`, `claude-code`, `cursor`, `github-copilot`, `kiro`, and `windsurf` (renamed in UI to Devin Desktop). The generic `agents` target writes `.agents/skills`; its source docs name Pi/OpenClaw-style tools. This is resource installation, not semantic Skill translation or activation verification inside every harness.

`src/operations/session.ts` does define `Session`, but the source shape is an application/UI snapshot: `StartupResolution`, bundle manifest/directory/content, resolved discovery Skills, OAuth auth state, project membership, catalogue scope, and warnings. The UI server exposes `/api/session`, load, auth login/logout and SSE job/session state. It does not represent user conversation turns, messages, transcript, forks/subtasks, attachments, model context, token costs, or history import/export. `src/api/types.ts` `Project` is an Atlassian API object (`id`, `teamId`, name, `toolIds`, admin emails, timestamps), not a ChatGPT conversational Project, Claude Project, or Codex Project; it has no Section or Session tree.

The Git importer scans a Claude Code plugin marketplace repository for `skills/<name>/SKILL.md` and optional `.claude-plugin/plugin.json`, then imports the **Skills only**. Source/docs do not implement plugin installation, MCP server configuration/credentials, Harness hooks, ChatGPT Projects/Sections, memory, scheduled tasks, or provider session APIs. No ChatGPT/Codex session exporter/importer was found. All three Claude Desktop modes—Chat, Cowork, Code—remain in scope and unsupported as sessions here. The project’s browser/OIDC bearer token is for bundle/catalogue APIs, not an Anthropic/Claude model API key.

## Positive architectural value and limitations

- Strong adjacent reference for a `ResourceBundle` + `DiscoveryCatalogue` + `SourcePin` + per-source version/cache/provenance + `SkillInstall` ledger, repo vs system scope, and explicit target provisioner registry. It uses namespaced links for Git/artifact sources, source-specific bundle caches, OIDC/PKCE and a hash-pinned artifact option; CLI/UI/CI share the catalogue and installer.
- Path segments are explicitly validated; ZIP extraction resolves the target root and requests `safeSymlinksOnly`; archive security and provisioner/symlink tests exist. `npm audit --registry=https://registry.npmjs.org` reports 0 vulnerabilities for the locked dependency tree at review time. Artifact `.sha256` sidecars are optional: absent sidecars warn and continue unless the operator supplies `artefact-sha256`, so provenance/hash policy remains an explicit trust setting.
- The root “Session” is not portable conversation history; Rovo “Projects” are a provider-specific access/catalogue concept. Never map those nouns to ChatGPT/Codex objects by name.

## Disposition

**Shortlist as a high-value Skills/resource-plane reference, not as the requested session/project migration engine.** Its bundle/version/provenance/discovery and per-target install patterns can inform Nexus’s resource adapters, but it does not migrate conversation Sessions, Projects/Sections, memory or provider-specific context. It cannot satisfy the target end state on its own. Keep API `Project`, local UI `Session`, Rovo agent config, Skill bundle and external conversation records as distinct entities.
