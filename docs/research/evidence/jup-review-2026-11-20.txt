## What the code actually manages

`jup` is a Python CLI for installing and synchronizing Agent Skills (`SKILL.md` directories). It accepts local and GitHub sources, stores downloaded material under `~/.jup/skills`, tracks source/layout/category/skill names/version and update/install timestamps in a `skills.lock`, and links or copies those Skills to configured local/global harness skill folders. It has built-in harness locations and custom providers, plus add/list/sync/update/remove/move/config/TUI commands. This is a useful resource-plane reference for Skill provenance, source locks and per-harness directory projection.

The symbol `skills_lock_session` in `src/jup/config.py:104` is a context manager that obtains a file lock, loads a `SkillsLock`, yields it, then saves the lock on exit. It is **not** an AI conversation/session-history API. CodeGraph source paths reviewed included `src/jup/config.py`, `src/jup/models.py`, `src/jup/core/sync.py`, `src/jup/core/filesystem.py`, `src/jup/commands/add.py`, and the tests below.

No Projects, Sections/Section Groups, conversation or Session graph, turns/events, parent/fork/child tasks, attachments/images, token usage, MCP server configuration, plugin lifecycle, personal/project memory, schedules, Cloud conversation store, ChatGPT export reader, or Claude Desktop/Claude Code session writer was found in the scoped source/docs review. The tool cannot satisfy Destruction Era ChatGPT/Codex → Claude Desktop Chat/Cowork/Code or local/self-hosted Claude Code session transfer. It does not write Anthropic-hosted Claude Code Cloud sessions either.

## Safety and limitations

- `src/jup/core/filesystem.py:11` resolves paths and checks that they remain under an allowed base; `safe_copytree` validates its destination. `tests/security/test_path_validation.py` covers absolute paths outside the base, relative traversal and symlink escape. No path-traversal exploit was reproduced in this review.
- Static review of `src/jup/core/sync.py:307-349` found that when a same-named target already exists and differs from the source, synchronization can unlink it or recursively remove the destination directory before creating a symlink/copy. The code labels this a managed target, but a same-slug unmanaged destination collision should be treated as a potential destructive overwrite. No valuable user files were used in the demo; Nexus should preview conflicts, back up and require approval.
- The lockfile has no per-Skill content digest in the reviewed schema. Link-based installation reflects later edits to the source directory; it is not a content-addressed archive.
- Custom skill-directory mapping does not prove the harness has loaded or activated a Skill. Require per-host discovery/version checks.
