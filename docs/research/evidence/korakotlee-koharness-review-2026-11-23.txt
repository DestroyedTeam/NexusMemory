## Scope and adapters

README describes a version-controlled dotfiles/capability repository for prompts, Skills, workflows and MCP configuration, plus a 3-layer documentation convention (memory/raw, memory/wiki, memory/AGENTS.md). The memory implementation validates folder/file presence, links and steering triggers; sync injects a pointer block to memory/AGENTS.md. It does not parse chat exports, retain turn/message events or parent/branch/task relationships, transfer Projects/Sections, reconstruct attachments/token usage/schedules, or serialize durable per-session memory. The raw directory may hold human-provided transcripts as files but no transcript import/conversion exists.

Implemented host IDs are Claude Code, Antigravity and Codex. Path source: Claude .claude/skills plus MCP path .claude.json; Antigravity .gemini/config/skills, .gemini/config/global_workflows and .gemini/antigravity-ide/mcp; Codex .codex/skills and .codex/mcp. Claude/Codex have no workflow path in the adapter. README mentions Claude CoWork in the memory-navigation description, but no Claude Desktop Chat/Cowork/Code adapter or Desktop-specific store path exists.

## Decision

High-value adjacent ResourcePlane/human-readable memory-layout reference, but not a chat/session migration engine. Before considering implementation reuse: resolve the missing license; model Claude MCP as a JSON merge into .claude.json rather than a child path; never write expanded secrets through a symlink into a tracked shared repository; keep env values local and mode 0600; mark each file as managed and avoid dirtying source on sync; and inject memory pointers only into explicitly detected/selected harnesses. Distinguish Claude Code from Claude Desktop Chat, Cowork and Code modes.
