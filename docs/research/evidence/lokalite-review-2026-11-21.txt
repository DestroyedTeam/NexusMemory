## What it is — and is not

Lokalite is a local macOS credential vault with a SwiftUI menu-bar/manager app, CLI, and local stdio MCP server. Its own “Projects” are secret namespaces with an optional linked filesystem path, not chat or coding-agent Projects. The typed `Project` fields are id/name/path/activeEnvironment/icon/createdAt; `EnvironmentRecord` belongs to a project; a project has a single active environment. Values belong to project/environment scopes. This is a useful credential-scope tree (`project → environment → secret`), not a nested Section/SectionGroup hierarchy, conversation history, session tree, branch, task graph, or child-session relationship.

The MCP server can be registered for four clients by writing each client’s local JSON config: Claude Code (`~/.claude.json`), Claude Desktop (`~/Library/Application Support/Claude/claude_desktop_config.json`), Cursor and Windsurf. Other MCP clients require a manual server block. This is generic Desktop MCP configuration, not a Chat/Cowork/Code session importer, provider/gateway route configurator, hosted Cloud Session writer, ChatGPT connector, or session restore. Source scans of `Sources` and `Tests` found no ChatGPT reader, transcript/session/project importer, attachment/media-event handler, branch/session graph, or conversation writer. “Conversation” matches are explanatory text saying secret values must not enter conversation/model context.

## Credential plane / implementation detail

- Secret values are AES-256-GCM encrypted in SQLite; the 256-bit vault key is held in the macOS login Keychain. Secret names, descriptions, project names/paths and activity metadata are plaintext database metadata, protected by the user’s home-directory permissions/FileVault. Encrypted export uses Argon2id; the candidate is a secret manager, not a model/API gateway.
- `lokalite://KEY`, `lokalite://project/KEY`, and `lokalite://project/environment/KEY` references carry no secret value. `lokalite run` resolves them at process spawn and fails closed if a reference is malformed, missing, or denied. This is a strong reference-only pattern for Nexus: migrate the reference/provenance/required scope, never the credential value; ask the user to bind a destination credential separately.
- Default MCP tool set is `get_secret`, `list_secrets`, `list_projects`, `list_environments`, and `use_environment`. `--read-write` adds secret add/set/delete. Nuance: `use_environment` is exposed in the default “read-only” tool set but changes the project’s single active environment shared by app/CLI/agents; this is a control-plane state mutation, so the read-only label is not a complete no-state-change guarantee.
- `get_secret` does not return the raw secret in MCP output. It writes a temporary shell handoff under a 0700 directory with a 0600 script; the value is plaintext inside that short-lived file, exported when sourced, self-deleted on first source, and unsourced files swept after 30 seconds. After sourcing, the secret is available to the agent-controlled shell/child processes. This protects model transcript context, not the shell from a determined agent.
- Per-secret policies are `allow`, `block`, `approve` (`requiresApproval`) and `strict`. `block` relies on best-effort process-tree agent detection and can be evaded by renamed/sandboxed agents. `approve`/`strict` require the GUI daemon and Touch ID; approval-tier reads/writes fail closed without the GUI, and `strict` prompts per read. Peer code-signature verification is explicitly attribution-only, not an enforcement gate.
- `MCPClientConfig.register` preserves unrelated keys when existing config parses as valid JSON and writes atomically. Source-level fallback `readJSON` returns an empty dictionary on unreadable/invalid JSON; then `register` writes a new minimal config. This could discard a malformed prior client config. The existing unit test covers preservation of valid JSON only. A safe synthetic probe compiled the pinned `MCPClientConfig.swift`, started with malformed JSON in a temporary HOME, and reproduced replacement by a minimal Lokalite server config (both compile and run exit 0); no actual user config was touched.
- No provider `base_url`, model router, gateway protocol, cross-provider auth translator, scheduling-task model, Skill/plugin sync, ChatGPT history/session parser/writer, or fidelity/round-trip measurement is present in the source. API-key examples are vault seed/reference fixtures, not model request routing.
