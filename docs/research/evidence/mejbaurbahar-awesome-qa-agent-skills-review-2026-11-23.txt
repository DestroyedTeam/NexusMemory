## What it is / fit

README describes 194 curated QA/product-management Agent Skills in 21 categories. Its shell installer targets Claude Code (~/.claude/skills) and Antigravity (~/.gemini/config/skills); it also documents the Claude Code plugin and npx skills installation routes. The actual implementation is a static Skill catalog, catalog builder, validator, source-vendor refresher, and link/copy installer. It does not model or import/export ChatGPT or Codex Projects, Sections/Section Groups, nested sessions, parent/child/fork/message event graphs, attachments, usage/token counters, MCP/plugin configuration as project/session resources, durable memory, or schedules. It has no Claude Desktop third-party-gateway Chat, Cowork, or Code session writer. Do not count it as a session/project migration engine or a target adapter. Reusable Skill text belongs only to the separate ResourcePlane.

The local catalog contains 194 Skills from 14 pinned vendor sources (178 MIT and 16 Apache-2.0 Skills); sources.lock.json, upstream licenses and THIRD_PARTY_NOTICES.md provide useful source/commit/license traceability. An optional 77-Skill Product-Manager-Skills pack is explicitly CC-BY-NC-SA-4.0 and is fetched at install time rather than vendored.

## Source and behavior findings

1. Manifest path is treated as ownership proof. install.sh tracks destination strings in $AQS_HOME/.installed. On install and uninstall, any existing path listed there is recursively removed with rm -rf; it does not verify the prior symlink target, copied content, or that the path remains under either configured skill root. In a disposable fake HOME, --pack qa --claude-only installed 120 links. Replacing one recorded symlink with a synthetic user-owned directory and USER_OWNED.txt, then running --uninstall, exited 0 (removed 120 skill entries) and deleted the marker. A second isolated probe appended a synthetic directory outside the skills root to .installed; --uninstall exited 0 (removed 121 skill entries) and deleted its sentinel. These show path-ownership/data-loss hazards if a recorded destination is replaced or the local manifest is stale/tampered; they do not establish remote exploitability.

2. Source refresh is not transactional. scripts/sync_vendor.py removes all previously locked skill directories for a source before validating/copying the new source. copy_skill() also rmtree's a destination before copytree. A later missing SKILL.md, copy failure, or interrupted run can leave the old catalog partially or wholly deleted; lock metadata is only rewritten at the end. This is maintainer-time refresh logic, distinct from the end-user installer.

3. Optional upstream is not commit-pinned by the installer. install.sh --with-upstream shallow-clones or fast-forwards deanpeters/Product-Manager-Skills at use time; the resulting commit is not added to the local source lock. The README discloses the CC-BY-NC-SA-4.0 license, which is a good redistribution boundary, but a reproducible package should record the fetched commit.
