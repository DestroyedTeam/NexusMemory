WHAT IT IS / ORGANIZATION
- TiguClaw is a local/self-hosted multi-LLM agent runtime, not a general-purpose conversation exporter. README describes Telegram/Web/CLI/HTTP channels, local sessions/memory/DB, Claude Code skills/hooks/settings formats, Codex/OpenAI/Anthropic/Google and OpenAI-compatible endpoints, scheduled work and manager/subagent orchestration.
- SQLite `threads` identifies a channel/thread and current provider session/model, last channel/target, name, and last input/output tokens. `transcript_index` maps `(channel, thread_key)` to provider session IDs and JSONL paths, with byte offsets/line counts/last message UUID. `transcripts` stores role/timestamp/text by provider session ID; `turn_items` stores ordered JSON tool items/output for turns. `chat_log` is a separate display-text log. FTS indexes transcripts and memory. The transcript storage field remains named `claude_session_id` even for other adapters.
- Conversation branching is a strong design reference. `thread_lineage` stores parent key plus transcript/chat/time cutoffs, and optional Claude SDK copied-session ID / included-through watermark. `thread-members` calculates inherited ancestor prefixes at those cutoffs. Forking is serialized on the parent conversation; message-point forks reject non-final/tool-use assistant messages; Claude branches call SDK `forkSession`, then verify the copied session's last message boundary before atomically writing lineage. Codex/OpenAI do not get a Claude SDK copy; their transcript rows are carried through a branch projection/rebuilt history. This is TiguClaw-native branch behavior, not import from ChatGPT or Claude Desktop.
- A transcript JSONL indexer ingests SDK-produced files incrementally. It stores raw content and an FTS projection; its JSONL parser flattens strings and `{type:"text"}` blocks. `turn_items` separately preserves some structured tool calls/results. This is not a canonical multimodal event schema for images/audio/URLs/token costs across all harnesses. Raw Claude SDK JSONL files remain the provider-side source; this code indexes sessions the runtime already knows via its session map, not a discovered external-harness import CLI.
- Projects are registered by absolute folder path; `<project>/PROJECT.md` is truth, SQLite is an index. Conversations can link registered projects and inherit project commands/skills/subagents/MCP tools. There is no project parent/Section/Section Group entity. Typed memories (`user`, `feedback`, `project`, `reference`) live in a local FTS-backed store. Scheduler records include originating thread; worker-job persistence is metadata only (source comments say result/error body is not persisted and restart is not full job resume).
- Search of README/docs/source found no productized import/export/migration interface for external sessions/transcripts. TiguClaw's OpenAI-compatible gateway is not evidence that Claude Desktop's developer-mode gateway protocol or session format is compatible; no Claude Desktop Chat/Cowork/Code session transfer was exercised.

FIT FOR NEXUS MEMORY
- High-value architecture reference for a canonical Session/Thread graph: channel-scoped conversation keys, provider-session aliases, append-only transcript indexing, a separate view log, immutable parent lineage with explicit transcript/chat/time watermarks, provider-native Claude fork plus boundary verification, search summaries/watermarks, project links, and typed project/user memory.
- Do not reuse the `claude_session_id` name as a universal provider identity; model it as a provider-specific session reference with source harness, account scope and provenance. Separate shared transcript content from native provider checkpoint and branch-copy metadata. Record losses when non-Claude sessions are reconstructed from text/tool records rather than provider-native continuation.
- It is not a migration tool: no ChatGPT Project/Section/Section Group parser, no external session import/export, no Cloud Desktop adapter, and no declared semantic-fidelity metric. Skills/MCP compatibility claims are runtime extensions, not conversation conversion.
