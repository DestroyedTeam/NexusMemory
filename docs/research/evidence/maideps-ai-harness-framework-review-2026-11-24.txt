## Implementation reviewed
This is a project-local engineering workflow harness, not a universal cross-agent/session adapter. It describes support for Claude Code, Codex, and Gemini CLI and implements reusable templates, bootstrap/upgrade/audit commands, verification gates and optional workspace components.

- Durable project state is feature declarations (`feature_list.json`), mutable per-feature shards (`.harness/state/<id>.json`), generated `PROGRESS.md`, `progress/` notes, `DECISIONS.md`, and `session-handoff.md`. Work is feature/task state, not a provider conversation archive.
- `session-trace start|end` writes/merges `.harness/traces/session-*.json` records containing timestamps, git branch/commit, active feature, verification summary, changed-file paths, and decision counts/titles. `harness-report` aggregates those records. These traces do **not** contain user/assistant turns, native conversation IDs, event order, branch/fork/subtask/session-parent lineage, message attachments/media, token usage, or transcript replay data.
- WIP=1 is enforced per worktree lane; optional parallel lanes use separate worktrees and sharded feature state. The project hierarchy is a software delivery workflow, not a port of ChatGPT Projects/Section Groups or native Harness sessions.
- Twelve packaged Skills support the workflow. The optional MCP component emits Context7 config for Claude Code and Gemini CLI, and its devcontainer registers a server with Codex. These are not source-resource importers or Claude Desktop gateway config. No parser/writer found for ChatGPT export, Projects/Sections, session graphs, attachments, model usage, MCP/plugin/Skills cross-platform migration, scheduled tasks, memory migration, or target-native session resume.
- `create-harness` preserves existing files on adoption; `harness-upgrade` makes a backup before overwriting framework-owned files and preserves project-owned/instance state. Useful safe-adoption/rollback patterns only; no cross-Harness migration mechanism.
- CodeGraph targeted exploration found `sessionTrace` has one caller and no direct covering test in the candidate's tests. The test suite includes adoption and upgrade behavior but does not demonstrate native session migration.

## Official scope check: Claude Desktop third-party inference (2026-11-24)
First-party Claude Desktop docs explicitly state that Chat, Cowork, and Code sessions run on Claude Code and route requests through the configured gateway. The self-hosted LLM gateway contract requires `POST /v1/messages` with streaming and tool use; `GET /v1/models` is optional. Gateways should preserve Anthropic Messages API fields, prompt-cache `cache_control`, and usage cache fields. The Developer → Configure Third-Party Inference UI supports Gateway base URL, static API key, auth scheme (Bearer or x-api-key), or interactive IdP login. The official Code docs clarify Desktop uses this third-party inference config, **not** CLI `ANTHROPIC_BASE_URL` / `settings.json`; when 3P gateway is active, Anthropic-hosted cloud environments and Remote Control are unavailable. Therefore Chat/Cowork/Code are real in-scope Desktop modes under a supported compatible gateway, but each still needs separate data/hierarchy/feature-resume tests.

This is not the same as API-key access to Anthropic-hosted cloud sessions. Cowork's current documentation says cloud sessions run on Anthropic servers and follow the account across surfaces; local-folder sessions and on-device legacy Cowork data are separate. Claude Code local sessions have a local project-bound transcript/session model and can resume via session ID or transcript path. Do not claim that an API key moves ChatGPT history into a Cloud session or that a model gateway restores native history.

## Decision
`maideps/ai-harness-framework` is a useful, low-maturity adjacent reference for auditable project workflow state, resumable *work briefs*, Skills packaging, safe adoption/upgrade and verification evidence. Reject it as a ChatGPT-to-Claude session migrator, Projects/Sections converter, universal adapter, or session hierarchy store. Do not count its session-trace feature as transcript fidelity or a migration success.
