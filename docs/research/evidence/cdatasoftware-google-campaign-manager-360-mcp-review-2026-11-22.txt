## Actual MCP function and harness relevance

This is a local Java stdio MCP adapter for a specific external datasource, Google Campaign Manager 360, using a separately supplied CData JDBC driver JAR and `.prp` connection properties. README provides a Claude Desktop `mcpServers` configuration example for local processes on Windows/macOS/Linux. The source registers 3 tools: get tables, get columns, and run SQL query; resources are table metadata CSV. It has no ChatGPT/Codex Projects, Section Groups, Session/turn/branch/message tree, attachments, tokens, project hierarchy, memory, scheduled tasks, export/import, MCP registry migration, or cross-Harness converter. The Claude Desktop snippet is configuration documentation only; Desktop 3P inference/API-key mode and Chat/Cowork/Code were not runtime-tested.

The code/POM do not bundle the CData Campaign Manager JDBC driver; `Config` requires `DriverPath`, `DriverClass`, and `JdbcUrl`, then loads that JAR with `URLClassLoader`. The connection URL/credentials/driver supply the actual data scope. This is a local datasource connector, not a transferable skill or conversation record.

README inconsistencies: it correctly says the project is a deprecated local **read-only** MCP server and describes `_run_query` as SQL `SELECT`, but a later generic “Usage Details” paragraph says tools can “read, write, update, and delete.” Actual source registers only metadata tools plus `Statement.executeQuery(sql)`; no write/delete tool is present. However, source does not call JDBC `Connection.setReadOnly(true)` or constrain query tables at the MCP layer. Treat read-only as an intended tool set/driver-permission contract, not a security guarantee proven by this checkout; no real CData driver or account was available for verification.
