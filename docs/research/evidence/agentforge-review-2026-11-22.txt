## Capability boundary
The repository's CLI search uses the local SkillRegistry, which scans bundled Markdown and recorded installs. The user-facing marketplace client is explicitly marked experimental/not available; search, get_skill, download, publish, category listing, and update-check methods all raise NotImplementedError. Marketplace data/cache modules have zero test coverage.
The model is a single Markdown Skill plus frontmatter metadata/variables, not a directory asset or conversation/event graph. There is no Session, transcript, project/section hierarchy, branch/subtask, attachment, token-usage history, MCP/plugin import, memory, recurring schedule, or native session-restoration path.
Only five CLI adapters are registered: Claude Code, Cursor, Copilot, Aider, and Hermes. The Claude Code adapter writes .claude/commands/<name>.md, not .claude/skills/<name>/SKILL.md; there is no Codex adapter and no Claude Desktop Chat/Cowork/Code or Cloud/API-key session adapter. Hermes ignores project/global selection and writes only to ~/.hermes/skills/<name>/skill.md. The installer serializes one Markdown file and does not preserve resource directories or attachments.
The update command reads from the local registry. scan_installed overwrites the bundled Skill entry with the installed file for a matching name; _show_update_check then compares that same installed object to itself, and update --all reinstalls the installed source, not a newer bundled/remote copy.

## Reproduced safety and correctness findings (synthetic data only)
1. Skill-name validation is not enforced in the production parse/install path. Skill.validate() rejects ../../../escaped, but Skill.from_file/from_string do not invoke it, Registry.scan_bundled accepts non-empty names without validating, and the installer interpolates skill.name directly into dest_dir / f"{name}.md". An isolated CLI install of ../../../escaped exited 0 and wrote a file outside the intended .claude/commands directory.
2. CLI uninstall path escape. A single command argument based on an absolute temp path to an existing synthetic .md file was appended with .md, escaped the target adapter directory and deleted that file. Single-item uninstall skips the confirmation prompt; the CLI test covers multi-item confirmation but not path containment.
3. Symlink overwrite. With a valid Skill name and --force, a symlink at the intended destination to an outside temp .md file remained a symlink while write_text changed its external target content.
4. Update false positive. In a temp registry with bundled demo v2.0.0 and installed demo v1.0.0, update --check printed “All installed skills are up to date.” Calling update single wrote the installed v1.0.0 body again; no v2.0.0 content reached the target.
5. PyPI identity mismatch. The README install command resolves to the unrelated GPL DataBassGit project in PyPI, not the pinned MIT repo.
6. Remote marketplace. MarketplaceClient.search raised NotImplementedError; the CLI's local bundled search successfully found code-review, but this is not a remote catalogue.
All filesystem probes used disposable temporary directories/HOME and synthetic Markdown only. No user files, real tokens, project data, or production Skills were touched.
