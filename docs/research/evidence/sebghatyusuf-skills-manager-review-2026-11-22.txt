## Product boundary

This Electron app catalogs/installs skill directories and toggles enablement across VS Code, OpenCode, Codex, Antigravity, Cursor, and Claude Code. Its Claude adapter uses `~/.claude/skills` plus workspace `.claude/skills`; it is not a Claude Desktop third-party-inference Chat/Cowork/Code adapter. It has no ChatGPT Project/Section/Session hierarchy, transcript/branch import, attachments, MCP/plugin/memory/schedule migration, or Cloud session writer. This can serve only as an adjacent ResourcePlane UI example.

## Pinned-source findings

- `SkillsService.buildTargets` registers six local directory adapters; the Claude path is specifically `.claude/skills`.
- `installSkillWithProgress` filters requested `skillName`, but `const toInstall = filtered.length > 0 ? filtered : skillDirs`; if the requested name is absent it installs every discovered skill rather than erroring. It copies candidates sequentially and exits on a later target collision without removing earlier copies (partial install/no transaction rollback).
- README describes the optional VS Code Copilot root as symlinked, but install/enablement code uses recursive `copyDir`; the destination is a copy. This creates untracked divergence and can leave old content after updates.
- `deleteSkillAll` takes `path.basename(skill.path)` and deletes that basename from every IDE root's active and `.disabled` folders plus the Copilot root. It does not compare content/source identity before removal; destructive behavior is intentional by label but broader than the selected entry's provenance.
- SkillsMP key is accepted from env or settings. `SettingsStore` persists the `AppSettings` object to `app.getPath("userData")/settings.json` using `JSON.stringify` with no application-level encryption. This is a marketplace-search API key, not a model/provider API key. Skill discovery and settings do not contain user conversation state.
- `SkillRegistry` collapses entries by `record.name.toLowerCase()`, which can merge same-name skills from distinct sources; it retains multiple paths internally for targets but the visible item identity is name-based. Include this as a UX/data-model caveat, not as proof of a vulnerability.
