## What it actually implements

The README describes six local Markdown agents for Claude Code and Gemini CLI, each with YAML frontmatter and a specific Smartsheet-MCP tool allowlist: bottleneck-scanner (read), reassignment-helper (write), engagement-cloner (create), risk-scanner (scan), standup-prep (brief), and status-comms-writer (draft). There are six files per host under `.claude/agents/` and `.gemini/agents/`. Contributing guidance is useful for Nexus resource adapters: one narrow workflow per file, explicit/limited tools, explicit confirmation for writes, structured output contracts, and a documented host-specific frontmatter dialect.

The pack is an application-specific prompt/config package, not a cross-Harness migration utility. It contains no ChatGPT export parser, Project/Section/SectionGroup model, conversation/turn/event schema, branch or parent/child session graph, transcript import/export, attachment/media handling, usage/token ledger, provider/API-key gateway adapter, native session writer, plugin/memory conversion, or session fidelity/round-trip tests. `USAGE.md`’s cron and CI examples are shell invocations around these agents, not an import/export model or a portable native-scheduler object.

Smartsheet’s launch article explicitly says these local agents run in Claude Code’s terminal or the Code Tab inside Claude Desktop; that maps to the user-confirmed **Code** mode only. It is not evidence for Claude Desktop Chat or Cowork session transfer, nor for Anthropic-hosted Cloud session creation. Source: https://www.smartsheet.com/content-center/managing-work/project-portfolio-management/introducing-cli-power-tools-smartsheet .

## Source-level portability and safety findings

- Agent files are duplicated per host rather than generated from one canonical body. The Claude/Gemini pairs are not byte-identical; Gemini variants add automated-chain instructions using `default_api.invoke_agent(...)`, while the Claude versions use human-directed handoff offers. The Gemini frontmatter only lists Smartsheet MCP tools; `invoke_agent` is not declared in the agent allowlist, and its runtime availability was not verified. Therefore filenames/Markdown portability does not imply equal behavior. Nexus should preserve original assets and test each host renderer independently.
- The Gemini `reassignment-helper` both says “No writes until explicit approval” / “Don't reassign without explicit user approval” and has an automated-chain section instructing downstream agents to proceed without confirmation. This is a material prompt-policy conflict around consequential writes. Do not copy agent chains into a target runtime without explicit, separately tested approval gates.
- Both setup scripts ask before replacing an existing `smartsheet-mcp`, remove it, then prompt for and validate the new PAT. Therefore an empty/short token or later setup failure can leave the old config removed. The scripts also interpolate the PAT into a `claude mcp add ... -H ...` or `gemini mcp add ... --header ...` process argument, so it may be exposed to local process inspection; do not pass real credentials through an unreviewed script.
- Safe isolated setup probes used a temporary `HOME`, temporary working directory, a fake `claude`/`gemini` executable at the front of `PATH`, and a synthetic token. No real CLI, credential, API, or network call was involved. With the realistic piped input `y\nSYNTHETIC_TOKEN...\n`, Claude setup exited 1 (`Token seems too short (1 characters)`); Gemini setup exited 1 (`No token provided`) after its mock log showed `mcp list` and `mcp remove smartsheet-mcp`, but before `mcp add`. This reproduces the one-character `read -n 1` confirmation leaving the Enter newline for the later token read in a piped `y<Enter>` sequence. This is an input/UX hazard; a user who presses only `y` without Enter follows a different path.
- Corrected mock input placed the synthetic token immediately after the single `y` key, with no intervening newline. Claude and Gemini setup scripts each exited 0, and their fake CLI logs showed the expected `mcp list`, remove, and add calls. Both logs contained the synthetic token inside the header argument, proving the argument-boundary finding without exposing a real secret. All config paths were in temporary directories.

## Nexus Memory disposition

Retain as a **low-adoption, high-specificity adjacent resource/adapter reference**, not as a core project/session migration engine and not as session-fidelity evidence. Useful patterns: separate host-specific agent manifest/frontmatter serializers, narrow MCP-tool allowlists, structured chain payloads, human approval gates, and adapter-by-adapter fidelity reports. Borrow none of its token-handling scripts or its Gemini automated-chain policy as-is. Add cross-host semantic-diff, approval-gate, local-secret-redaction and round-trip tests to Nexus; represent the Smartsheet MCP server as an external capability reference, never as imported conversation/session content.
