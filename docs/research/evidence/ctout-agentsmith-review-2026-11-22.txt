## Implemented scope and fit for Nexus Memory

`agentsmith` is a local asset sync/install manager, not a conversation/session importer. README says it syncs the GitHub `awesome-copilot` catalogue and installs assets to VS Code, Kiro, or Antigravity in repo or user scope. Source code confirms the target union is exactly `vscode | kiro | antigravity`; the current adapters are only VS Code, Kiro, and Antigravity. Roadmap marks Claude Code, Cursor, Warp, and Codex adapters as planned, not implemented.

- Canonical records contain asset id/type/title/description/source/local path/directory flag/content hash/setup metadata/tags; subscriptions add target, repo/user scope, absolute installed path, installed/source hashes and timestamps. No Project, Section, Session, message/event/turn, branch/fork, subagent, attachment graph, token/cost, memory, schedule, or account/cloud entity exists.
- The only source adapter is `awesome-copilot`; current scan code reads `instructions/`, `agents/`, legacy `chatmodes/`, and `skills/`. `AssetType` also declares `plugin`/`workflow`, but current source scan does not produce them and target adapters return unsupported/no path for those types. No MCP server or credential transfer is implemented.
- The target adapters use an explicit `native | adapted | unsupported` outcome and report frontmatter changes. They map VS Code `applyTo` to Kiro `inclusion/fileMatchPattern` or Antigravity `trigger/globs`; some target adapters explicitly omit agent fields such as `chat-tools`, `handoffs`, and `target` and list those omissions. This structured degradation is a useful pattern, but only for markdown assets.
- Positive architecture reference: separate source/target adapters; explicit target+scope identity; per-asset hashes; local-edit detection; dry-run; tracked subscriptions; and reported frontmatter adaptation. Nexus can reuse the pattern for a resource plane only; it cannot replace the canonical session/event/relationship graph or the separate Claude Desktop Chat/Cowork/Code acceptance adapters.
- All user-confirmed Claude targets remain separate: Desktop third-party-gateway **Chat, Cowork, and Code, all three**, plus local/self-hosted Claude Code. `agentsmith` gives no evidence for any of those modes, an API gateway/session import, or Anthropic-hosted Cloud.

## Source/runtime findings

1. **Mass-removal threshold documentation/code mismatch (dynamically reproduced).** `SECURITY.md` and release notes describe the guard as blocking removal of **at least** 25%; source `validateSyncSafety()` compares `removalRatio > MASS_REMOVAL_THRESHOLD` where the threshold is 0.25. `awesome-copilot.test.ts` covers a 2/3 removal, not exactly 1/4. Calling the actual built export with 1 removal among 4 previous assets produced literal stdout `exactly-25%: allowed`; 2/4 produced `50%: blocked: Safety check failed: mass removal detected (2/4 assets removed). Pass --force to override.`; `threshold=0.25`. Thus precisely 25% is allowed, contrary to the stated ≥25% policy. Synthetic records only; no sync or remote pull was invoked.

2. **Forced directory update is not transactional (dynamically reproduced).** `installAsset()` calls `rmSync(targetPath, {recursive:true, force:true})` before `cpSync(sourceDir, targetPath, ...)`, then updates the subscription record only after the copy and hash succeed. In a disposable Node process, a synthetic Kiro/VS Code Skill had an old target `SKILL.md`, a valid subscription with `installedHash=old-hash`, and a source child deliberately chmod 000. Calling `installAsset(..., force:true)` threw `EACCES` during copy after deleting the old file. Literal post-state: `after_target_entries=[]`, `after_sentinel_exists=false`, `subscription_still_points_to_target=true`, `stored_installedHash=old-hash`. The prior content was lost while metadata still claimed it was installed. The temp directory was removed; no user files were involved.

3. **Upstream version/provenance is not locked.** Sync shallow-clones/pulls `github/awesome-copilot` default branch and stores per-asset hashes/timestamps, not a pinned upstream commit or source tree identity. The hash/status design detects file changes but does not make a reviewable catalogue revision reproducible. This is a source-derived finding; no actual upstream sync was performed.

4. **Path guard and removal boundary.** Target path resolvers call `assertPathWithin`, which resolves candidate/base and walks components to reject escapes/symlinks; install/remove also call it before write/delete. This is a useful default-deny pattern, but the check and subsequent filesystem operation are separate (TOCTOU risk is source-derived, not dynamically exploited). User-scope and repo-scope paths are constructed from only those trusted scopes; `assetId` rejects separators and `..`.

5. **Project/session migration absent.** `Scope` is only `repo | user`; subscription grouping is flat by asset/target/scope/path. No project/container hierarchy or exported graph exists. The product copies Markdown assets and adapts frontmatter; “cross-environment” should not be interpreted as cross-Harness history migration.

## Disposition

Keep as an adjacent ResourcePlane example for explicit adapter outcomes, asset hashes, subscriptions, local-edit protection, and dry-run UX. Do not rank it as a session migration backend or evidence of Claude Desktop 3P compatibility. If borrowing its sync safety concepts, fix the exact-threshold boundary, make forced replacement atomic/rollbackable, and pin catalogue provenance. The repository is early-stage (one published v0.1.0, 0-star snapshot) and the public main branch is ahead of that release.
