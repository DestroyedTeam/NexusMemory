# Norte candidate review — governed file-manager/MCP audit plane, not session migration

Date: 2026-11-21. Repository: `compilando/norte`; source pinned to exact current `main` `52256ccb816999705fb681a5336d39839497d099` (merge commit 2026-11-02; `git ls-remote origin refs/heads/main` matched). Latest first-party release observed: `v0.3.0-alpha.16` (2026-10-16). GitHub About showed 5 stars / 0 forks at review time; the search-corpus snapshot had 7 stars, so adoption counts are a changing metadata signal, not a quality grade.

## Verdict

A high-safety, local file-manager/agent-control application with MCP, file-operation undo/audit, an OpenAI/Anthropic/Ollama model provider abstraction, and an optional in-app text assistant. It is not a ChatGPT/Codex conversation importer, Projects/Sections migrator, or portable transcript format. Keep only as an adjacent reference for agent permission boundaries, reversible file-operation ledgers, and careful naming of unrelated “session” concepts. Do not adopt `norte-core`, `norte-mcp` or `norte-ai` without an explicit AGPL-3.0-only review: those core crates are AGPL-only; selected crates such as `norte-proto` and `norte-frontend` are MIT OR Apache-2.0.

## Source-level findings (CodeGraph + focused source inspection)

### Four meanings that must not be confused

1. **Persistent UI session.** Core stores `<state_dir>/session.json`, versioned by `version`/`revision` with an opaque JSON `body`; the core does not interpret the body. The frontend body stores active profile, layouts, per-slot directory path/cursor/back-forward/jump/sort/marks/search, recent commands, popular directories, open panels and docks. This is app screen/resume state, not a chat transcript.
2. **Built-in AI assistant conversation.** The in-memory `norte_frontend::assistant::Assistant` has `Reader`, `Order`, `Answer`, and `Failed` turns, caps its local display at 200 turns, and sends only the newest `AI_CHAT_MAX_MESSAGES`; failures are not sent back as model history. The UI-host controller constructs `Assistant::default()` at boot. `SessionBody` and `SlotState` have no assistant-turn field, so this conversation is not part of the persisted `session.json` body. A turn/order has text, not generic content blocks, attachments, tool call/result IDs, forks, token usage/cost or parent-child session links.
3. **MCP agent identity.** `norte mcp serve --session <label>` uses an operator-supplied string to identify the MCP `Actor::Agent`; the daemon records that identity in policy, approvals and undo. The ID names an agent’s file-operation authorization/journal scope. It is not the provider’s conversation ID and the bridge does not save the agent’s prompt/response transcript.
4. **Operation journal.** `journal.db` is a hash-chained SQLite ledger of file mutations: sequence/time, actor kind and actor ID, operation, path/path-to bytes, reversal metadata, undo target and optional batch ID. `norte audit` verifies/exports this ledger. It records what Norte itself changed and supports undo; it is not the message/event history that caused an agent to ask for the change.

No ChatGPT Project/Section or project-membership graph was found. `Profile`/layout and a `VPath` workspace are different objects and must not be relabeled as a conversation Project/Section. Focused source/document scan found no external conversation-session import/export adapter; the README’s `norte theme import` and the operation-journal export are unrelated operations.

### Capability, security and platform boundaries

- Project describes an agent-facing local file interface through MCP with scopes and human `ask` policies; policy is first-match and default-deny. Mutating file operations are journalled and undoable where supported. This is valuable as a separate *tool-action/audit* plane, not a way to restore external session ancestry.
- `norte-ai` implements streaming Anthropic, Ollama and OpenAI-compatible chat providers. That endpoint/provider setting is model routing, not a session store. No ChatGPT or Claude Desktop session reader/writer was found.
- Release notes call v0.3.0-alpha.16 pre-release; Linux packages are available and Windows x64 is unsigned preview; README says macOS builds from source. GitHub Actions currently expose Nightly remote integration, while ordinary CI/GUI/Release workflows are explicitly disabled. Nightly #62 on 2026-11-20 passed, but it covers SFTP/OpenSSH, FTP/pure-ftpd and S3/MinIO remote integration—not Mac local tests or session migration.
- Multi-license repository: GitHub identifies AGPL-3.0 plus two other licenses; crate manifests confirm AGPL-3.0-only for `norte-core`, `norte-ai`, `norte-mcp` and `norte-cli`, and MIT OR Apache-2.0 for `norte-proto` and `norte-frontend`. Review component-level licensing before any reuse.

## Disposition

Keep `compilando/norte` as an adjacent reference for permission-gated agent file access, undo, provenance and hash-chained operation audit. Exclude it from the core session-migration engine and any fidelity score: it neither preserves externally authored prompts/responses nor maps Project/Section/thread/fork/task topology or attachments into a target session. Do not claim the separate UI session or MCP actor label as a portable agent conversation.
