What the implementation actually does
- Reads local Pi session JSONL under `<PI_CODING_AGENT_DIR>/sessions/<project>/*.jsonl` (default `~/.pi/agent/sessions/`). It registers a `pi_history` list/search/read tool and `/history` picker for preview, agent handoff, or native Pi resume.
- `HistorySession` is a local locator plus id, modified time, byte size, cwd, title, record count, and diagnostics count. Search is lexical AND-term matching. Read is a paginated normalized text projection via `@letta-ai/trajectory`.
- Bounds scan count (default 1,000/max 5,000), list/search results (default 10/max 50), transcript records (default 80/max 200), and tool output by characters, UTF-8 bytes and lines. Supports cancellation and current-session exclusion.
- Pi's append-only branch history is read in file order rather than reduced to a selected active branch; it does not export a branch graph.
- Canonicalizes and realpaths the session root and requested path, enforces containment, rejects an outside file and a symlink escape, and only accepts a `.jsonl` session file. It does expose the local path/cwd in results; treat those as private metadata.
- The extension does not write an interchange archive or import a session into another Harness. “Resume” calls Pi's native `ctx.switchSession`; it changes the active Pi UI session, not the source transcript format.

Migration coverage and disposition
