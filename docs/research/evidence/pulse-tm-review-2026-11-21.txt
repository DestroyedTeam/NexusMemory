The app may give a manually written tag description to an agent as context, but it does not copy or restore conversation context.
- Data lives in YAML at a project-root .pulse/<tag>.yml path (default project root is found by walking to .git; explicit working-directory override is available). One file is used per tag. It is portable as ordinary files, but moving YAML by hand is not a session converter.

## Source and data-integrity review

- Task IDs increment independently per tag file. There is no stable global task UUID; lookups without a tag scan tags and return the first matching numeric ID. This is weaker than an identity model for migration across multiple projects.
- Subtask tree depth is exactly one level. Subtasks are embedded in the parent task YAML. Parent/child task ordering is not a conversation turn/branch relation.
- Storage uses synchronous readFileSync/writeFileSync and no file lock or atomic replace. The source does not provide a multi-process merge/transaction layer; concurrent independent writers could overwrite a tag file. This is a static integrity risk, not a reproduced concurrent-write loss.
- Reproducible synthetic malformed-YAML test: an isolated project contained .pulse/feature.yml with exactly the invalid text “next_id: [not valid yaml” followed by newline. Running the CLI add command returned exit 0, stdout “✓ Created task #1: "Synthetic recovery test" (feature)”, while stderr logged a YAMLParseError; the original malformed file was replaced by a new YAML file containing only the new task. This confirms that loadTagFile's parse-error fallback to an empty TagFile lets later mutation overwrite the malformed file. No user files were used.
- A normal synthetic CLI flow created a task and subtask under a test-only feature tag. It produced a YAML record with task id 1 and nested subtask id 1, confirming task persistence, not session persistence.
- Tag names are normalized to lower-case letters/digits/hyphens, reducing path traversal risk. Task deletion is permanent in CLI; no native undo/rollback or migration preview exists.
