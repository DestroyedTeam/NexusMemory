## What the archived documentation describes

The `docs/usage.md` (marked reflect-kb v0.1.1) describes a local knowledge-base CLI. `reflect init` creates `documents/` and `nano_graphrag_cache/` under `~/.claude/global-learnings/` (or `GLOBAL_LEARNINGS_PATH`) and initializes that directory as a Git repository. `reflect add` ingests Markdown with `title`, `category`, `key_insight`, optional confidence/tags/language; it derives a content-hash `doc_id`, copies the document, creates a heuristic `.entities.yaml` sidecar and indexes it with GraphRAG, optionally syncing a QMD index. `reflect search`, `reindex`, `stats`, `critical-patterns`, `generate-sidecars`, and `metrics stats` act on that document KB. Search offers vector and entity/community graph modes. Metrics are documented separately at `~/.learnings/metrics.jsonl`.

The public README describes an accompanying Claude Code plugin (`reflect@agents-in-a-box`) for orchestration, hooks, statusline and recall, and says the only real consumer was that plugin. README says the KB data stays in `~/.learnings/`, while the versioned usage guide gives `~/.claude/global-learnings/` as the default; treat the path split as unresolved documentation drift. The default/custom-path model is a single Markdown memory corpus; no contract links a note back to a source conversation, message/event ID, parent session, branch, project section, attachment, token ledger or resume ID.

## Fit to Nexus Memory

This can inform a **derived MemoryPlane**: structured learnings, provenance-aware note IDs, entity sidecars, graph/vector retrieval, Git-backed local content, explicit confidence/tags, metrics and a rebuildable index. It is not a lossless archive or SessionGraph. Its `doc_id` identifies a derived note from title/body; it does not preserve source message identity, turn sequence, branching, interruptions, prompt additions, tool-call/result state, source media, cost/tokens, schedules or target-native resume. A shared path via `GLOBAL_LEARNINGS_PATH` could make a single KB readable by other agents only if each harness has a compatible CLI/API/hook and same filesystem; those adapters and scope controls are not present in this pinned repository.

Official current Claude Code documentation distinguishes these objects: `CLAUDE.md` instructions, per-repository auto-memory (`~/.claude/projects/<project>/memory/MEMORY.md` plus topic files), and local session JSONL transcripts (`~/.claude/projects/<project>/<session-id>.jsonl`) are separate. Auto memory is machine-local and not shared across machines/cloud; a session is a resumable conversation tied to a project directory. The reflect docs' `global-learnings` knowledge base is yet another custom store, not the native Auto Memory directory or transcript store. See https://code.claude.com/docs/en/memory and https://code.claude.com/docs/en/sessions.
