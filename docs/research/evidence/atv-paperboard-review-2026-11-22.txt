## What the implementation actually does
- One Python core + harness wrappers recognize Claude Code, Codex CLI, GitHub Copilot CLI, GitHub Copilot Coding Agent via Actions, and standalone. `paperboard render` accepts JSON/Markdown and writes a derived `{slug}.html` + `{slug}.DESIGN.md` + `{slug}.meta.yaml`; CLI regenerates a static HTML gallery. Skills/hooks suggest or opt into rendering structured status/table outputs. There is no import/export of agent sessions.
- Persistence roots are harness-specific: Claude `CLAUDE_PLUGIN_DATA`, Codex `~/.codex/atv-paperboard-artifacts`, Copilot CLI `COPILOT_HOME` or `~/.copilot/plugin-data/...`, Copilot agent repo-relative, standalone cwd. `PAPERBOARD_ARTIFACT_DIR` can override all roots but does not merge/parse harness histories. README explicitly declares cross-harness aggregation a v0.1.x non-goal.
- The `sections` schema (`hero`, `sec`, `stack-list`, etc.) shapes a rendered HTML report; it is not ChatGPT’s Project Section Group or a Session hierarchy. No source IDs, conversation/branch/subtask model, attachment transfer, token usage, memory/schedule migration, chat history writer, MCP server (deferred), ChatGPT adapter, Claude Desktop Chat/Cowork/Code adapter, or Claude Code session reader/writer exists. Claude Code CLI is supported, but that is distinct from Claude Desktop Code mode.
- The product is an output-presentation/resource-plane utility, not a data portability engine. `core.render.render_artifact()` writes only HTML/design/meta; the original JSON/Markdown input is not persisted. README says `meta.yaml` contains the source input path, but current source writes no input path/title or source digest; this was verified in a fresh wheel smoke. `_GENERATOR` is hard-coded to `atv-paperboard/0.1.0` while package version is 0.1.4, and `tests/test_render_real_world.py` asserts that stale value.

## Security and persistence boundaries
- Rendered HTML is active content. README explicitly documents raw HTML pass-through and says it is not sanitized. `body_html` is emitted as-is, Jinja uses `autoescape=False`, and Markdown raw HTML lines are preserved. A synthetic isolated `body_html` with `<script>window.__paperboard_probe__=1</script>` rendered with that script tag preserved (`render_exit=0`, `script_tag_preserved True`); it was not opened/executed. Treat untrusted imported/session HTML as unsafe until independently sanitized. Structured table cell helpers escape values, but that does not sanitize all input paths.
- Default browser opening runs a loopback-only HTTP server on `127.0.0.1` and opens the generated artifact; headless/remote guard exists. CLI `--design URL` accepts a URL and uses urllib to fetch it to a temp file; that is explicit user input, not a safe untrusted-session parser.
- Main has no retention/cleanup command. Open PR #11 proposes `paperboard uninstall` with dry-run by default, `--yes`, `--keep-artifacts`, `--all-harnesses`, allowlist/sentinel checks and 12 tests plus maintainer-reported sandbox scenarios; this is not merged and was not treated as shipped functionality.
