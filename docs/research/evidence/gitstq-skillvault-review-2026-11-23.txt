## GitHub candidate's actual behavior

The GitHub source is a small Python CLI that stores Markdown prompt content plus name/description/author/tags/platform metadata, lists/searches a bundled six-item market catalog, runs a regex validator, and JSON-imports/exports registry objects. `skillvault install` creates files only under its own `~/.skillvault/registry/<name>/` store. Its “multi-platform” field is metadata/search filtering for Claude Code, Cursor, Copilot, Windsurf, Cline and Aider, not a native adapter that writes each Harness's Skills directory or config. An isolated CLI smoke test of the actual checkout exited 0 and printed `Installed 'code-review-best' successfully!`; the synthetic file existed at `~/.skillvault/registry/code-review-best/skill.md`, while `.claude/skills`, `.cursor/skills`, `.copilot/skills` and `.windsurf/skills` target files were all absent.

Therefore it supports reusable Skill text as a resource concept, but no ChatGPT/Codex Project/Section Group/session graph, transcript, task/branch lineage, images/files/links, usage/tokens, MCP/plugin configuration, persistent memories, or schedule import/export. It has no Claude Desktop third-party-gateway Chat/Cowork/Code or local Claude Code session adapter. The JSON package is one Skill metadata/content object; it is not a Harness session archive or migration interchange format. Disposition: `SKILL_CATALOG_REFERENCE_ONLY; NO_NATIVE_HARNESS_DEPLOYMENT; NO_PROJECT_SECTION_SESSION_OR_TRANSCRIPT_MIGRATION; PYPI_INSTALL_NAME_COLLISION`.

## Separate PyPI project, source archive and tests

- PyPI 0.1.3 sdist SHA-256 `abd5d76448b56adcce1502d151d01ee19f6c4024eb00ac20de35a8b2f722e5dd` was verified from official PyPI JSON; no Trusted Publishing/provenance is recorded and repository metadata points to a `yourusername` placeholder. Extraction was static, not `pip install`.
- This separate package has an interesting adjacent design: SQLite Skills/chunks, vector retrieval with token budget and dependencies, caller-supplied `llm_fn` for turning a flattened conversation into a draft, and an admin/agent permission flag. It does not preserve source message/turn hierarchy; `extracted_from` is only the first 200 characters; it produces reusable Skills rather than restoring full sessions or Harness state. It hard-codes the vector dimension at 1536 and makes callers provide embedding and LLM integration; no native ChatGPT/Codex/Claude Desktop import/export adapter is present.
- The package docs promise “agent can only write drafts; humans control canonical” and say agent mode cannot approve. Source calls `check_auto_promote()` unconditionally after `extract()`, including in `mode='agent'`. Synthetic no-network POC used `:memory:`/temporary SQLite, fake embedding and fake LLM callbacks: an admin-mode draft was queried five times with `include_drafts=True`, then agent mode called `extract()` for the same draft ID. Literal output: `ADMIN_USAGE_BEFORE_AGENT 5 SOURCE draft`; `AGENT_EXTRACT_RETURNED draft::905999d0 SOURCE_AFTER canonical USAGE 5`; a direct `agent.approve()` still raises `PermissionError`. Thus the agent can cause automatic canonical promotion through `extract()` without calling `approve()`, contradicting the documented permission boundary. The threshold is reachable from ordinary admin queries of drafts; the test seeded usage through public `query()` calls and never edited SQLite directly.
- PyPI sdist tests required a temporary venv with pytest, httpx and respx; `respx` is imported by tests but absent from the declared dev extras. After installing these test-only dependencies, `pytest tests/` exited 0: **15 passed**. An initial POC pointed to the PyPI source while attempting to import the GitHub-only `skillvault.validator` module and exited 1 (`No module named skillvault.validator`); correcting the source path to the GitHub candidate produced the validator results above. This failure itself reflects the distinct packages, not a GitHub candidate test failure.
- Treat this PyPI package only as a separate **adjacent memory-extraction/reference candidate**: useful two-tier draft/canonical, chunk dependency, token-budget retrieval and explicit integration ideas, but not universal session portability; do not confuse or install it as the GitHub repo. Its agent auto-promotion behavior and unverified source provenance must be fixed/clarified before adopting its permission model or dependency.
