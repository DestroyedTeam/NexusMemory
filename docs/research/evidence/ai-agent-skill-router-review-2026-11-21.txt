## What source actually implements

- skill-router is a SKILL.md instruction plus a Claude Code SessionStart reminder hook. It asks the host model to select the minimum existing skills, one subagent and needed MCP tools; it is routing policy, not a file/state adapter.
- skill-audit scans local skill directories, Claude Code plugin/agent/command metadata, and MCP config server names for Claude, Codex, Cursor and Gemini. It writes inventory, overlap clusters and candidate actions under ~/.skill-router. MCP env values, args, headers and URLs are intentionally not serialized.
- Opt-in usage statistics walk only Claude Code ~/.claude/projects JSONL, parse selected event types and aggregate Skill/Agent/MCP names with timestamps. Source allowlists typed command names/tool metadata, and self-tests assert transcript marker text is absent from outputs. This is usage counting, not session export/import; there is no ChatGPT/Codex source parser or target-native archive writer.
- Safe apply design is useful adjacent evidence: a candidate trash operation revalidates a direct child of known skill roots, rejects links, rechecks SKILL.md SHA-256, refuses an existing trash destination, takes a lock, moves the directory to trash, logs an undo command, and supports undo. Claude plugins are toggled with the Claude CLI rather than hand-editing settings. The instructions, not an autonomous background service, require asking the user about each action.
- Security policy acknowledges sanitized third-party descriptions remain untrusted prompt text; the Claude auditor is read-only, but on other hosts analysis runs inline with the main agent and its normal tools. This is a residual cross-host prompt-injection boundary to preserve in any Nexus design.
